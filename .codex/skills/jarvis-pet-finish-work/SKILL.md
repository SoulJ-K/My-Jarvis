# Jarvis Pet 작업 마무리

이 스킬은 `/Users/rkfrk/Desktop/My Jarvis` 프로젝트에서 사용한다. 먼저 최신 `AGENTS.md` 13.1~15절과 변경 범위에 해당하는 PRD, Decision Log, 기술 설계 문서를 확인한다. 스킬은 실행 순서를 정하는 지시이며, 사용자 요청의 범위를 넓히는 근거가 아니다.

## 호출과 병합 범위

사용자가 완료된 작업에 대해 **이 스킬을 사용해 마무리하라**고 명시적으로 요청하면, 그 요청에 포함된 작업 브랜치의 GitHub 전송, 개별 PR 생성, 검증 후 GitHub 병합, 원본 로컬 `main` 동기화까지 위임한 것으로 처리한다. 사용자가 검토만 요청하거나 병합을 보류하라고 하면 병합하지 않는다. 호출만으로 관련 없는 브랜치, 보호 규칙 우회, 강제 푸시, 브랜치 삭제, 작업 대화 보관까지 승인된 것은 아니다.

대상 브랜치나 PR이 불분명하면 Git 기록과 현재 작업 대화로 식별한다. 그래도 범위를 특정할 수 없으면 사용자에게 확인한다. 작업 중 새로 생긴 범위까지 자동으로 포함하지 않는다.

## 실행 순서

1. **개별 수정·검사:** 원본과 각 워크트리의 Git 상태, 기준 커밋, 대상 PR을 확인하고 변경 범위를 기존 문서에 대조한다. 각 담당자는 자기 워크트리에서 관련 검사를 마친다. 개별 담당자는 원본에 직접 복사하거나 병합하지 않는다. 실제 구현, 설계만 완료, 미래 확장을 구분하고 민감정보·실제 펫 자료·불필요한 생성 파일은 결과물에서 제외한다.
2. **결과 인계:** 각 담당자는 통합 담당에게 워크트리 경로, 브랜치와 기준 커밋, 결과 커밋 또는 미커밋 변경 여부, 변경 파일, 검사 결과, 미검증 사항·남은 문제, 공통 파일 충돌 가능성, 문서 반영 사항을 전달한다. 개별 검사 통과를 통합 완료로 보고하지 않는다.
3. **병합 전 통합 검사:** 통합 담당은 원본의 기존 변경을 확인·보존하고, 적합한 기존 공간이 없으면 별도 통합 워크트리와 브랜치를 준비한다. 인계된 변경과 **원본에 이미 있는 이번 승인 범위의 미커밋 변경**을 차례로 합치되 관련 없는 변경은 섞지 않는다. 공통 파일의 의도를 대조하고 기능 간 연결과 기존 동작을 검사한다. 제품 결정이 필요한 충돌은 임의로 선택하지 않는다. 통합 검사가 실패하면 원인을 해결하고 관련 검사를 통과하기 전에는 PR을 병합하지 않는다.
4. **기록·PR·병합:** 중요한 제품·기술 결정만 기존 Decision Log와 설계 문서에 제자리에서 기록하고, 단순 구현 세부사항 때문에 새 문서를 만들지 않는다. 개별 작업의 커밋·PR 이력을 보존하고 통합 검사용 브랜치로 이를 대체하지 않는다. 검증한 변경으로 작업별 PR을 만들거나 기존 PR을 갱신하며 중복 PR은 만들지 않는다. 원본을 기존 변경 손실 없이 동기화할 수 있는지 **원격 병합 전에** 확인하고, 안전하게 동기화할 수 없다면 병합을 멈춘다. GitHub 검사와 최종 변경을 확인한 뒤 의존 순서대로 병합한다. 통합 검사 이후 코드나 대상 `main`이 바뀌었다면 차이를 확인하고 영향받는 검사를 다시 수행해, 실제 병합 내용이 검증한 내용과 일치하는지 확인한다.
5. **원본 반영·확인:** 기존 변경을 보존하며 원본 로컬 `main`을 동기화한다. 반영 직전 새 변경을 다시 확인하고 원본의 파일·문서 연결과 필요한 실행 검사를 확인한다. 검증한 통합본과 원본 결과가 다르면 영향받는 검사를 다시 수행한다.
6. **실사용 확인:** 원본 반영 후 사용자와 실제 화면·조작·생활 흐름을 확인한다. 할 수 없었던 수동 확인은 미검증으로 남긴다. 자동 검사는 격리된 시험 자료로 수행하고, 실제 펫 자료 초기화나 앱 강제 종료·재시작을 검사 편의로 임의 수행하지 않는다.

검사는 변경 위험에 맞게 선택한다. 근거 없이 전체 검사를 반복하지 않으며, 창·입력 초점에 영향을 주는 화면 검사는 순차 실행한다. 마지막 보고는 **개별 완료 / 통합 검사 완료 / 원본 반영 완료 / 실사용 확인 완료**를 구분하고, 브랜치별 PR·병합 여부·검사 범위·미검증 사항·남은 문제를 적는다. 문서 작업은 내용·참조 연결 검수로 보고하고 앱 동작 검증이라고 표현하지 않는다. Git 워크트리 정리와 Codex 작업 대화 보관은 별개이며 요청 범위에서만 각각 처리한다.
