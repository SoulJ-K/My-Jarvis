## 측정 방법

- 문장은 사용자가 실제로 쓰거나 쓰고 싶은 말을 고치지 않고 그대로 모았다. 원문과 판단은 [`requests.json`](requests.json)에 있다.
- [`run.cjs`](run.cjs)가 앱 입력창과 같은 분기(`src/renderer/prompt.ts`: `타이머`가 없고 알람·알림·오늘·내일·오전·오후 등이 있으면 일정 해석기, 아니면 타이머 해석기)로 빌드된 해석 함수를 호출한다. 앱 코드는 바꾸지 않았다.
- 기준 시각: 2026-10-16 10:00 KST. 기준 커밋: `66dd5fd`. 해석 관련 소스(`time-parser.ts`·`timer.ts`·`prompt.ts`)의 마지막 변경은 2026-10-07이다.
- **성공 판단은 사람이 한다.** 해석기가 받아들였는지(`accepted`)가 아니라 사용자의 의도대로 해석했는지가 기준이다. 그래서 A17은 받아들여졌지만 실패(`misparse`)로 셌다.

## 한계

- 해석 **함수만** 검사했다. 실제 앱 화면에서 입력·확인 카드·등록까지 해 본 결과는 아니다.
- 기준 시각 하나로만 재서, 시각에 따라 결과가 달라지는 문장(A23·A27)은 다른 시각에서 다를 수 있다.
- 사용자 한 명의 문장이다. 일반 사용자 전체의 성공률로 확대하지 않는다.

## 다시 재는 방법

```bash
npm run build && node experiments/request-baseline/run.cjs
```
