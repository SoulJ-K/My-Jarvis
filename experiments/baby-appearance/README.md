## 브라우저 비교 화면 실행과 확인

저장소 루트에서 다음 명령으로 이 컴퓨터 안에서만 접근하는 시험 주소를 띄운다. 명령 자체는 브라우저나 펫 앱을 열지 않는다.

```sh
node experiments/baby-appearance/serve.cjs
```

터미널에 나온 `http://127.0.0.1:...` 주소를 브라우저에서 연다. 다른 세션의 화면·초점 검사와 먼저 조율한다. 종료는 그 터미널에서 Ctrl+C이며 실제 펫 앱과 별개다. 파일을 직접 더블클릭하면 브라우저의 이미지 픽셀 접근 제한 때문에 실패할 수 있다.

- 각 아기의 기본·앉기·수면 버튼으로 자세를 바꾼다. 세 그림 사이의 연속 동작은 아직 없다.
- 쉬기는 정면을 기본으로 12초마다 좌우를 번갈아 0.85초 살핀다. 기본 자세는 고개만, 앉기는 몸 방향 그림을 전환한다. 일반 커서 이동은 시선을 바꾸지 않는다.
- 이동 보기는 고개를 먼저 0.18초 돌린 뒤 몸 방향을 바꾸고 시험 영역 안에서 한 차례 이동한다. 정지 0.25초 뒤 정면으로 복귀한다. 보행 프레임은 아직 없어 위치만 이동하는 순서 시험이다. 드래그·수면·다른 행동을 시작하면 예약된 이동을 취소한다.
- 먹이/구슬 바라보기는 해당 대상에 시선을 유지한다. 그 상태에서 이동 보기는 시작하지 않으며 쉬기로 해제한다. 먹이는 별도 시험 표식일 뿐 섭취 처리는 없다. 수면에서는 행동 버튼을 비활성화한다.
- 기본·앉기는 정면으로 시작한다. 좌우 이동 방향으로 바라보고, 놓은 뒤 0.25초간 그 방향을 본 다음 정면으로 돌아온다. 드래그 중에는 멈춰 있어도 정면으로 돌아오지 않는다. 작은 손떨림에는 방향을 바꾸지 않는다.
- 왼쪽·정면·오른쪽 보기 버튼은 각 그림을 계속 비교하기 위한 시험 조작이다. 새 움직임을 시작하면 이동 방향을 따른다. 수면은 기존의 오른쪽을 향한 낮은 자세를 유지하며 방향 비교 버튼은 비활성화한다.
- 기본 몸 높이는 원본 `babyBodyInset()`의 73.6px를 기준으로 한다. 큰 잎·귀를 포함한 **전체 외형 높이**이므로 기존 아기보다 얼굴이 작다. 96px/144px는 비교용이며 제품 크기 변경 결정이 아니다.
- 같은 계열의 자세는 발이 닿는 지점을 맞추며, 시점별 그림의 높이를 맞추고 원래 비율을 유지한다. 정면은 좌우와 너비가 다를 수 있다. 수면 이미지를 기본 자세 높이만큼 억지로 늘리지 않는다. 정밀한 뼈대·관절 정렬이나 프레임 애니메이션은 아니다.
- 몸의 불투명한 부분을 끌거나 방향키·위치 버튼으로 이동한다. 투명 여백은 마우스 몸 클릭으로 처리하지 않는다. 구슬·이름은 이 시험 화면 안에서만 배치한다.
- 밝고 어두운 배경에서 윤곽·잔여 테두리를 확인한다. 새로 생성한 이미지의 일부 색 테두리는 확대 시 남을 수 있으며 최종 자산 보정 대상이다.
- 아기의 입·코 그림은 없다. 먹기는 이번에 연결하지 않았다. 이후 먹이는 입이 있었다면 위치할 얼굴 아래 지점으로 접근하되 입을 그리지 않는다.
- 움직임 줄이기 설정에서는 놓은 뒤 시선을 돌리는 지연을 생략하고 즉시 정면으로 표시한다. 자동 주변 살피기와 고개 전환 대기를 생략하고 시험 이동은 목적지에 즉시 표시한다. 숨쉬기·통통 튀기는 넣지 않았다. 방향별 그림과 고개 전환 중간 그림을 바꾸며, 연속 회전이나 보행 중간 그림은 아직 없다.

## 남은 연결과 제안 — 현재 구현과 구분

1. 별도 시험 앱의 생활 화면에는 외형을 연결했다. 다음에는 부화 화면도 같은 외형 정보를 읽도록 연결해야 한다. 그림 식별자·자세·보이는 경계·먹이 접근점을 함께 관리한다. 손·귀·꼬리를 가진 계열에만 해당 동작을 사용한다. 지금의 `geometry.js`는 시험 외형 경계 계산용이며 일반 실행의 기존 창 배치 계산을 대체하지 않는다.
2. 기존 아기의 외형 정보가 없으면 기존 모습으로 표시하고 새 외형으로 자동 변환하지 않는다. 현재 키우는 아기에게 적용하는 결정은 별도로 받는다.
3. 새 부화는 최초 아기 표시 전에 외형 식별자와 제작 규칙 버전을 로컬 저장소에 확정한다. 실패하면 아기를 표시하지 않고 재시도하며, 이미 저장된 결과는 항상 다시 읽는다. 선택과 생애 진행의 저장 경계를 SQLite의 하나의 저장 묶음으로 검토한다.
4. 저장 전 종료·실패에도 후보가 바뀌지 않도록 개체 식별자와 고정된 후보 목록 버전으로 같은 선택을 복원하는 방식을 검토한다. 목록 추가 시 과거 결과를 재계산하지 않으며, 저장 형식 변경·실패 복구·이전 자료 읽기는 격리된 시험 DB에서 검사한 뒤 연결한다. 아직 DB 변경은 없다.
5. 시험 앱에서는 기존 생활 움직임에 그림을 연결했다. 연속 걷기나 동작별 전용 그림은 필요성을 검토해 보완하며, 먹기·기상·구슬놀이·약한/강한 재촉의 외형별 자연스러움은 추가 확인한다. 강한 재촉의 붉은 몸과 거부를 뜻하는 빨간 구슬은 독립적으로 유지한다. 확대 10%/20%는 임시 표현이며 저장된 기본 외형을 바꾸지 않는다.

## 두 시험 펫의 실제 앱 실행 — 2026-10-07

사용자가 실제 펫을 보존하면서 두 외형을 각각 시험하도록 승인했다. 고정 후보인 `시험·잎`과 `시험·날개`를 독립 프로세스와 별도 저장 공간으로 실행하는 구현이다. 부화 시 무작위 선택이나 기존 펫 외형 변경 기능은 아니다. 새 시험 개체에 한해 준비·장면·이름의 저장 절차로 합성 아기를 생성하며, 부화 장면을 사용자에게 보여 줬다는 검증으로 세지 않는다.

- 기준: 위 기준 커밋과 원본 미커밋 변경. 이번 시작 때 원본의 최신 코드·문서 13개 차이를 대조하여 갱신했다. 해시는 `.local/appearance-trial/native-baseline.json`, 갱신 전 사본은 `before-native-baseline/`에 보존한다.

- 자료: `.local/appearance-trial/native-pets/leaf/`와 `wing/`. 경로는 실행 코드 내부에서 고정하며 임의의 기존 펫 경로를 받지 않는다. `appearance.json`에 계열을 고정하고, 표시와 생활은 각각의 새 SQLite 저장소에 연결한다. 표식 없는 기존 자료나 계열 불일치 자료는 재생성·덮어쓰기하지 않고 중단한다. 실제 펫 자료를 읽거나 복사하지 않는다.
- 두 실행의 잠금·브라우저 저장소도 각 자료 폴더에 분리한다. 원본의 실행 중인 앱에 종료·재시작·활성화 요청을 보내지 않는다. 시험 모드는 시스템 알림과 실제 휴지통 처리를 비활성화한다. 메뉴와 이름표에 시험임을 표시하며 개별 종료 메뉴가 있다.

### 개별 검사와 인계

- 빌드·타입 검사 통과. 방향/배치 단위 검사 13개 통과.
