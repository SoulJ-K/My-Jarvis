## 3. 알: 첫 만남부터 부화 전까지 — v0.1 설계 확정

### 3.1 첫 만남과 상호작용

첫 실행에서 사용자는 완성된 캐릭터 목록이 아니라 **남색 바탕·금색 별무늬·보랏빛 외곽빛의 판타지형 알 하나**를 받는다. 반응 애니메이션은 소수의 짧은 동작으로 구성한다.

알은 짧은 클릭에 작은 흔들림으로 반응한다. 누르자마자 끌면 위치를 옮기고, 잠깐 누른 뒤 알이 밝아지면 왕복해서 문지르는 동작을 쓰다듬기로 구분한다. 쓰다듬기는 부드러운 크기·밝기 반응으로 표현한다. 일반 마우스로 이동과 돌봄을 구분하는 선택은 2026-09-26 [D-042](Jarvis_Pet_Decision_Log.md), 좌우뿐 아니라 대각선 왕복과 같은 투명 창 안의 알 경계 밖 놓기를 인정하는 보정은 2026-09-27 D-054를 따른다. 위치 이동·한 방향 이동·조작 취소는 쓰다듬기 성공으로 처리하지 않는다. 드래그할 때 살짝 굴러가는 연출은 설계 표현이며 구현·검증 완료로 표시하지 않는다.

**과거 기록 연결:** 2026-09-26 D-042 개별 작업에서는 돌봄 사건·경과의 저장과 재시작을 자동 검사했지만 실제 손맛은 통합 후 확인 대상이었다. 굴러가기 연출·부화 준비·아기 생활·성격 반영은 그 개별 작업의 범위 밖이었다. 당시 결과와 후속 확인은 [개발 기록](Jarvis_Pet_Development_Log.md)의 ‘알 돌봄과 경과 기록’, PR #20 후속 및 ‘2026-10-06: PR #39 병합 후 쓰다듬기 사용자 실사용 확인’을 함께 읽는다. 이 한계는 현재 제품 전체의 미구현 목록을 뜻하지 않는다.

알은 평소 감정을 크게 드러내지 않는다. 부화에 가까워질수록 움직임과 반응이 조금씩 늘어난다. 기쁨과 불편함 정도를 약하게 표현하고, 부화 직전에는 잦은 터치에 제자리에서 가볍게 통통 뛰는 반응을 줄 수 있다. 알도 타이머·알람·단순 리마인더를 수행하지만 **말하지 않는다**. 요청을 받았다는 반응과 알림 시점의 표현은 움직임과 별도 알림 표시로 구분한다.

### 3.2 부화 전 외형 입력 — 설계 고려

부화가 가까워지면 사용자가 상상한 아기 펫의 모습을 자연어로 묻고, 원하면 **“랜덤”**을 선택하게 하는 경험을 고려한다. 넓은 종족 계열부터 구체적인 창작 특징까지 참고할 수 있지만, 결과는 주문과 완전히 일치하는 복제품이 아니라 **그 방향에서 태어난 새 개체**다. 성장 후 모습까지 미리 고정하지 않는다. 이 입력 방식은 대화에서 합의한 방향이지만 **마지막 v0.1 필수 완료 목록에는 포함되지 않았으므로 구현 필수로 잠그지 않는다.**

- 사용자가 만든 창작 캐릭터의 특징은 입력으로 받을 수 있다.
- 실존 인물의 외형을 그대로 재현하는 요청은 받지 않고, 원하면 일반적인 특징으로 다시 표현하도록 안내한다.
- 기존 작품의 캐릭터를 그대로 복제하지 않고, 추상적인 특징을 참고한 새로운 펫으로 바꾼다.

입력 정책은 부화 경험의 일부다. 외형 생성 기술·검토 절차·재시도 방식은 아직 **설계 고려**이며 구현 방법을 확정한 것은 아니다.

**v0.2 후속 범위 — 2026-10-07:** 위 외형 입력·무작위 생성 구상은 기존 방향으로 보존하되, 외형 무작위 생성은 이번 구현에서 보류한다. 아래 입 제거와 부화 표현 보완을 외형 생성 기능 승인으로 확대하지 않는다.

### 3.3 부화 이벤트

부화 조건은 **시간을 기본으로, 알을 돌본 경험을 함께 반영**한다. 방치가 부화 실패나 죽음으로 이어지지는 않는다. 사용자가 없는 사이 조건이 충족돼도 실제 부화는 보류하고, 사용자가 볼 수 있을 때 전조와 연출을 진행한다.

**부화 준비 기준 — 2026-09-26 D-051 후속 결정:** 돌봄 없이도 누적 24시간이 지나면 준비된다. 인정된 직전 돌봄과 누적 경과 시간 기준으로 1시간 이상 떨어진 클릭·쓰다듬기는 건당 30분씩, 총 6시간까지만 앞당긴다(최저 18시간). 연타를 시간 단축으로 세지 않되 실제 돌봄 기록은 보존하기 위한 선택이다. 준비돼도 알로 기다리며, 첫 장면은 사용자가 메뉴의 **부화 함께 보기**를 선택할 때 시작한다. 정책과 변경 이유는 [D-051](Jarvis_Pet_Decision_Log.md), 실제 시간 경과 검증 여부는 개발 기록을 따른다.

연출의 순서는 다음과 같다.

1. 알에 금이 간다.
2. **감정구슬이 먼저** 알 밖으로 튀어나온다.
3. 알이 완전히 갈라진다.
4. 아기 펫이 나온 뒤 주변을 살핀다.
5. 아기는 사용자를 바라보고 조금 안심한 듯 가까이 오며 첫 반응을 나눈다.
6. **첫 교감 뒤** 이름을 짓는다.

**같은 창의 부화 표현 — 2026-09-30 사용자 선택 / [D-060](Jarvis_Pet_Decision_Log.md):** 알이 있던 투명창에서 부화가 이어지며, 아기가 나온 뒤에만 창을 넓힌다. 창이 넓어질 때 펫의 화면상 중심을 유지한다. 메뉴에서 시작한 장면은 차분한 움직임으로 자동 연결하되, 위 단계의 저장 지점마다 저장 성공 후에만 다음으로 간다. 첫 교감 뒤 이름 입력은 같은 창에서 아기 아래의 작은 카드에 둔다. 자동 말풍선은 추가하지 않는다. 2026-10-01 추가 선택에 따라 화면 하단에서 카드 공간이 부족할 때만 이름 단계의 아기를 필요한 만큼 위로 옮긴다.

**선택한 시안의 크기:** 알과 아기의 보이는 외형은 이전 시안 대비 약 80%, 알 창은 180×200, 아기 생활 창은 420×300이다(D-060). 이 비교 비율과 창 크기를 모든 외형에 적용할 최종 수치로 확대하지 않으며, 구현 구조는 기술 설계를 참조한다.

감정구슬은 부화 때 함께 나온 아기의 고유한 물건이다. 첫 반응은 낯섦과 알 시절부터의 익숙함이 섞인 느낌이다. 예를 들면 조금 다가오기, 구슬의 밝은 노랑 반응, 손이 있다면 작게 흔들기다. 첫 교감 후 이름 짓기는 v0.1 필수 경험이다. 대화에서는 이후 **한 차례만 이름을 변경**하는 방향도 정했지만, 마지막 v0.1 필수 완료 목록에는 변경권이 없다. 변경권은 **설계 고려**로 두고, 구체적인 대기 시간과 연출 길이는 구현하면서 정한다.

**v0.2 구현 예정 — 부화 위치와 연속 표현(2026-10-07):**

- 사용자가 **부화 함께 보기**를 선택하면 알이 있는 **현재 모니터 중앙**으로 이동하고, 부화부터 이름 짓기까지 그곳에서 진행한다. D-060의 기존 위치 유지·하단에서 이름 단계만 위로 옮기는 기준은 v0.1 이력이며, v0.2에서는 이 중앙 배치 요구를 우선한다. 이름 카드가 화면 안에 있고 아기와 겹치지 않아야 한다.
- 금 → 구슬 먼저 → 껍질 갈라짐 → 아기의 주변 살핌 → 첫 교감 → 이름 순서를 유지한다. 장면의 끊김을 줄여 연속 애니메이션으로 잇되 같은 개체와 기존 저장 경계, 저장 실패 시 다음 장면으로 진행하지 않는 원칙은 유지한다.
- 이름을 짓는 동안 감정구슬은 아기 좌·우 중 무작위 한쪽의 바닥 가까이에 둔다. 그 장면에서는 위치를 다시 뽑지 않고 유지하며, 살짝 굴러 구슬임이 보이게 한다. 아기·이름 카드와 겹치지 않게 배치한다. 구슬 위치 선택을 아기 외형 무작위 생성으로 해석하지 않는다.
- 이 변경은 부화 준비 시간이나 돌봄 단축 정책을 바꾸지 않는다. 자연 경과 부화·며칠 아기 생활의 새 검증을 뜻하지 않는다.

## 4. 아기의 생활과 표현 — v0.1 설계 확정

### 4.1 기본 생활

아기는 혼자 자고 깨며, 앉기·눕기·짧게 움직이기·쉬기를 반복한다. 초기 아기는 주로 한곳에 머물고, 아기 단계 안에서 시간이 지나면 이동 범위와 빈도가 조금 늘 수 있지만 넓게 돌아다니지 않는다. 커서가 가까워질 때에는 끊임없이 따라붙기보다 나비를 잠깐 쫓듯 반응한다. 놀이 종류는 **커서 쫓기와 감정구슬 놀이 두 가지**로 제한한다.

사용자가 화면을 가릴 때 언제든 아기를 드래그해 옮길 수 있다. 기본적으로 얌전히 들려가되, 자주 옮기거나 졸릴 때는 현재 상태에 맞는 반응을 보인다. 별도의 상태 확인 클릭은 두지 않는다. 클릭은 작은 입력창을 여는 동작이며, 짧은 대화나 요청이 끝나면 입력창은 자동으로 닫힌다.

**v0.2 구현 예정 — 외형·이동·내 자리:** 아기의 입을 제거하고 눈·몸짓으로 표현한다. 입 앞 좌표를 요구하지 않던 먹이 전달 원칙은 유지하며, 과거 문서의 ‘입에서 먹기’는 새 입 그림을 남겨야 한다는 뜻이 아니다. 먹는 모습은 입 없는 외형에 맞춰 표현한다. 상하좌우 가장자리와 네 구석까지 **보이는 몸 기준**으로 옮길 수 있어야 하며, 투명창 여백이 이동을 막지 않게 한다. 이름·구슬·먹이·카드가 잘리지 않는지도 함께 검토한다.

사용자가 옮긴 위치는 **내 자리**로 기억하고 재시작 뒤에도 유지한다. 재촉이 끝나면 그 자리로 복귀하며, 모니터 구성이 달라지면 화면 밖에 남지 않게 한다. D-058의 현재 실행 동안만 유지하던 위치 기준을 v0.2에서 확장하는 요구다. 평소의 조용한 생활은 유지하되 **6.4절 강한 재촉은 선택된 예외**다. 사용자가 드래그하는 동안 적극 재촉 행동은 멈춘다.

### 4.2 감정, 생활 상태, 관계는 서로 다르다

| 구분 | 뜻 | v0.1 표현 |
|---|---|---|
| 감정 | 지금의 마음. 기쁨·불편함·호기심 같은 순간 반응 | 표정·행동·감정구슬. 아기 곁 자동 문구는 사용하지 않음 |
| 생활 상태 | 몸의 필요. v0.1에서는 **배고픔·졸림 두 가지** | 먹이 오브젝트, 하품·꾸벅임·수면 |
| 관계 | 사용자와 쌓은 장기적인 신뢰와 익숙함 | 다가오기·쉬는 거리·터치 허용·구슬을 보여주는 방식 |

이 셋을 사용자에게 숫자나 게이지로 표시하지 않는다. 일정과 알림처럼 정확해야 하는 정보는 명확하게 표시한다. 기쁨은 손이 있으면 흔들기·만세, 가능한 신체 부위나 표정의 변화, 작은 통통 뛰기로 보일 수 있다. 불편함은 움찔하기·몸을 돌려 등을 보이기·잠깐 거리두기로, 호기심은 고개 갸웃하기와 주변이나 커서 살피기로 표현한다. 외형에 없는 귀·꼬리·손 동작을 모든 펫에 강요하지 않는다.

### 4.3 감정구슬

감정구슬은 배고픔·졸림 표시기가 아니라 **어린 펫의 감정 표현을 돕는 자기 물건**이다. 아기 때는 굴리며 놀거나 사용자에게 보여줄 수 있다. **v0.1 기준에서는** 늘 화면에 떠 있어야 하는 것은 아니고, 놀 때·감정이 강할 때·사용자에게 보여주고 싶을 때 자연스럽게 드러나는 방향이었다. 사용자는 구슬의 색이나 감정 상태를 임의로 바꿀 수 없다.

칭찬을 들은 아기의 구슬은 머리 위로 올라와 **밝은 노랑**으로 빛날 수 있다. 불편하거나 실수해 미안해할 때에는 잠깐 **주황 계열** 반응을 사용할 수 있다. 감정별 전체 색상표는 아직 미정이다. **v0.1의 관계 표현 구상에서는** 관계가 깊어지면 구슬을 더 쉽게 보여주거나 만지도록 허용할 수 있고, 거리를 둘 때에는 숨길 수 있었다. 성장 후에는 표정·행동·말이 풍부해지므로 구슬의 감정 전달 비중이 줄지만, 물건 자체는 계속 남는다.

**v0.2 구현 예정 — 항상 보이는 구슬과 거부 표현:** 아기 때 감정구슬은 **항상 표시**한다. 위의 가끔 드러내기·거리두기 때 숨기기는 v0.2 아기에 적용하지 않는다. D-029의 소지품·비수치 표현 원칙은 유지하면서 표시 방식만 후속 결정으로 바꾼다.

- **빨강**은 아기가 상호작용을 거부하거나 혼자 있고 싶다는 뜻이다. 입력창의 상호작용 수락·거부와 **같은 판단**을 사용한다. 다시 받아주는 상태가 되면 평소색으로 돌아가며, 별도의 임의 타이머로 빨강을 유지하거나 해제하지 않는다.
- 수락·거부의 구체 임계값과 전체 색상표는 미정이다. 기존 노랑·주황은 표현 예시이며 새 거부 판단을 대신하는 확정 색상표로 읽지 않는다. 상시 표시를 감정·관계의 숫자나 게이지로 바꾸지 않는다.
- **구슬의 빨강**은 아기가 상호작용을 거부하는 상태이고, **몸의 붉은 재촉**은 사용자의 남은 일을 챙기는 상태다. 두 의미를 합치거나, 재촉한다는 이유로 구슬을 빨갛게 만들지 않는다.

### 4.4 배고픔과 먹이

배고픔은 **먹이 오브젝트의 등장**으로 먼저 알린다. 오브젝트는 펫 근처에 생기지만 펫이 혼자 먹을 수는 없는 거리에 둔다. 사용자가 드래그해서 일정 범위 안에 놓으면 아기가 마지막 한두 걸음을 다가와 먹는다. 입 앞의 정확한 좌표에 놓도록 요구하지 않는다.

v0.1의 먹이는 종족 공통 **가상 먹이 한 종류**다. **v0.1 설계에서는** 아기가 이것을 항상 먹고 편식하거나 거부하지 않는다. 먹이는 고정된 속도로 소비되며 먹으면 사라진다. 먹은 뒤 짧게 만족하고, 원래 졸렸다면 조금 쉬거나 잠들 수 있다. 먹이 오브젝트가 오래 남아 화면을 차지하지 않도록 사라졌다가 나중에 다시 나타난다. 계속 놓치면 다음 등장 때 크기나 반짝임으로 배고픔을 은근히 알릴 수 있지만, 반복해서 보채거나 경고처럼 압박하지 않는다.

오래 먹지 않아도 생존 위협이나 성장 실패는 없다. 성장 속도에는 약한 영향이 있을 수 있고, 식사 경험은 이후 입맛의 차이를 만드는 자료로 남긴다. 여러 종류의 먹이와 편식은 **미래 비전**이다.

**v0.2 구현 예정 — 먹기 간격과 생활 보류:** 일반 먹이와 4.7절의 휴지통 간식은 **공통 15분 간격**을 사용한다. 간격은 먹기 **완료 시점**부터 세며, 그동안 새 음식·간식을 먹지 않는다. 6.4절의 일정 우선 조건에서도 새 먹기를 보류한다. 이는 위 ‘항상 먹음’에 추가되는 생활 조건이며 편식 기능을 넣는 것이 아니다. 못 먹는다는 반응은 눈·몸짓으로도 보여주고 문자만으로 거부하지 않는다. 이미 먹는 중이면 다 먹게 한다.

### 4.5 졸림, 수면, 실제 시간

아기는 졸리면 하품하고 꾸벅거리며 움직임이 줄고, **어디서든 스스로 잠들 수 있다**. 잠을 못 자서 보채는 경우, 사용자가 구석이나 거처로 옮겨주면 재우는 돌봄으로 해석할 수 있다. 같은 터치라도 자는 아기를 반복해서 깨우면 방해로 받아들인다. 거처의 구체 형태는 구현 가능성을 확인한 뒤 정한다.

**v0.2의 예외:** 6.4절의 일정 우선 조건에서는 새 잠들기를 보류하고 이미 잠들었다면 깨운다. 다른 일정의 조건이 남아 있으면 보류를 유지한다. 이는 사용자의 반복 터치와 다른 원인이며, 기존의 어디서든 잠들기·식후 수면보다 이 조건을 우선한다.

실제 시간은 앱을 사용하지 않는 동안에도 흐른 것으로 반영한다. v0.1은 고정 시간대를 사용한다. 낮에는 기본 활동, 밤에는 활동량 감소, 늦은 밤에는 졸림과 눈부심 같은 반응이 나타날 수 있다. 아침은 별도 반복 루틴보다 사용자가 다시 나타났을 때의 **재등장 이벤트**로 다룬다. 컴퓨터를 켰거나 오래 자리를 비웠다가 돌아온 경우 모두 짧게 반가워하고 평소 생활로 돌아간다.

장기간 부재해도 배고픔·졸림이 극단으로 악화되지 않는다. 돌아왔을 때 자고 있거나 쉬고 있거나 구슬을 가지고 놀던 것처럼 자연스럽게 이어진다. 부재 시간은 기억할 수 있지만 벌점으로 취급하지 않는다.

**수면 후 기상 표현 — 2026-09-30 사용자 선택 / [D-059](Jarvis_Pet_Decision_Log.md):** 실행 중 보이던 수면이 끝나면 손 없는 임시 아기는 좌우로 살짝 흔들리고 몸을 낮춘 뒤 높이를 달리해 두 번 통통 뛴다. 현재 시안은 약 1.26초이며 외형별 최종 움직임 수치는 아니다. 기상 몸짓을 먼저 보여주고 이어서 진행 중인 식사·거리두기를 표현한다. 재회 몸짓은 기상 뒤 기존 재회 표시 조건이 남아 있을 때 보인다. 이미 깨어 있는 상태로 앱을 다시 켜거나 화면을 다시 불러오면 기상을 재생하지 않는다. 운영체제의 움직임 줄이기 설정에서는 기상 움직임을 생략한다. `zZ`는 실제 수면이 끝나면 즉시 사라진다.

### 4.6 집중 모드와 방해 수준 — 설계 고려

집중 모드의 아래 동작은 대화에서 정한 경험 방향이다. 마지막 v0.1 필수 완료 목록에 없으므로 **v0.1 구현 필수로 보지 않는다.** 돌봄이 업무를 방해하지 않아야 한다는 원칙은 v0.1에도 적용한다.

사용자가 집중 모드를 켜면 **Jarvis Pet의 행동만** 조용해진다. 먼저 관심을 요구하는 빈도와 움직임을 낮추고, 구석에서 쉬거나 잠들 수 있다. 알람과 중요한 리마인더는 예외로 알려준다. 모드는 배고픔·졸림 등의 시간 흐름을 멈추지 않으며 **표현 강도만 바꾼다**. 끝날 때에는 외형에 맞는 가벼운 몸짓으로 평소 행동으로 돌아갈 수 있다. 오래 켜져 있을 때의 확인 표현은 후속 설계에서 정한다.

자연어로 켜고 끄는 방향은 합의됐지만 기본 지속 시간, 해제 조건과 운영체제의 집중 모드 연동은 미정이다. 운영체제 전체 설정 연동은 **미래 비전**이다.

집중 모드는 v0.2에서도 이번 선택 범위에 포함되지 않는다. 이 검토안을 이유로 6.4절에 선택된 재촉을 생략하지 않으며, 향후 집중 모드와 재촉의 관계는 후속 설계에서 정한다.

### 4.7 휴지통 간식 — v0.2 구현 예정

아기를 **macOS 휴지통으로 드래그**하거나 입력창에 **“간식먹어” / “간식먹을래?”**라고 입력하면 간식 흐름을 시작한다. 가상 먹이와 달리 실제 파일의 영구삭제가 뒤따르므로, 시작 요청 자체를 삭제 승인으로 해석하지 않는다.

- **사용자가 자신의 휴지통에서 일반 파일 최대 2개를 직접 선택**하며 폴더는 제외한다. 2026-10-07 후속 선택으로 정확한 버린 순서를 보장하기 어려운 자동 선택안을 대체했다.
- 삭제할 대상의 이름과 **영구삭제되어 되돌릴 수 없다는 의미**를 먼저 보여주고 최종 명시 확인을 받는다. 그 확인을 받은 대상만 실제 완전삭제한다. 한 번의 확인을 전체 휴지통이나 향후 삭제 권한으로 확대하지 않는다.
- 일반 먹이와 같은 15분 간격, 일정에 따른 새 먹기 보류, 진행 중인 먹기는 끝까지 먹는 원칙을 적용한다. 거부·보류는 비언어 반응과 필요한 기능 안내로 전달한다.
- 파일을 가리키는 연결인 심볼릭 링크, 하나처럼 보이는 앱 묶음, 외장 디스크의 휴지통, 일부 삭제 실패의 처리는 구현 전 검토 항목이다. 삭제와 먹기 표현의 성공·실패 연결도 검토하며 실패를 먹기 완료처럼 표시하지 않는다. 새 기술 방식은 이 문서에서 확정하지 않는다.

이 흐름의 확인 문구는 아기의 말이 아니라 파일 작업 안내다. 6.3절의 **‘했어요’ 기록 되돌리기**와 달리 **영구삭제 되돌리기는 제공한다고 약속하지 않는다**. 이번 문서 작성에서는 실제 휴지통 접근·파일 삭제를 수행하지 않는다.

## 5. 관계, 성격과 초기 기억

### 5.1 관계의 행동 표현 — v0.1 설계 확정

관계가 깊어질수록 더 가까운 곳에서 쉬기, 이름을 부르면 반응하기, 먼저 가볍게 다가오기, 잘 때 사용자 곁을 선호하기, 감정구슬을 보여주기 같은 변화가 나타난다. 외형에 맞는 안정감 표현을 쓴다. 처음에는 머리 정도의 터치를 허용하고, 신뢰가 쌓이면 다른 부위를 허용할 수 있다. 싫어하는 부위를 반복해서 만지면 피하거나 잠시 거리를 둔다. 관계는 일시적으로 멀어질 수 있지만 **회복 가능**하며 펫이 사용자를 영구히 떠나지는 않는다.

아기의 먼저 다가오는 빈도는 낮다. 자율적 접근은 어린이 시기에 더 활발해지고 성체에서는 다시 절제된 방향이다. 칭찬에는 구슬·표정·몸짓으로 뚜렷하게 반응한다. 부재 뒤 재회는 조금 더 반가울 수 있지만 길게 관심을 요구하지 않는다.

**v0.2 후속 관계:** 구슬을 보여주는 관계 표현은 상시 표시 상태에서의 움직임·밝기·접촉 허용 등으로 읽으며, 구슬을 숨기는 방식은 사용하지 않는다(4.3절). 평소 접근 빈도와 별개로, 6.4절의 강한 재촉에서는 선택된 적극 행동을 한다. 이를 애착 수치 증가나 상호작용 수락으로 간주하지 않는다.

### 5.2 선천 기질과 후천 경험 — v0.1 경험 기록 필수 / 이후 성격 반영은 설계 고려

태어날 때 약한 기질의 차이가 있고, **함께 지낸 경험이 더 크게** 성격을 만든다. 성격·선호·비선호는 사용자가 목록에서 선택하거나 수치로 확인하는 결과물이 아니다. 같은 돌봄을 받아도 반응이 약간 다를 수 있고, 나중에 행동을 돌아보면 그 성향이 납득되는 정도를 지향한다.

**v0.1 필수 구현:** 아기 때의 상호작용·돌봄 경험을 내부적으로 기록하고 앱 재시작 뒤에도 유지해 이후 성장에 활용할 준비를 한다.

**이미 선택한 최소 기록:** 2026-09-26 [D-048·D-049](Jarvis_Pet_Decision_Log.md)는 식사·접촉·완료 수면과 칭찬·재회·반복 접촉·두 놀이의 최소 경험 기록을 다룬다. 실제로 없었던 돌봄을 부재 중 경험으로 만들어 넣지 않는다. 저장 형식과 실제 확인 결과는 각각 기술 설계·개발 기록을 따른다.

**후속 설계 고려:** 식사·수면·놀이·칭찬·혼남·실수 뒤 위로·터치·부재·재회 등을 어디까지 수집할지의 확장 범위, 보존 기간, 이후 성격·선호에 반영하는 규칙은 아직 정하지 않았다. 단기 메모는 용도가 끝나면 사라지고, 사용자가 명시적으로 기억하라고 한 내용은 장기 기억으로 다루는 원칙을 둔다. 이후 먹이·놀이·터치 선호는 오래가되 경험에 따라 **서서히** 달라질 수 있다.

작은 실수는 아기다운 행동으로 허용한다. 예를 들어 짧은 표현을 헷갈리거나 다시 묻고, 필요하면 고개 숙이기와 같은 반응을 할 수 있다. **v0.1의 “미안…” 같은 짧은 말 예시는 v0.2에서 눈·몸짓·구슬의 비언어 표현으로 대체한다**(6.1절). **중요 알람 누락이나 위험한 파일 조작 같은 실수는 캐릭터 표현으로 허용하지 않는다.** 실수 뒤 사용자의 반응도 초기 경험으로 남길 수 있다.

**v0.2 구현 예정 — 기억의 구분:** 아기는 6.3절에서 사용자가 명시한 완료·미완료 결과를 기억한다. 배너가 표시됐거나 사용자가 응답하지 않았다는 이유로 일을 했다고 만들어 기록하지 않는다. 알림 확인과 실제 완료·취소는 서로 다른 기록이다. 6.4절의 개체별 선호 재촉 행동과 4.1절의 내 자리는 재시작 뒤에도 유지한다. 이는 모든 성격·선호 계산이나 자유 대화의 장기 기억을 구현한다는 뜻이 아니다.

## 6. 말과 비서 행동의 성장

### 6.1 알·아기의 표현 — v0.1 설계 확정

알은 말을 못하며 기본 알림에 움직임으로 반응한다. 아기는 감정과 생활 상태를 표정·움직임으로 표현하고, 실제 수면 중에는 작은 `zZ` 기호를 보인다. 아기 곁에 짧은 문구가 자동으로 뜨지는 않는다. **v0.1 설계에서는** 사용자가 직접 연 입력창에서 “응”, “시러”, “좋아”처럼 짧은 말로 요청 결과를 알려주고, “존댓말 해”라고 요구하더라도 아기 말투를 유지하는 방향이었다. **v0.2에서는 아래 비언어 응답으로 대체한다.**

아기는 **짧고 명확한 요청**을 이해한다. 사용자가 연 입력창에서 빠진 정보를 되묻고, 복잡한 문장을 이해한 척 실행하지 않는다. 기존 “몇 시?” 같은 예시는 v0.2에서 아기의 발화가 아닌 기능적 시간 확인 안내로 구분한다. 감정·일상 반응은 아기의 표정·움직임으로, 요청 결과와 시간·내용이 중요한 알림은 각각 입력창과 별도 알림 표시로 분리한다. 저장 실패와 오류도 필요한 안내를 유지한다. 기본 비서 기능은 알람·타이머·단순 리마인더이며, 알과 아기 모두 기능적 정확성을 지켜야 한다.

**과거 설계 고려 — v0.1 필수 밖:** 알림의 중요도를 **일반 / 중요** 두 단계로 나누고, 일반은 한 번 전달하며 중요 알림이 미확인되면 더 눈에 띄게 다시 알리는 방향이었다. `이따 다시 알림`의 기본 10분과 기다리는 동안 보채지 않는 동작도 당시 구상이었다. **v0.2에서 선택된 재알림·재촉은 6.3~6.4절로 대체**한다. 일반/중요 구분은 여전히 검토 항목이며, v0.2 아기 카드·재알림을 ‘중요’ 일정에만 제한하지 않는다. 실제 실행 권한이 필요한 컴퓨터 작업은 사용자 허용을 전제로 한다.

**v0.2 구현 예정 — 말하지 않고 이해·반응하기:** “뭐해”, “배고파”, “보고싶었어” 같은 짧은 생활 표현을 이해하고 **말로 답하지 않는다**. 눈·몸짓과 감정구슬의 색·밝기로 반응한다. 수락·거부는 4.3절의 구슬과 같은 판단을 사용한다. 펫의 상태·행동을 정하는 **Pet Brain**을 중심으로 외부 AI 없이 기본 반응을 유지한다. 생활 표현별 동작·색을 이 예시만으로 일대일 확정하지 않는다.

입력창은 기존 메뉴바 진입과 아기 클릭 진입을 유지한다. 알에서는 아기 전용 도움말을 숨기며, **알 우클릭으로 입력창을 여는 제안은 철회되어 구현에서 제외**한다. Enter 전송을 개선해 한글 입력기의 글자 조합 중 글자 누락·중복 전송이 없게 하고, “구슬놀이 / 구슬 놀이” 같은 띄어쓰기·간단한 표현 변형을 허용한다. 시간·오류·등록·확인·삭제 안내와 카드의 글은 아기가 하는 말과 구분한다. 긴 대화·자유로운 AI 대화는 이번 범위에 포함하지 않는다.

### 6.2 성장 후 방향 — 미래 비전

| 단계 | 대화와 행동의 방향 | 비서 역할의 방향 |
|---|---|---|
| 어린이 | 짧은 문장, 뚜렷한 취향·호기심과 가벼운 제안 | 간단한 정리·분류 제안 |
| 청소년 | 이전 경험과 사용자 패턴을 더 잘 연결 | 여러 단계 업무와 파일·정보 정리 보조 |
| 성체 | 성숙한 표현, 가끔 남아 있는 어린 시절 말투 | 복잡한 업무와 여러 도구의 조합, 먼저 챙기는 제안 |

성장은 **외형·행동·비서 능력**이 함께 달라지는 사건으로 보여준다. 외형은 같은 개체임을 알아볼 수 있도록 핵심 특징을 이어받고, 행동과 애정 표현은 성숙해진다. 이해·제안·수행 능력의 변화는 메뉴에만 갑자기 나타나지 않고 성장 직후 행동이나 짧은 대화로 드러난다. 실제 작업 실행 권한은 성장 단계와 별개로 사용자가 허용한 범위에서만 주어진다. 성체의 애정 표현은 사용자를 챙기는 비서 행동과 이어진다. 구체 기능 목록과 사용자 허용 규칙은 후속 버전에서 확정한다.

**2026-10-07 장기 방향:** 같은 일을 점점 잘 챙기는 흐름은 **알의 알려주기 → 아기의 결과 기억 → 유아/어린이의 후속 행동 → 청소년의 패턴 이해 → 성체의 허용받은 수행**이다. 여기서 유아/어린이는 장기 방향의 표현이며, 새 성장 단계의 구현 조건을 확정한 것은 아니다. 이번에 선택된 아기의 결과 기록·재알림은 v0.2에 포함하지만 후속 성장 전체나 자동 완료 감지, 파일·시스템 권한의 자동 획득은 포함하지 않는다.

### 6.3 알림 확인·완료와 머리 위 카드 — v0.2 구현 예정

**기본 전달:** 모든 타이머·알람·리마인더는 시스템 배너와 소리로 전달한다. 최초 알림과 동시에 앱 팝업을 자동으로 띄우지 않는다. 운영체제 제한·앱 종료·절전 중 정시 전달을 보장한다고 설명하지 않는다. 시스템의 `shown`(표시 신호)은 배너·소리를 실제로 보고 들었다거나 확인했다는 증거가 아니다.

| 상황 | 알 | 아기 |
|---|---|---|
| 최초 알림 | 시스템 알림만 전달하고 앱 안 기록 유지. 실패·불명확이어도 자동 추가 팝업 없음 | 시스템 알림 우선. 최초 시점 자동 카드 없음 |
| 시스템 배너 클릭 | 기존 앱에서 해당 알림을 확인 | 해당 알림 확인과 함께 **즉시 머리 위 카드**를 열어 결과 입력 기회 제공 |
| 최초 알림 후 2분 동안 사용자 미확인 | 자동 추가 팝업 없음 | 시스템 전달 성공·실패·불명확 모두 **머리 위 작은 카드** 표시 |

‘시스템 전달 실패 때만 카드 표시’라는 이전안은 2분 미확인 기준으로 대체한다. 배너 클릭 또는 앱에서의 명시 확인을 알림 확인으로 취급한다. 단순 창 열기·배너 사라짐·표시 신호만으로 확인하거나 일을 완료 처리하지 않는다. 앱에서 명시 확인한 뒤 다시 카드로 들어가는 세부 방법은 검토 항목이며, **알림을 확인했다는 사실과 실제 일을 완료했다는 사실은 다르다.**

카드에는 **일정 제목 + ‘했어요’ / ‘아직이에요’ / ‘취소할게요’**를 바로 둔다. 2026-10-07 후속 사용자 결정으로 ‘더 보기’와 추가 메뉴를 없애고 작은 말풍선으로 변경했다.

- **했어요:** 사용자가 실제 일을 마쳤다는 결과를 기록한다. 실수로 눌렀을 때 5초 동안 완료 기록 되돌리기를 제공한다.
- **아직이에요:** 같은 카드 안에서 **5분 / 30분 / 직접입력** 중 재알림 시간을 매번 선택한다. 10분 기본값이나 고정 반복으로 바꾸지 않는다. 선택한 재알림 시각에는 **시스템 배너·소리와 카드를 즉시 함께 표시**하며 다시 2분 기다리지 않는다.
- 여러 미완료 일정은 **카드 하나**에 모으되 가장 오래 기다린 일정부터 보여주고 나머지는 개수로 묶는다. 응답은 일정마다 개별 처리하며 하나의 응답을 전체 완료로 확대하지 않는다. 가장 오래 기다린 순서를 계산할 세부 기준은 기술 검토에서 명확히 한다.
- 시간이 지난 일정도 **취소할게요**로 취소할 수 있다. 취소를 실제 완료로 기록하지 않는다. 해당 일정의 후속 상태만 해제한다.
- 완료·취소하면 **그 일정의** 재알림·재촉·생활 보류를 해제한다. 다른 일정에 필요한 상태는 유지하고, 남은 조건이 없으면 평소 모습·생활로 복귀한다.

입력창 목록은 **진행 중 타이머·알람·리마인더를 위**, **시간이 지난 미확인 알림을 아래**의 두 구역으로 나눈다. 진행 중은 종료·예정 시각이 빠른 순이며 새로 등록한 일정이 지난 미확인 알림 아래로 밀리지 않게 한다. 새 항목도 위쪽 구역의 종료·예정 시각순을 따른다. 상태는 짧은 글로, 여러 색상·블록 장식을 섞지 않고 단정하게 표시한다. 이 목록의 예정 시각순과 머리 위 카드의 오래 기다린 순서는 서로 다른 기준이다. 타이머의 메뉴바 표시·숨김·고정 교체 여부는 알림 전달에 영향을 주지 않는다. 타이머 설정·표시의 상세 규칙은 [D-062](Jarvis_Pet_Decision_Log.md#v02-decisions)와 [기술 설계 8.3절](Jarvis_Pet_Technical_Design.md#v02-implementation-plan)을 따른다.

### 6.4 재촉과 생활 우선순위 — v0.2 구현 예정

재촉은 남은 일을 챙기는 행동이며, 아기의 상호작용 거부·관계 악화와 구분한다. **재알림에서 사용자가 명시적으로 ‘아직이에요’를 다시 선택할 때** 강도를 높인다. 시간이 지났거나 응답이 없다는 이유만으로 강도나 주기를 강화하지 않는다. 최초 아직이에요에서 약한 재촉과 재알림 예약을 함께 시작하고, 재알림에서도 아직이에요를 선택하면 강한 재촉으로 올린다.

| 표현 | 선택된 요구사항 |
|---|---|
| 약한 재촉 | 기본 크기 대비 **10% 확대 + 몸의 붉은 변화**. 정확한 색상은 미정 |
| 강한 재촉 | 기본 크기 대비 **20% 확대 + 몸이 붉어짐**. 정확한 색상은 미정 |
| 여러 일정 | 현재 필요한 **가장 강한 단계 하나**만 표현. 일정을 더해 크기를 누적 확대하지 않음 |
| 유지·해제 | 해당 일정 완료·취소까지 유지. 잠깐 붉어진 뒤 자동 평소 복귀하지 않음. 해제 뒤에도 다른 일정이 요구하는 단계는 유지 |

강한 재촉의 적극 행동은 **A. 화면 아래에서 통통 뛰기 / B. 커서 근처로 따라갔다가 바라보기**다. 아기마다 다른 선호 행동을 유지하고 재시작 뒤에도 보존한다. 모든 아기가 A와 B를 번갈아 하는 방식으로 바꾸지 않는다. 사용자 입력·클릭을 방해하지 않아야 하며, 사용자가 아기를 드래그하는 동안 중지한다. 메뉴바의 화난 표정·빨간 배경안은 선택되지 않았다.

한 번의 적극 행동은 **5초**다. 행동 간격은 **60 → 45 → 30 → 최소 15초**이며, 재알림에서 ‘아직이에요’를 다시 선택할 때 단축한다. 무응답·단순 시간 경과로 단축하지 않는다. 행동 한 번의 종료가 재촉 상태의 종료는 아니다. 해당 재촉이 끝나면 기억한 내 자리로 돌아가고, 다른 일정이 요구하는 재촉은 계속 유지한다.

**먹기·수면과의 우선순위:** 타이머·알람·리마인더가 **3분 이하로 임박**하거나 **‘아직이에요’ 상태**이면 새 먹기와 잠들기를 보류한다. 이미 먹는 중이면 끝까지 먹고, 이미 잠든 상태면 깨운다. 일반 먹이와 휴지통 간식에 동일하게 적용한다. 완료·취소한 일정의 조건만 해제하며 다른 일정의 조건이 남아 있으면 보류를 유지한다. 미확인이라는 사실만으로 임의의 재촉 강화 규칙을 추가하지 않는다.

## 7. 다음 성장에 남겨둘 원칙 — 설계 고려 및 미래 비전

알 → 아기의 확정된 부화 기준은 3.3절을 따른다. 아래는 아기 이후 성장에 남겨둔 방향이며 v0.1 구현 약속이 아니다. v0.2도 6.3~6.4절의 아기 기능까지이며, 아래 후속 성장의 구현 승인을 뜻하지 않는다.

- **설계 고려:** 아기 이후 성장에는 시간이 기본 보장을 제공하고, 돌봄·관계·경험은 속도와 성향에 약하게 영향을 준다. 방치로 성장 자체를 막지 않는다.
- **설계 고려:** 사용자가 없는 사이 성장 조건이 충족돼도 실제 성장 연출은 사용자 앞에서만 진행한다. 성장 전에는 행동·구슬 반응 같은 전조를 보인다. 아기 → 어린이 연출은 v0.1에서 구현하지 않는다.
- **설계 고려:** 어린 시절의 긍정·부정 경험은 성체 성향까지 이어질 수 있다. 다만 성격을 `행동 몇 회 → 특성 획득` 공식처럼 노출하지 않는다.
- **미래 비전:** 어린이·청소년·성체의 상세 성장 조건, 먹이 종류와 취향, 사용자 생활 패턴에 맞춘 시간 반응, 복잡한 업무 제안은 각 후속 버전에서 정의한다.
- **미래 비전:** 전체 성장 체계가 완성된 뒤 사용자가 원하면 바로 성체로 시작하는 선택지를 검토한다. 기억·성향의 초기화 방식은 그때 결정한다.
