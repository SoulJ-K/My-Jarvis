# ADR-001. 같은 펫을 유지하는 SQLite 저장

> 편집 상태: **2026-10-06 문서 정리본 / 문서 간 내용·참조 검수 완료.** 기존 SQLite 선택의 확정 상태와 이번 문서 편집 상태를 구분한다.

## 문서 작성·읽기 규칙

- **원본과 사본:** 최종 원본은 `/Users/rkfrk/Desktop/My Jarvis`의 프로젝트 문서다. GitHub는 승인된 변경 기록을 확인하는 곳이며 Notion은 읽기·확인용 사본이다. 수정은 프로젝트 문서에서 하고 검토 후 사본에 반영한다. 워크트리의 수정본은 통합 검수 후 원본에 반영한다.
- **역할:** 이 ADR(기술 결정과 이유를 남기는 기록)은 펫 저장 도구의 선택 이유·대안·제약, 저장 형식과 변환·복구·호환성 근거를 맡는다. 제품 범위는 PRD, 결정의 요약과 후속 관계는 Decision Log, 구현 구조는 기술 설계, 실행·통합·사용자 확인 이력은 개발 기록에 둔다.
- **갱신 시점과 방법:** 저장 방식·형식·복구·호환성에 중요한 변경이 생기면 기존 파일을 갱신한다. 과거 선택 이유와 당시 제약을 지우지 않고, 후속 결정 번호·날짜·해당 형식을 붙여 무엇이 바뀌었는지 연결한다. 검토 중인 대안은 확정 결정과 분리한다.
- **읽는 기준:** 확정된 선택, 미정·제안, 형식 도입 당시 이력, 실제 구현·검증을 구분한다. v1~v5는 저장 형식 번호이며 제품 버전이나 전체 기능 완료를 뜻하지 않는다. 과거의 미구현·미검증은 해당 시점의 범위로 읽고 후속 결과를 함께 확인한다.
- **근거와 한계:** 검사 기록에는 당시 환경·자료·확인 범위와 실패·미검증 항목을 보존한다. 임시 자료 검사와 실제 사용자 자료 변환, 자동 검사와 사용자 확인을 서로 대신하지 않는다. 공식 문서의 보장을 앱에서 모두 검증한 것으로 쓰지 않는다.
- **날짜와 참조:** 최초 결정일과 후속 변경일을 구분하고 관련 결정 번호·문서·절 연결을 유지한다. 제목이나 연결 대상을 바꾸면 참조를 대조한다. 고유 기록을 다른 문서로 옮길 때는 대상에 보존된 사실을 확인한 뒤 중복을 줄인다. 문서 수정일은 구현·검사일을 대신하지 않는다.
- **펼침과 요약:** 제목·이 규칙·현재 유효한 결정은 항상 보이게 두고 대안 비교·과거 변경 상세는 중첩 없이 접는다. 접혔다는 이유로 결정이 무효가 되지는 않는다. 상단의 최근 변경 요약은 새 변경 때 교체하고 이력은 기존 결정·개발 기록에 남긴다. 이 규칙만으로 다른 문서 수정이 승인되지는 않는다. Notion 가져오기의 접기·펼침 상태 보존은 별도 확인 사항이다.

## 결정 상태와 문서 범위

- 최초 결정일: 2026-09-26
- 상태: SQLite 선택 확정(D-039). 아래 v1~v5는 저장 형식의 변경 이력이며 제품 버전 번호가 아니다. 검사 결과와 미검증 항목은 각 기록 당시의 범위로 읽는다.
- 관련 결정: [Decision Log D-006·D-039·D-042·D-047·D-048·D-049](Jarvis_Pet_Decision_Log.md)

ADR은 기술 선택의 이유·대안·제약을 남기는 기록이다. D-006의 별도 ADR 요구에 따라 이 문서를 만들었다. Decision Log에는 선택과 이유의 요약을, 여기에는 저장 형식·실패 처리·호환성 근거를 둔다. 구현 구조는 기술 설계, 개별·통합 검사와 사용자 확인 이력은 개발 기록을 따른다.

## 현재 유효한 결정과 확인할 사항

- **저장 선택:** SQLite와 Electron 내장 `node:sqlite`의 `DatabaseSync`를 사용한다. SQLite는 별도 서버 없이 기기 안의 파일에 표 형태로 정보를 저장하는 도구다. 외부 SQLite 연결 패키지는 추가하지 않았다.
- **같은 펫의 연속성:** 알의 식별자를 유지하며 부화 진행·이름·아기 생활·최소 경험·사회 상태를 같은 `pet.sqlite3`에 저장한다. 관련 상태와 경험은 전부 저장하거나 전부 취소하는 묶음으로 처리한다. 문서에 기록된 최신 형식은 v5이며 이전 v4 앱에서 열 수 없다.
- **자료·표현 경계:** 대화 원문·커서 좌표는 저장하지 않고 감정·관계 내부값은 제품 화면으로 보내지 않는다. 경험 보존 기간과 반응 수치 조정은 미정 사항으로 구분한다.
- **확인할 사항:** 실제 사용자 자료 변환·사본 복원 사용자 경험·정식 배포용 설치 앱·장기 저장량은 기록된 검사로 검증됐다고 볼 수 없다. 후속 검사와 사용자 확인은 개발 기록을 함께 읽는다.

**최근 문서 정리:** 현재 결정과 v1~v5 도입 당시 상세·검증 기록을 분리하고 대안 비교와 과거 상세에 접기 구조를 적용했다. 제품 결정 변경이나 앱 재검사를 뜻하지 않는다.

## SQLite·내장 연결 방식의 선택 이유와 대안

SQLite와 Electron에 포함된 `node:sqlite`의 `DatabaseSync`를 사용한다. SQLite는 별도 서버 없이 기기 안의 파일에 표 형태로 정보를 저장하는 도구다. JSON은 초기 알 정보만 저장하기에는 충분했지만, 이후 상태와 경험을 한 묶음으로 기록할 때 직접 구현해야 할 부분이 늘어난다. SQLite의 트랜잭션은 여러 변경을 전부 저장하거나 전부 취소하는 방식으로, 일부 기록만 남는 일을 줄인다.

외부 SQLite 연결 패키지는 추가하지 않았다. 채택 당시 Electron 실행 파일에서 내장 모듈이 실제로 동작하므로 별도 네이티브 모듈 설치·재빌드 부담을 늘릴 이유가 없다. 동기 방식은 저장 작업이 끝날 때까지 호출한 실행 흐름이 기다리는 방식이다. v1 당시에는 한 알의 시작 시점에만 작은 읽기·쓰기를 했다. v2부터는 실행 중 돌봄 사건과 경과 시간을 저장하도록 쓰기 연결을 유지했다. 이후 기록량이 늘면 처리 시간을 측정한 뒤 별도 실행 영역을 판단한다.

## 저장·실패 처리의 공통 원칙

펫 자료는 `app.getPath('userData')/pet/pet.sqlite3`에 두고 프로젝트 코드·GitHub·화면의 브라우저 저장소와 분리한다. 검사는 운영체제 임시 폴더의 자료를 사용하며 실제 사용자 펫 자료와 구분한다.

손상·빈 기존 파일·미지원 형식·필수 기록 누락·권한 문제·저장 실패를 새 알이나 새 생활 기록의 생성으로 숨기지 않는다. 시작 시 저장소 검증·생성 실패는 기존 파일과 SQLite 부속 파일을 보존하고 실행을 중단한다. 정상 앱의 시작 오류는 오류 코드와 보존 안내를 운영체제 대화상자로 보여주며, 원문 데이터·SQLite 내부 오류는 로그에 출력하지 않는다. 실행 중 저장 실패의 안내와 재시도는 해당 기능의 처리 범위를 따른다.

최초 저장 중 중단되어 빈 파일이나 불완전한 파일이 남아도 자동 초기화하지 않는다. 사람이 파일·권한·사본을 확인하는 복구가 필요하다. v1 최초 구현에는 이전 형식 변환이 없었고, 이후 v1→v2→v3→v4→v5의 단계별 변환에 원본 사본 보존을 추가했다. 각 변환의 조건은 아래 이력을 따른다. 그 외 형식 변환은 별도 절차와 검사가 필요하다.

변환 전 사본은 자동 복구나 주기 백업을 뜻하지 않는다. 자동 이전 버전 복귀·사본 복원 화면은 없으며 기존 자료를 조용히 덮어쓰지 않는다. 자동 백업 주기·사본 수·암호화 정책은 미정이다. 파일 접근 권한 설정과 로컬 저장 자체는 암호화가 아니다.

## 저장 형식 변경 이력 — 2026-09-26

아래는 각 형식 도입 당시의 저장 구조와 변환 절차다. 예를 들어 v1의 읽기 전용 재실행 설명을 v2 이후 실행 중 쓰기 연결에 적용하지 않는다. 버전별 검사 결과는 다음 절에 별도로 보존한다.

<a id="최초-저장-형식과-실행-순서--v1-당시-기록"></a>

### v1. 같은 알의 최초 저장

- 형식: `application_id = 0x4a505431`, `user_version = 1`. `pet` 표에 `singleton = 1`, UUID v4 `pet_id`, UTC ISO 문자열 `created_at`, `stage = egg` 한 행만 둔다. 알 생성 시각은 부화 시각이 아니다.
- v1 당시 아직 없는 이름·성격·아기 경험·예약·임시 반응·화면 위치는 저장하지 않는다. 실제 아기 경험 수집은 당시 이후 필수 단계로 남아 있었다.
- 앱은 중복 실행 잠금을 먼저 확보하고, 저장 성공 후에만 알 창을 만든다. 추가 실행은 저장 코드에 들어가기 전에 종료한다.
- 새 파일만 배타적으로 생성한다. POSIX 환경에서는 파일 권한 `0600`, 새 데이터 폴더 `0700`을 사용한다. 암호화는 아니다.
- SQLite `DELETE` 저널과 `synchronous = FULL` 설정에서 표·형식 번호·알 한 행을 같은 트랜잭션으로 만든다. 저장 성공 전에 알을 표시하지 않는다.
- 재실행은 읽기 전용으로 열어 `quick_check`, 앱 식별값, 형식 번호, 행 개수와 값 형태를 검사한다. v1 당시에는 이후 상태 변경·저장 작업이 없었으므로 실행 중 DB 연결을 유지하지 않는다.
- 화면에는 검증된 `egg:snapshot` 읽기 요청만 추가한다. 발신 창·최상위 프레임·로컬 페이지 주소·인자 개수를 확인한다. 저장 경로·SQL·쓰기·일반 IPC(프로세스 사이의 통신) 호출은 화면에 노출하지 않는다.

<a id="d-042-후속-알-돌봄경과-시간--v2-작업-브랜치"></a>

### v2. 알 돌봄·경과 시간 — D-042

**추가 내용:** 최초 v1의 식별 표는 그대로 두고 `egg_life`, `egg_care`를 추가한다. [D-042](Jarvis_Pet_Decision_Log.md)에 최소 필드·시간 해석·미구현 범위를 기록했다. 일단 v2로 변환한 저장소는 v1 전용 이전 앱으로 열지 않는다.

**변환·호환성:** `loadOrCreateEgg`는 v1/v2의 식별자를 읽기 전용으로 검증한다. `openEggLife`는 단일 실행 잠금 아래 쓰기 연결을 열고, v1이면 변경 전 `pet.sqlite3.v1-backup`을 배타적으로 복사한다. 기존 사본이 원본 v1과 일치하면 재시도를 허용하며, 다른 파일·심볼릭 링크면 보존하고 중단한다. 표 추가·초기 경과·형식 번호 2를 한 묶음으로 저장한다. 사본은 자동 삭제하지 않으며 프로젝트·GitHub 업로드 대상도 아니다. 실패 시 v1 원본과 사본을 보존한다. 사본을 자동 복원하는 기능은 없다.

**실행 중 저장:** 실행 중에는 작은 동기 쓰기 연결을 유지한다. 돌봄 사건과 해당 경과는 함께 저장하며 커밋(저장 확정) 뒤에만 성공 반응을 보인다. 주기 경과 저장 실패는 오류 코드로 알리고, 돌봄 저장 실패는 화면에서 재시도를 안내한다. 강제 종료 직전 아직 저장하지 않은 경과는 다음 시작 시 벽시계 차이로 반영한다. 저장된 사건은 재시작 뒤 남고 반응 애니메이션은 대기에서 시작한다.

<a id="부화-진행을-위한-v3-확장--2026-09-26"></a>

### v3. 부화 진행 — D-047

**추가 내용·이유:** 부화 구성요소는 기존 `pet.sqlite3`의 펫 식별자와 돌봄 기록을 그대로 유지하고, `pet.stage`가 알·아기를 표현하도록 제약을 넓힌다. 이름과 연출 완료 지점은 같은 파일에 저장한다. 별도 부화 파일을 기준으로 삼으면 같은 펫의 단계가 두 파일에서 달라질 수 있어 채택하지 않았다. `pet` 표의 단계·이름과 `lifecycle` 표의 완료 지점을 한 트랜잭션으로 변경하고 읽을 때 서로 일치하는지 검사한다.

**변환·호환성:** v1 자료는 검증된 v1→v2 변환을 먼저 통과한다. v2→v3 전에 원본을 `pet.sqlite3.v2-backup`으로 배타적으로 복사하고, 다른 내용의 기존 사본이 있으면 덮어쓰지 않고 멈춘다. 표 재구성·연출 초기 상태·형식 번호 3을 한 트랜잭션으로 반영한다. 실패하면 v2 본문과 사본을 보존한다. **v3 파일은 이전 v2 앱에서 열 수 없다.** 자동 이전 버전 복귀나 사본 복원 화면은 아직 없다.

<a id="아기-생활과-경험을-위한-v4-확장--2026-09-26"></a>

### v4. 아기 생활과 경험 — D-048

**추가 내용·이유:** [D-048](Jarvis_Pet_Decision_Log.md)의 최소 아기 생활은 같은 `pet.sqlite3`에 `baby_life` 상태와 `baby_experience` 사건을 추가한다. 상태와 식사·접촉·완료 수면 시간을 한 트랜잭션으로 저장한다. 첫 이름 저장과 생활 시작 시각도 한 트랜잭션에 넣어 이름만 저장된 아기가 생기지 않게 한다. 저장 실패·누락·손상은 새 생활 기록을 임의 생성해 숨기지 않는다. 다만 v3에서 이미 이름을 지은 펫은 과거 명명 시각이 없으므로 v4 변환 시점부터 추적하며, 과거 경험을 만들어내지 않는다.

**변환·호환성:** v3→v4 전에 원본을 `pet.sqlite3.v3-backup`으로 배타적으로 복사하고, 내용이 다른 기존 사본과 심볼릭 링크는 보존한 채 변환을 멈춘다. 표 추가·형식 번호 4 변경을 한 트랜잭션으로 묶는다. **v4 파일은 이전 v3 앱에서 열 수 없다.**

<a id="아기-감정관계를-위한-v5-확장--2026-09-26"></a>

### v5. 아기 감정·관계 — D-049

**추가 내용:** [D-049](Jarvis_Pet_Decision_Log.md)의 감정·관계·놀이 상태는 기존 `pet.sqlite3`에 `baby_social`과 `baby_social_experience`를 추가해 유지한다. 사회 경험은 칭찬·재회·반복 접촉·커서/구슬 놀이의 종류와 시각만 기록하며 대화 원문·커서 좌표는 저장하지 않는다. 생활 상태와 사회 상태, 두 경험 표는 한 트랜잭션으로 갱신한다. 첫 이름을 저장할 때 첫 생활·사회 상태도 같은 묶음에 만든다.

**변환·호환성:** v4 파일을 열 때는 원본을 `pet.sqlite3.v4-backup`으로 배타적으로 남기고 충돌·손상은 자동 초기화하지 않는다. **v5 파일은 이전 v4 앱에서 열 수 없다.**

**표현·미정 사항:** 감정·관계 내부값은 제품 화면으로 보내지 않으며, 반응 수치와 기록 보존 기간은 실제 사용 뒤 조정한다.

## 버전별 검증 근거와 남은 한계

다음은 각 형식 도입 당시의 검사 기록이다. 문서 갱신일을 검사 재실행일로 해석하지 않는다. 임시 자료·숨긴 화면·모의 잠금/절전 검사는 실제 사용자 자료 변환·사용자 조작·물리 절전을 대신하지 않는다. 로컬 Mac 미리보기 앱의 후속 검사도 정식 배포용 설치 앱 검증과 구분한다.

### v1 당시 검증

macOS 26.6.2 / arm64, Electron 44.4.5, 내장 Node.js 24.21.0, SQLite 3.53.4에서 검사했다. 내장 모듈 조회뿐 아니라 실제 Electron 메인 영역에서 저장·복원하고 숨긴 화면이 동일 식별자를 받는 것까지 확인했다.

- `npm run typecheck`, `npm test` 통과. 저장 검사 8개, 실제 앱 시작 검사 5개와 화면·요청 경계 검사를 포함한다.
- 새 저장소, 별도 프로세스 재실행, 단일 알 제약, 중복 앱 실행, 손상·빈 파일·미지원 형식·행 누락·잘못된 값 보존을 검사했다.
- 실제 파일 권한 거부와 경로 충돌, 삽입 실패 주입에 따른 취소, 최초 저장 중 프로세스 강제 종료, 실행 중 강제 종료 후 복원을 확인했다.
- 검사 자료는 임시 데이터이며 사용자의 실제 알과 원본 실행 앱은 조작하지 않았다. 잘못된 요청 거절 시 Electron이 기록하는 예상 오류 로그와 검사 실패는 구분한다.
- 실제 디스크 전체 소진·정전, 정상 화면의 오류 대화상자 사용자 확인, 설치용 `.app`, Windows, 다중 모니터, 장시간 보존은 미검증이다. v1 당시 아기 상태·경험의 동시 저장도 구현·검사하지 않았다. 후속 구현·검사는 아래 v4·v5 기록과 구분한다.

### v2 당시 검증

기존 v1 검사에 더해 원본 사본 동일성, 변환 취소, 기존 사본 충돌 보존, 가짜 시계 복원, 사건 삽입 실패 시 상태 동시 취소, 실제 앱 쓰다듬기·실패 안내·재시작·강제 종료를 검사했다. 실제 디스크 소진·정전·타 프로세스의 비협조적인 DB 수정·장기 저장량·사본 복원 사용자 경험은 미검증이다. 당시 검사 수와 후속 통합·사용자 확인은 [개발 기록의 알 돌봄과 경과 기록](Jarvis_Pet_Development_Log.md#알-돌봄과-경과-기록--d-042--pr-6)을 따른다. 실제 사용자 자료 변환은 포함하지 않았다.

### v3 당시 검증

임시 저장소에서 v1→v2→v3의 동일 `petId`·돌봄 사건 유지, 모든 연출 지점의 별도 프로세스 재시작, 이름·단계 쓰기 실패 시 동시 취소, 백업 충돌·손상 파일 보존을 검사했다. 실제 사용자의 펫 DB는 변환하지 않았다. v3 형식은 아기의 실제 생활·경험 기록을 포함하지 않았으며, 제품의 부화 자동 발동·실기기 잠금·절전도 검증하지 않았다.

### v4 당시 검증

임시 저장소에서 원본·사본 보존, 실패 시 취소, 이름 직후 종료·재시작, 식사 중 종료·복원, 중복 식사 방지와 긴 부재 수면 집계를 검사했다. 실제 사용자 DB 변환·사본 복원 사용자 경험·설치용 앱·장기간 저장량은 미검증이다. 후속 화면·통합 검사 상태는 [개발 기록의 아기 생활·감정·관계·놀이](Jarvis_Pet_Development_Log.md#아기-생활-감정관계놀이-낮밤--pr-131416)를 따른다.

### v5 당시 검증

임시 저장소에서 기존 식별자·식사·수면·구슬 유지, 변환 실패·사본 충돌 보존, 저장 실패 동시 취소, 앱 재시작·잠금/절전 모의 흐름을 검사했다. 실제 사용자 DB 변환·사본 복원 경험·설치용 앱·장기 저장량은 미검증이다.
