# Jarvis Pet Decision Log v0.1

- 기록일: 2026-09-25
- 목적: 제품 요구사항 문서(PRD)에 적힌 방향의 **결정 이유**를 보존한다.
- 상태 기준: **확정**은 현재의 설계 원칙, **가설**은 추가 조사·검증 전의 방향이다. 세부 구현 방식을 정하지 않은 항목은 그 범위를 명시한다.
- 변경 원칙: 결정을 바꿀 때 기존 기록을 불필요하게 지우지 않고, 해당 항목에 변경 취지를 남기거나 새 결정에서 이전 결정 번호를 참조한다. 기술 선택이 확정되면 필요에 따라 별도의 아키텍처 결정 기록(ADR)에 상세 근거를 남긴다.
- 문서 역할: 이 문서는 **무엇을 왜 선택했는지와 결정의 변경 이력**을 기록한다. v0.1의 기능·완료 기준은 `Jarvis_Pet_PRD_v0.1.md`, 펫의 행동·감정·성장 표현은 `Jarvis_Pet_Character_and_Growth_Design_v0.1.md`를 기준으로 한다.
- 기술 설계: 구현 구조와 단계별 검증 계획은 [기술 설계 v0.1](./Jarvis_Pet_Technical_Design_v0.1.md)에 정리한다. 검토용 초안의 추천안을 이 문서의 확정 결정과 혼동하지 않는다.
- 구현 상태: 아래의 **확정**은 결정이라는 뜻이며 앱 구현 완료를 뜻하지 않는다. **2026-09-26 현재 임시 알의 표시·클릭·드래그를 사용자 실기기에서 확인했다.** 도구 설치는 D-037, 첫 앱 검증과 남은 항목은 D-038에 기록한다. v0.1 본 기능이나 기술 검증 단계 전체 완료는 아니다.

## D-001. 프로젝트 정체성은 게임이 아니다

- **날짜:** 2026-09-25
- **상태:** 확정
- **결정:** Jarvis Pet은 육성 게임이 아니라 성장형 데스크톱 펫이자 AI 비서 동반자다. 게임 요소는 향후 선택적으로 검토한다.
- **배경/이유:** 처음부터 경험치·미션을 중심에 놓으면 제품 방향이 게임으로 고정되기 쉽다. 핵심 경험은 펫과 관계를 맺고, 성장에 따라 도움을 받는 데 있다.
- **영향/후속 조치:** 초기 화면과 기능에서 레벨·경험치·퀘스트를 중심 요소로 설계하지 않는다.

## D-002. 큰 비전은 크게, MVP는 작게

- **날짜:** 2026-09-25
- **상태:** 확정
- **결정:** 장기 비전과 개인용 최소 기능 제품(MVP)의 범위를 분리한다. 모든 기능·비전은 `현재 반드시 구현 / 구조만 고려 / 미래 확장`으로 구분하고, 실제 구현 완료 여부는 별도로 표시한다.
- **배경/이유:** 여러 AI 제공자, 작업 수행 기능, 멀티펫을 한 번에 만들면 범위가 커져 첫 버전의 완성을 방해한다. 설계 의도와 구현 사실도 구분해야 한다.
- **영향/후속 조치:** PRD와 포트폴리오에 같은 세 분류를 사용한다. 구현하지 않은 기능을 완성된 기능처럼 쓰지 않는다.

## D-003. 펫은 AI 없이도 동작한다

- **날짜:** 2026-09-25
- **상태:** 확정
- **결정:** Pet Brain은 외부 AI 언어 모델(LLM) 없이도 펫의 정체성·상태·감정·행동·관계·기억·성장·간단한 반응을 유지한다.
- **배경/이유:** 어린 성장 단계에는 AI 기능이 적어도 펫 자체의 존재감이 있어야 한다. 인터넷이나 AI 서비스가 멈췄을 때 펫 전체가 작동하지 않는 상황도 피해야 한다.
- **영향/후속 조치:** 기본 상태 변화와 반응을 AI 호출 없이 처리한다. 어린 단계의 핵심 경험을 별도로 정의한다.

## D-004. Pet Brain과 AI를 분리한다

- **날짜:** 2026-09-25
- **상태:** 확정(구조 원칙)
- **결정:** 펫의 정체성·상태·행동·감정·관계·기억·성장을 다루는 Pet Brain과 선택적으로 쓰는 AIService를 분리한다. Codex는 Pet Brain 전체가 아니라 사용자가 시작하는 로컬 작업을 돕는 Agent/도구 후보다. 구체적인 모듈 경계는 설계 단계에서 정한다.
- **배경/이유:** AI 언어 모델이 펫의 성격과 상태 전체를 결정하면 AI 장애나 제공자 변경에 따라 같은 펫의 연속성이 흔들릴 수 있다.
- **영향/후속 조치:** 기본 상태 변화는 Pet Brain에서 관리하고, 외부 AI는 자연어 생성·복잡한 추론·고난도 작업에만 선택적으로 쓴다. 상세 구조 확정 시 ADR을 작성한다.

## D-005. 특정 AI Provider에 종속되지 않고, One Provider First로 간다

- **날짜:** 2026-09-25
- **상태:** 확정(구조 원칙); 일반 대화용 첫 제공자 미정
- **결정:** AI 제공자를 교체할 수 있는 연결 경계를 고려하되, MVP에서 여러 제공자를 동시에 연동하지 않는다. Codex 작업 경로는 일반 대화용 AIProvider와 별도로 판단한다.
- **배경/이유:** 여러 제공자를 처음부터 모두 연동하면 범위가 커진다. 반대로 한 제공자의 고유 기능을 펫 핵심 코드에 직접 엮으면 이후 교체 비용이 커진다.
- **영향/후속 조치:** 제공자별 연결 방식과 펫 핵심 기능을 분리한다. 첫 일반 대화용 제공자는 아직 선택하지 않는다. Codex의 조건부 작업 경로와 Claude·Gemini 보류 판단은 D-019에 기록한다.

## D-006. Local-first & User-owned Memory

- **날짜:** 2026-09-25
- **상태:** 확정(저장 원칙); SQLite 선택은 D-039, 세부 방식은 ADR-001
- **결정:** 펫의 감정·관계·성장·기억·리마인더 등 핵심 데이터는 기본적으로 사용자 기기에 저장하고, 특정 AI 제공자의 기억 기능에 종속시키지 않는다.
- **배경/이유:** 기억을 사용자가 소유해야 AI 제공자를 바꿔도 펫의 연속성을 유지할 수 있다. 개인정보 보호, 오프라인 동작, 초기 서버 비용 절감에도 맞는다.
- **영향/후속 조치:** 로컬 저장·내보내기·복구 방안을 검토한다. SQLite 선택 시 별도 ADR로 근거와 제약을 기록한다. 이후 D-039의 사용자 선택에 따라 [ADR-001](ADR-001-local-pet-storage.md)에 방식·대안·실패 처리·검증 한계를 기록했다.

## D-007. 무료 원칙을 제품의 핵심 제약조건으로 둔다

- **날짜:** 2026-09-25
- **상태:** 확정
- **결정:** '무료'는 추가 AI API 과금을 기본값으로 요구하지 않는다는 뜻이다. 기존 유료 구독 자체가 무료라는 뜻은 아니며, 모든 기존 구독을 제3자 앱에서 재사용할 수 있다는 뜻도 아니다. 이는 Jarvis Pet의 핵심 제약조건이다. 초기에는 중앙 서버·저장소 운영이나 Jarvis Pet이 사용자별 AI API 비용을 대신 부담하는 구조를 제외한다.
- **배경/이유:** 현 단계의 목표는 개인용 완성품과 실제 사용 검증이다(D-017). 기존 구독을 추가 API 요금 없이 쓰는 경로는 제공자별로 다르므로 D-019의 조사 결과를 따른다. 기존의 '초기 운영비 최소화' 결정은 이 원칙의 일부로 유지한다.
- **영향/후속 조치:** 서버가 꼭 필요한 기능만 별도 비용 근거를 세워 검토하고, 로컬에서 처리 가능한 기능을 우선한다. AI 연결 방식을 결정할 때 추가 API 과금 여부와 운영자의 사용자별 비용 부담을 필수 조건으로 확인한다(D-008).

## D-008. 기존 AI 계정의 공식 연결을 기본 전략으로 삼는다

- **날짜:** 2026-09-25
- **상태:** 연결 검토 원칙 확정; 제공자별 실제 연동 방식은 D-019에 따름
- **결정:** 기존 AI 계정과 공식 로컬 클라이언트·명령줄 도구(CLI)를 통한 연결은 해당 용도가 공식적으로 허용될 때에만 우선 검토한다. 다음으로 무료 공식 계정 범위와 로컬 모델을 보조 경로로 검토한다. API 키는 기본값이 아니며, 추가 과금 가능성을 안내받은 사용자가 원할 때만 선택하는 대체 연결 수단으로 둔다. Jarvis Pet이 사용자별 AI API 비용을 대신 부담하는 구조는 피한다.
- **배경/이유:** D-007의 무료 원칙을 지키면서 공식 허용 범위 밖의 구독 재사용을 피해야 한다. ChatGPT·Claude·Gemini의 개인용 유료 구독이 제3자 앱의 API 사용권을 뜻한다고 가정하지 않는다. 현재 제공자별 결론은 D-019에 기록한다.
- **영향/후속 조치:** 제공자별로 공식 로그인·로컬 도구 연동 가능 여부, 이용 조건, 구독 범위 및 추가 과금 여부를 확인한 뒤 지원 방식을 정한다. 공식 인증 토큰을 추출하거나 내부 API를 우회하는 등 비공식적이거나 이용 조건을 위반할 수 있는 방식은 사용하지 않는다. 사용자가 API 키를 선택하는 경우에만 예상 과금과 안전한 보관 방식을 안내·설계한다.

## D-009. 단일 펫으로 구현하되 `petId`로 멀티펫 확장을 고려한다

- **날짜:** 2026-09-25
- **상태:** 확정
- **결정:** MVP에서는 펫 한 마리만 구현한다. 데이터 식별에는 `petId`를 고려해 나중에 여러 펫을 구분할 여지를 둔다.
- **배경/이유:** 현재 멀티펫 기능은 필요하지 않지만, 펫별 데이터의 식별 방법을 나중에 추가하면 저장 구조를 크게 바꿔야 할 수 있다.
- **영향/후속 조치:** 데이터 모델 설계 시 펫 식별자를 검토하되, 멀티펫 화면·관리 기능은 MVP 범위에 넣지 않는다.

## D-010. 성장은 외형뿐 아니라 관계·사용자 이해·비서 능력의 성숙을 뜻한다

- **날짜:** 2026-09-25
- **상태:** 방향 확정; 단계는 D-022에서, 성장 방식은 D-026에서 후속 결정, 수치 조건은 미정
- **결정:** 성장을 단순한 외형 변화로 정의하지 않는다. 펫과 사용자의 관계, 사용자에 대한 이해, 수행할 수 있는 비서 업무도 함께 성숙하는 경험을 지향한다.
- **배경/이유:** 어린 펫의 기본 행동에서 시작해 대화·기억·상황 이해·업무 수행으로 이어져야 성장이 제품 경험으로 느껴진다. 단순한 기능 잠금 해제만으로는 이 의도가 전달되기 어렵다.
- **영향/후속 조치:** 단계별 이해·제안·수행 능력과 구체적 성장 조건은 사용자 경험과 구현 가능성을 확인하며 후속 설계에서 정한다. 실제 실행 권한은 성장 단계와 별개로 사용자가 허용한 범위에서만 주어진다(D-032).

## D-011. 이미 존재하는 기능 자체를 차별점으로 주장하지 않는다

- **날짜:** 2026-09-25
- **상태:** 확정(표현 원칙)
- **결정:** 움직이는 펫, 감정, 기억, 여러 AI 연동, 로컬 저장, 알람, 성장 같은 기능 하나만으로 독창성을 주장하지 않는다.
- **배경/이유:** 앞선 대화에서 NekoAI, Miru, Pet Mochi, desktop-pet 등 유사 사례를 비교 대상으로 확인했다. 개별 기능의 존재만으로 차별화가 검증되지는 않는다.
- **영향/후속 조치:** 경쟁 분석에서 각 제품의 실제 제공 범위를 확인하고, 차별성은 기능의 조합·성장 과정·사용자 경험을 근거로 평가한다.

## D-012. 현재 차별화는 가설 상태로 유지한다

- **날짜:** 2026-09-25
- **상태:** 가설
- **결정:** ‘펫이 사용자와 함께 성장하면서 이해·제안·수행 능력을 넓히고, 장기적으로 여러 AI와 도구를 조율하는 개인 비서가 된다’는 방향을 차별화 가설로 둔다. 실제 실행 권한은 성장 단계와 별개로 사용자가 허용한 범위에서만 주어진다.
- **배경/이유:** 이 조합이 의미 있는 경험인지, 경쟁 제품과 실질적으로 어떻게 다른지는 아직 충분히 검증되지 않았다.
- **영향/후속 조치:** 경쟁 분석과 최소 기능 제품 검증 전에는 확정된 차별점으로 표현하지 않는다. 검증 결과에 따라 가설을 수정하거나 폐기하고 새 결정을 기록한다.

## D-013. 태어난 펫의 정체성은 교체하지 않는다

- **날짜:** 2026-09-25
- **상태:** 확정(제품 원칙); 구체적인 외형·구현 방식 미정
- **결정:** 한 번 태어난 펫은 성장 과정에서 다른 캐릭터로 교체하지 않는다. AI 제공자나 외형이 변해도 같은 개체로 이어진다.
- **배경/이유:** 사용자가 펫에게 쌓은 기억과 애착은 특정 외형이나 AI 제공자보다 오래 지속되어야 한다. NekoAI를 AI 연결 없이 써본 경험에서도 캐릭터 교체 구조가 애착을 약하게 느끼게 했다.
- **영향/후속 조치:** 캐릭터 교체를 기본 경험으로 설계하지 않는다. 액세서리·꾸미기는 펫의 정체성을 바꾸지 않는 범위에서만 검토한다.

## D-014. 관계의 지속성을 외형 선택권보다 우선한다

- **날짜:** 2026-09-25
- **상태:** 확정(사용자 경험 원칙)
- **결정:** 외형이 취향에 완전히 맞지 않더라도 “못생기고 못나도 내가 키운 내 펫”이라는 관계와 애착을 우선한다.
- **배경/이유:** 원하는 외형을 계속 고르고 바꿀 수 있는 선택권보다, 태어난 개체와 함께 살아온 시간이 펫 경험의 중심이어야 한다.
- **영향/후속 조치:** 외형 선택·꾸미기 기능을 검토할 때 관계의 연속성을 해치지 않는지 확인한다. 구체적인 외형과 꾸미기 범위는 별도로 정한다.

## D-015. 성장에서 예측하지 못한 개체 고유성을 허용한다

- **날짜:** 2026-09-25
- **상태:** 확정(방향); 표현 방식 미정
- **결정:** 성장 과정에서 미리 정해진 외형·행동만 반복하기보다, 함께 지낸 결과로 예상하지 못한 개체 고유성이 드러나는 것을 허용한다.
- **배경/이유:** 모든 펫이 같은 결과로 수렴하면 사용자가 키운 한 개체라는 감각이 약해질 수 있다. 관계와 경험이 쌓이는 과정이 성장에 반영되어야 한다.
- **영향/후속 조치:** 성격·행동·말투 등에서 개체성을 표현할 수 있는 방안을 검토하되, 성장 조건과 구현 방식은 검증 후 결정한다.

## D-016. 성장의 최종 목표는 애착과 높은 업무 수행 능력의 결합이다

- **날짜:** 2026-09-25
- **상태:** 확정(장기 목표); 구체적인 능력과 사용자 허용 범위의 설계 미정
- **결정:** 펫은 관계와 개체성을 유지하면서 사용자 이해, 비서 능력, 업무 수행 주도성(Agency)이 성장해 믿고 일을 맡길 수 있는 개인 비서·에이전트가 된다. 최종상은 “일 완전 알잘딱깔쎈 내 펫”이다.
- **배경/이유:** 외형 변화나 친밀감만으로는 Jarvis Pet의 개인 비서 비전을 달성할 수 없다. 반대로 업무 능력만 높아져도 함께 키운 펫이라는 의미가 약해진다.
- **영향/후속 조치:** 성장 단계별로 관계 경험과 이해·제안·수행 능력을 함께 설계한다. 실제 작업 실행 권한은 성장과 별개로 사용자 허용 범위에 따라 정한다(D-032).

## D-017. 개인용 완성품을 먼저 만든다

## D-018. 기본 자동화와 사용자 오버라이드를 함께 제공한다

- **날짜:** 2026-09-25

- **결정:** 기본 사용은 자동화하고 기술 설정을 단순하게 한다. 사용자가 체감하는 선택권은 펫의 외형·탄생·키우는 방식·관계에 집중하되, 명시적 요청과 고급 설정으로 AI 제공자·모델·사용 시점·허용·금지 조건을 제어할 수 있게 한다. 우선순위는 **사용자 명시 제약 > 고급 설정 > 작업별 선호 > 자동 Router 판단**이다.
- **배경/이유:** 자동 선택은 편리하지만 사용자의 명시적 금지나 선택을 덮어쓰면 신뢰를 해친다. 반대로 모든 기술 결정을 먼저 요구하면 펫과 관계를 맺는 경험이 약해진다.
- **영향/후속 조치:** 자동 Router는 미래 확장으로 두고, 도입 시에도 이 우선순위를 지킨다. 고급 설정의 구체적 범위와 화면은 별도로 설계한다.

## D-019. 기존 구독 재사용은 Codex 작업 경로만 조건부 후속 후보로 둔다

- **배경/이유:** `research/`의 OpenAI·Claude·Gemini 구독 재사용 타당성 조사에서 구독과 일반 API 과금은 구분되며, 제공자별 공식 허용 범위가 다름을 확인했다. D-005·D-007·D-008의 넓은 연결 원칙을 현재 조사 결과에 맞춰 좁힌다.

## D-023. 돌봄의 부재가 죽음이나 성장 실패로 이어지지 않는다

- **배경/이유:** 관계를 점수로 관리하면 살아 있는 개체와 함께 지내는 감각보다 최적화 게임에 가까워진다. 사용자는 강아지나 고양이의 마음을 알아가듯 펫의 반응을 관찰한다.
- **영향/후속 조치:** 내부 계산값이 필요할 수 있지만 사용자에게 직접 노출하지 않는다. 구체적 표현은 캐릭터 설계에서 정한다.

## D-025. 선천 기질과 후천 경험을 함께 쓰되 성격은 키우며 발견한다

## D-026. 성장은 시간과 경험을 결합한다

## D-028. 감정·몸 상태·관계를 구분한다

## D-029. 감정구슬은 수치판이 아닌 펫의 소지품이다

## D-037. 첫 검증용 Electron·TypeScript는 프로젝트별로 설치하고 버전을 고정한다

- **날짜:** 2026-09-26
- **상태:** 설치 요청 범위의 기술 선택·개발 도구 설치 및 버전 실행 확인 완료; 앱 기능 구현·실기기 검증 아님
- **결정:** 기존 Node.js 24.21.0·npm 11.19.0을 사용해 Electron **44.4.5**와 TypeScript **7.0.2**를 원본 프로젝트의 개발용 패키지로 설치했다. `package.json`에 정확한 버전을 지정하고 연관 패키지 버전은 `package-lock.json`에 보존한다. 두 도구를 전역 설치하거나 다른 프로젝트·시스템 설정을 변경하지 않는다.
- **배경/이유:** 다른 프로젝트에서도 사용하더라도 필요한 버전과 갱신 시점은 다를 수 있다. 전역의 한 버전을 공유하는 것보다 프로젝트별로 버전을 기록하면 업데이트 충돌을 줄이고 같은 개발 환경을 복원하기 쉽다. 공개 npm registry의 안정판과 Node.js 요구 조건을 조회했으며 현재 Node.js는 Electron의 `>=22.12.0`, TypeScript의 `>=16.20.0` 조건을 충족한다.
- **검증:** macOS 26.6.2 / arm64에서 `npm ls --depth=0`으로 직접 의존성 두 개를 확인하고 `./node_modules/.bin/tsc --version`은 `Version 7.0.2`, `./node_modules/.bin/electron --version`은 `v44.4.5`를 반환했다. Electron 바이너리 다운로드 완료와 `node_modules/`의 Git 제외도 확인했다. 설치 시 npm 취약점 조회 결과는 0개다.
- **영향/후속 조치:** `package.json`은 도구 명세, `package-lock.json`은 동일 의존성 구성을 재설치하기 위한 기록으로 관리한다. 앱 실행·테스트 명령과 앱 코드는 아직 없다. 창·클릭·이동·입력 방해 여부, Windows, 앱 코드의 TypeScript 호환성은 미검증이다. D-035의 Electron 최종 채택 판단과 React·SQLite 등 미정 상태는 유지한다. 설치 준비와 문서 갱신은 원본에 저장했으며 이번 작업에서 커밋·GitHub 전송은 하지 않는다.

위는 설치 단계 종료 시점의 상태다. 이어진 앱 구현은 아래 D-038에서 구분한다.

## D-038. 첫 구현은 추가 화면 도구 없이 임시 알 창으로 검증한다

- **날짜:** 2026-09-26
- **상태:** 사용자 구현 승인 / 임시 알 표시·클릭·드래그 사용자 확인 / 자동 검사 통과 / 단계 1 일부 검증

## D-040. Pet Brain의 첫 조각은 대기·클릭 반응만 담당한다

- **날짜:** 2026-09-26
- **상태:** 사용자 구현 승인 / 브랜치 구현·자동 검사 완료 / GitHub 검토 대상 / 머지 금지
- **결정:** 사용자에게 제시한 ‘쉬기 → 클릭 반응 → 다시 쉬기’를 새 `codex/egg-brain` 브랜치와 실제 워크트리에서 구현한다. 알의 반응 규칙은 `src/pet/brain.ts`, 상태 계약은 `src/shared/pet-state.ts`에 둔다. Electron·화면·저장·AI는 Brain 안에 직접 연결하지 않는다.
- **배경/이유:** 기존에는 화면이 클릭 직후 흔들림을 직접 시작했다. 앞으로 펫 상태에 따라 반응을 결정할 수 있도록 작은 규칙을 먼저 독립시키고, 화면은 결과만 표현하게 한다. 새 라이브러리나 복잡한 상태 관리 도구 없이 TypeScript 클래스와 허용된 상태 조회·전달 통로로 충분하다. D-004의 전체 Pet Brain 구조를 최종 확정한 것은 아니므로 새 ADR을 늘리지 않고 이번 작은 결정은 이 로그에 남긴다. 전체 구조 확정 시의 ADR 검토는 유지한다.
- **동작:** 480ms 반응은 기존 임시 애니메이션 길이에 맞춘 구현값이다. 반응 중 추가 클릭은 누적·연장하지 않는다. 화면 재로딩 시 메인 영역의 현재 상태를 받고, 늦게 도착한 이전 상태는 무시한다. 종료 때 타이머를 취소한다. 임시 반응은 감정·관계·성장 수치나 저장해야 할 장기 경험이 아니다. 고유 식별자와 SQLite 저장은 별도 작업이며 아직 통합하지 않았다.
- **검증:** `npm test`에서 시간 제어를 이용한 규칙 검사 4개와 실제 Electron 연결 검사를 통과했다. 대기·반응·복귀, 반복 클릭, 원본 상태 보호, 종료 취소, 화면 상태 반영, 페이지 재로딩, 이전 상태 무시, 취소·중복 종료, 다른 창 조회 거절, 투명 픽셀을 확인했다. 다른 창 조회 거절의 예상 오류는 검사 성공과 구분해 설명한다. 종료/재생성 검사에서 Electron의 기본 종료가 오류를 가릴 수 있어 테스트 종료 제어를 보완했다.
- **한계:** 새 브랜치의 실제 macOS 마우스 동작·장시간·SQLite 통합은 미검증. 쓰다듬기·굴러가기·부화·아기·알림·LLM은 미구현이며 단계 4 전체 완료가 아니다. 이전 버전의 사용자 확인을 이번 브랜치 검증으로 확대하지 않는다. 위치 복원 약 1.3초 지연은 별도 후속 개선이다.
- **기록·보존:** 사용자는 이력용 새 브랜치에서 자율 진행하되 머지는 하지 말라고 지시했다. 따라서 GitHub 브랜치·검토용 PR까지 남기고 원본 main에 기능을 통합하거나 워크트리를 삭제하지 않는다. 원본의 기존 미커밋 문서는 보존한다. 저장 작업과 창·preload·문서가 겹치므로 후속 통합 시 두 PR의 충돌과 연결을 검사해야 한다.


## D-041. 저장과 반응은 같은 앱 흐름에서 함께 검증한다

- **날짜:** 2026-09-26
- **상태:** 사용자 통합 검사 요청 / 통합 브랜치 검사 통과 / GitHub 병합·원본 앱 반영 보류
- **결정·이유:** D-039 저장과 D-040 반응을 따로 검사한 결과만으로 함께 동작한다고 답할 수 없다. 사용자 지적에 따라 `codex/egg-integration`에서 두 변경을 조합하고 끝까지 이어지는 앱 흐름을 검사했다. 새 제품 기능이나 라이브러리를 추가한 것이 아니라 승인된 두 기능의 연결과 검사 누락을 보완했다.
- **변경:** `createPetWindow`에 저장된 알 정보를 넘기고 동일 창의 Brain을 연결한다. 영구 식별자와 임시 반응 조회는 각각 제한된 통로로 제공한다. 두 검사 묶음을 하나의 실행 명령으로 실행하며 창 재생성에도 저장된 알 정보를 전달한다. 클릭·반응 기록은 영구 저장하지 않는다.
- **검증:** macOS 26.6.2 / arm64, Electron 44.4.5에서 규칙4·저장8·앱시작 및 통합7과 화면 연결·타입 검사를 통과했다. 실제 페이지 클릭 입력 → 반응 → 페이지 재로딩 → 대기 → 앱 종료 → 같은 알 복원 → 재클릭과, 반응 중 강제 종료 → 같은 알의 대기 복원 → 재클릭을 검사했다. 반응 전후 SQLite 파일 내용도 동일했다. 통합 후에도 중복 실행·손상·쓰기 실패와 요청 차단 검사를 통과했다.
- **한계·보존:** 숨긴 Electron 창에 클릭을 전달한 자동 검사다. 바탕화면의 운영체제 마우스 경험·설치용 앱·Windows·장시간은 미검증이다. 원본 앱·기존 두 PR은 유지하며 main에 병합하지 않는다. D-039·D-040의 ‘미통합’ 표기는 각 개별 작업 종료 시점이고 이 항목이 후속 통합 결과다.


**일반 실행 시작 경로 수정 — 2026-09-26:** 사용자 수동 확인을 위해 `npm start`로 실행했을 때 `require.main === module` 조건 때문에 초기화가 호출되지 않는 문제를 확인했다. 이전 검사 도우미가 초기화 함수를 직접 불러 시작 파일의 누락을 놓쳤다. `src/main/index.ts`는 초기화를 항상 호출하고 실제 초기화 함수는 `src/main/app.ts`로 분리했다. 검사도 실제 시작 파일을 불러오도록 바꾸고 화면 표시·검사 콜백만 대체한다. 수정 후 타입 검사·19개 검사·화면 연결 검사가 통과했고, 일반 실행 명령의 정상 시작 메시지와 앱 전용 알 저장 파일을 확인했다. 사용자 직접 클릭·종료·재실행의 후속 확인은 아래에 구분한다.


**사용자 직접 확인 — 2026-09-26:** 일반 실행한 통합본에서 사용자가 알 클릭 후 흔들림·대기 복귀를 확인하고 메뉴로 종료했다. Codex가 다시 일반 실행한 뒤 저장된 식별자·생성 시각·단계의 종료 전후 비교값이 일치하고 알이 1개임을 읽기 전용으로 확인했다. 이어 사용자가 복원된 알도 클릭하면 흔들렸다가 멈춘다고 확인했다. 이로써 이 macOS 환경의 클릭 반응 → 메뉴 종료 → 같은 알 복원 → 재클릭 반응 흐름을 사용자 확인과 저장 자료 대조로 검증했다. 식별번호 원문이나 실제 펫 데이터는 문서·GitHub에 기록하지 않았다. 드래그·입력 유지·클릭 통과의 이번 통합본 재확인, 설치용 앱·Windows·장기간 보존은 이 확인에 포함하지 않는다. 실행 중인 앱은 통합 워크트리 버전이며 원본 코드 반영·main 병합은 아직 하지 않았다.


**후속 병합 승인 — 2026-09-26:** 사용자 직접 재실행 검증 후 사용자가 기존 PR #2·#3 종료, [통합 PR #4](https://github.com/SoulJ-K/My-Jarvis/pull/4) 생성·병합과 원본 main 동기화를 승인했다. 위의 병합 보류는 각 기록 시점의 상태이며 이 후속 승인으로 변경됐다. 기존 브랜치·기억 자료·실행 중인 앱은 보존한다. 원본의 기존 문서 추가 내용은 통합본과 대조해 위치 복원 지연·D-039 등이 포함됐음을 확인했고, 이전 다음 단계 안내는 최신 검증 내용으로 갱신한다. 실제 완료 여부는 PR·Git 결과로 확인한다.


## D-042. 알의 쓰다듬기와 이동을 나누고 최소 돌봄 사건을 보존한다

- **날짜·상태:** 2026-09-26. 담당 2 `codex/egg-care-life`의 구현·자동 검사 결과. 사용자 승인 범위의 개별 draft PR(검토용 변경 요청)까지이며, main·원본·기존 실행 앱·실제 펫 자료에는 반영하지 않았다.
- **조작 결정·이유:** 짧은 클릭은 기존 흔들림, 누른 직후 6 DIP 이상 움직이면 위치 이동, 350ms 동안 이동을 시작하지 않고 누른 뒤 좌우로 문지르면 쓰다듬기다. DIP은 화면 배율과 무관한 논리적 거리 단위다. 이동을 먼저 시작하면 손을 놓기 전까지 이동으로 고정한다. 쓰다듬기는 좌우 이동 합계 24 DIP 이상과 6 DIP 이상의 방향 전환을 요구하고 시작점에서 72 DIP를 넘게 벗어나면 무효다. 숫자는 **잠정 구현값**이며 실제 손맛은 통합 후 사용자 확인이 필요하다. 키보드 보조키만으로 쓰다듬기를 구분하는 안은 일반 마우스만으로 돌봄이 가능해야 한다는 조율에 따라 채택하지 않았다. 정확한 왕복 횟수·돌봄 목표·게이지는 요구하거나 표시하지 않는다.
- **표현·취소:** 눌러 준비되면 알이 조금 밝아지고 커서가 바뀐다. 툴팁·접근성 이름에 조작을 설명한다. 쓰다듬기는 480ms의 부드러운 크기·밝기 반응 후 대기로 돌아온다. 움직임 감소 설정에서는 크기 변화 대신 밝기만 사용한다. 반응 중 추가 돌봄은 누적하지 않는다. 취소·포인터 포획 해제·화면 재로딩·큰 이탈·이동은 돌봄 사건을 만들지 않는다. 굴러가는 최종 애니메이션은 아직 없다.
- **최소 저장:** 같은 SQLite 파일의 `egg_life`에 누적 경과 시간·마지막 관측 시각을, `egg_care`에는 자동 순번·종류(`touch`/`stroke`)·발생 시각·당시 경과 시간만 저장한다. 단일 펫 DB이므로 별도 사용자·기기·마우스 경로·대화 내용은 수집하지 않는다. 인식되고 반응 가능한 실제 돌봄 하나당 사건 하나만 남긴다. 사건과 경과 시간은 한 트랜잭션, 즉 전부 저장하거나 전부 취소하는 묶음으로 쓴 뒤 반응한다. 실패하면 반응 성공을 표시하지 않고 재시도 안내를 보인다. 보존 기한은 이번에 임의 설정하지 않으며 삭제·집계·성격 공식은 후속 검토다.
- **시간 결정·이유:** 실제 날짜 시각의 양의 차이를 누적해 앱 종료·장기 부재도 포함한다. 마지막 관측보다 과거 시각이면 증가시키지 않고 이전 최대 관측 시각을 유지하여 역행 후 같은 시간을 두 번 세지 않는다. 시스템 시각의 큰 순방향 변경과 실제 부재는 구분할 수 없다. 잘못 앞선 시각을 기록한 뒤 되돌리면 그 시각을 따라잡을 때까지 누적이 멈추는 한계가 있다. 지금은 기록만 하며 죽음·실패·돌봄 의무·부화 조건에 연결하지 않는다. 타이머 기능의 시간 정책도 이 결정에 포함되지 않는다.
- **구조·변환:** 생활 규칙은 `src/pet/egg-life.ts`의 순수 함수, 반응은 `src/pet/brain.ts`에 둔다. 두 파일은 AI·LLM·SQLite·Electron을 알지 않는다. 앱이 시계와 저장을 연결한다. 시작·60초마다·정상 종료·돌봄 시 경과를 저장하고 재시작 때 차이를 반영한다. 형식 v1→v2 전 기존 검증된 파일을 `.v1-backup` 사본으로 남기며, 표 추가와 형식 변경은 함께 처리한다. 다른 사본이 있으면 덮어쓰지 않고 중단한다. D-039/ADR-001의 SQLite 선택을 유지하는 작은 확장이므로 새 ADR은 만들지 않고 [기존 ADR](ADR-001-local-pet-storage.md)을 갱신한다.
- **검증:** macOS 26.6.2 arm64 / Electron 44.4.5에서 타입·빌드 검사, 규칙·생활·저장 검사 20개와 실제 앱 검사 8개, 화면 연결 검사를 실행했다. 가짜 시계로 장기 부재·시각 역행·재복원, 제스처 경계, v1 사본·변환 실패 복구, 돌봄·상태 동시 취소를 검사했다. 별도 실제 Electron 앱에서 페이지 마우스 입력→쓰다듬기→저장→종료→동일 알·사건 복원, 이동·취소·큰 이탈·화면 재로딩·중복 종료의 미기록, 저장 실패 안내→재시도, 반응 중 강제 종료 후 사건 보존을 확인했다. 화면 캡처에서 알 반응과 오류 안내 표시를 확인했다. 검사용 좌표만 주입했고 사용자 OS 커서·실제 DB는 건드리지 않았다.
- **한계·범위:** 사용자 직접 마우스 조작감, 실제 절전·시각 변경, 운영체제 움직임 감소 설정, 설치용 앱·Windows·장기간 저장량은 미검증이다. 전체 키보드 접근성은 기존 비활성 펫 창의 후속 과제이며 이번에 완성했다고 주장하지 않는다. 부화 준비·부화·아기 생활·성격 계산·입력창·타이머·AI는 구현하지 않았다. 원본 반영과 병합은 메인 작업의 후속 책임이다.

## D-043. 입력과 5분 타이머를 펫 행동과 분리하고 지난 예약을 복원한다

- **날짜:** 2026-09-26
- **상태:** 담당 3의 승인된 작은 구현 / 별도 브랜치 검증 / 개별 초안 PR 검토 대상. 원본 main 반영·전체 v0.1 완료가 아니다.
- **승인 범위:** 사용자는 세 작업을 별도 워크트리·대화·브랜치에서 병렬 진행하고, 각 결과를 개별 PR로 기록한 뒤 통합 담당이 검증·순차 병합하도록 했다. 이번 담당은 입력 열기·입력·닫기/취소와 “5분 타이머”의 저장·알림·취소·복원이다. 종료 중 정시 전달은 보장하지 않는다는 이번 요청을 적용한다. PRD의 알람·리마인더 전체나 아기 대화는 구현하지 않는다.
- **결정·이유:** 메뉴 막대 `알 → 입력 / 타이머`에서 명시적으로 여는 별도 입력창을 둔다. 알 클릭과 드래그는 다른 담당이 검증 중이므로 기존 알 창·Brain을 바꾸지 않는다. 타이머 완료는 초점을 받지 않는 앱 안내와 미확인 목록으로 표현한다. 알의 발화나 감정으로 업무 결과를 대신하지 않는다.
- **저장:** 기존 `node:sqlite`로 앱 전용 `assistant/timers.sqlite3`를 사용한다. 펫 DB와 별도 파일로 두어 이번 예약 구조와 저장 실패가 펫의 식별·돌봄 구조를 변경하지 않게 했다. DB 파일 분리는 동시 개발 편의를 넘어 서로 다른 실패 영역을 보존하기 위한 선택이며, 통합 시에도 원본 펫 DB 마이그레이션이 필요 없다. 새 의존성은 없다. 입력 원문은 저장하지 않고 요청 식별자, 5분 길이, 시작·예정 시각, 상태와 전달 상태만 저장한다.
- **등록·취소:** 저장 성공 후에만 등록됨을 표시한다. 동시에 진행하는 타이머는 하나이며 같은 요청 식별자의 재전송은 중복 등록하지 않는다. 모호하거나 다른 요청은 실행하지 않고 지원 표현을 안내한다. 입력 취소·닫기는 미전송 초안을 버린다. 이미 저장한 타이머 취소는 목록의 별도 버튼이며 취소도 저장한다. 기한이 이미 지났다면 완료가 취소보다 우선한다.
- **시간 정책:** 실행 중에는 역행하지 않는 경과 시간 기준을 사용한다. 절전/복귀 이벤트가 있으면 두 이벤트 사이 경과 시간을 한 번만 포함한다. 이벤트 누락 또는 앱 재시작은 저장된 날짜·시각으로 판단한다. 따라서 재시작 사이 또는 절전 중 시스템 시각 변경의 정확한 실제 경과 시간은 보장하지 않는다. 시간대만 바뀌어도 저장된 절대 시각은 유지한다. 500ms 재확인 주기는 운영체제 정시 실행 보장이 아니다.
- **지난 예약·전달:** 종료 중/재시작 전에 지난 예약은 `recovered`(재시작 후 복원)인 미확인 항목으로 남기며 시스템 알림을 다시 보내지 않는다. 실행 중 늦게 확인한 경우에도 지연을 표시한다. 시스템 알림 요청·표시 신호·실패·미지원·결과 미확인을 별도 저장한다. 표시 신호는 사용자가 읽었다는 뜻이 아니다. 요청 후 결과 기록 전에 종료된 항목은 재시작 시 결과 미확인으로 복구하며 재전송하지 않는다. 앱 표시 기록과 사용자 확인도 별개다. 미확인 항목은 사용자가 확인할 때까지 남는다. DB와 운영체제 표시를 원자적으로 묶거나 정확히 한 번 표시됐다고 보장하지 않는다.
- **검증:** macOS 26.6.2 arm64, Electron 44.4.5에서 가짜 시계·SQLite·실제 Electron 입력 연결·재시작을 검사했다. 최종 세부 결과는 README의 담당 3 검증 기록을 따른다. 숨긴 Electron 창의 `document.hidden`만으로 표시를 판단할 수 없는 문제를 찾아 메인 영역의 실제 창 표시 여부도 확인하도록 수정했다.
- **중요 한계:** 실제 시스템 알림은 `failed`와 `UNErrorDomain 오류 1`을 반환했다. 설치된 개발용 Electron.app의 읽기 전용 서명 검증도 실패했다. Electron 공식 문서는 macOS 알림에 유효한 코드 서명이 필요하다고 설명한다. 서명·알림 허용 상태가 원인 후보이며 둘 사이 인과관계는 확정하지 않았다. 권한·서명 설정을 변경하지 않았다. 서명된 설치용 앱·시스템 표시 성공·실제 OS 한글 입력기·다른 앱으로의 입력 복귀·실제 절전/잠금·Windows는 별도 확인이 필요하다. [Electron 알림 조건](https://www.electronjs.org/docs/latest/tutorial/notifications#macos), [Apple 알림 허용 오류](https://developer.apple.com/documentation/usernotifications/unerror/code/notificationsnotallowed).
- **통합 주의:** `src/main/app.ts`, `scripts/test.mjs`, `scripts/copy-assets.mjs`, README와 본 결정·기술 설계는 다른 담당과 겹칠 수 있다. 담당 1의 창 수정·담당 2의 Brain 수정은 이번 브랜치에서 하지 않았다. 원본 저장은 메인 대화의 순차 PR 병합·통합 검사로 마무리한다.

## D-046. 일회성 알람·리마인더는 확인 후 별도 저장한다

- **날짜·상태:** 2026-09-26. [PR #10](https://github.com/SoulJ-K/My-Jarvis/pull/10)의 로컬 입력·저장·복원 구현과 자동 검사 통과. 실제 macOS 시스템 알림은 미검증.

**후속 결정 — 2026-09-26:** 사용자는 v0.1에서 앱이 완전히 종료된 동안 알람·리마인더 시간이 지났다면, 재실행 시 앱 안의 지난 미확인 항목으로 보여주기로 했다. 종료 중 정시 운영체제 알림은 약속하지 않는다. 실제 macOS 배너 표시·물리 절전 중 전달은 이 결정으로 검증된 것이 아니다. 별도 임시 펫의 리마인더를 등록하고 앱을 종료한 뒤, 예정 시각 이후 재실행하여 ‘재시작 후 복원’ 표시와 확인 처리까지 사용자 화면에서 확인했다. 같은 경로의 알람 종류는 자동 검사만 통과했으며 실기기 직접 조작은 아직 하지 않았다.

## D-047. 부화 진행 지점은 기존 펫 파일에 같은 개체로 저장한다

- **날짜·상태:** 2026-09-26. [PR #9](https://github.com/SoulJ-K/My-Jarvis/pull/9)의 순서·저장·재시작 구성요소 구현·자동 검사 통과. 실제 제품 화면 연결과 자동 부화는 미구현.
- **선택·이유:** 알의 `petId`를 아기까지 유지하고 전조·금·감정구슬·껍질·아기·첫 교감·이름의 완료 지점을 기록한다. 기존 `pet.sqlite3`를 v2→v3로 확장해 단계·이름·진행 지점을 함께 저장한다. 별도 부화 DB가 기준이 되면 서로 다른 성장 단계가 남을 수 있어 피했다. 기존 v2 원본 사본을 보존하고 충돌·저장 실패·중간 종료를 검사한다. 구체적인 저장 형식과 이전 버전 호환성은 [ADR-001](ADR-001-local-pet-storage.md)에 기록한다.
- **미정·한계:** 부화 준비 시간, 돌봄이 시점을 얼마나 바꾸는지, 사용자가 실제 연출을 볼 수 있는 시작 조건, 이름 길이 정책은 확정하지 않았다. 기본 제품의 자동 부화 발동은 꺼 두고 검사에서만 명시적으로 진행한다. v3 파일은 이전 v2 앱에서 열 수 없으며 사용자 실제 DB 변환·실기기 잠금·절전·아기 생활은 미검증이다.

**후속 연결 — 2026-09-26 / [PR #12](https://github.com/SoulJ-K/My-Jarvis/pull/12):** 저장된 부화 준비 상태가 있으면 실제 앱에서 전조→금→구슬→껍질→아기→첫 교감→이름 화면을 순서대로 보여주고, 장면 확인·이름 저장이 성공한 뒤에만 진행 지점을 바꾼다. 이름을 저장하면 같은 `petId`의 아기 대기 화면으로 돌아간다. 사용자는 첫 이름의 앞뒤 공백을 정리한 1~20자 기준을 선택했다. 부화 창은 별도 비영속 세션을 써서 권한 정책이 기존 알림·입력창과 섞이지 않게 한다. 임시 펫 저장소에서 앱 재시작·저장 실패·잘못된 화면 요청·모의 잠금/절전과 화면 캡처를 검사했다. 실제 사용자 조작·물리 잠금/절전·사용자 DB 변환·시스템 알림·Windows는 미검증이다. 부화 준비 시간과 돌봄 단축 수치는 아직 미정이므로 자동 준비 판단은 꺼져 있다. 위 최초 기록의 이름 정책·실제 화면 연결 미정 표시는 당시 상태다.

## D-048. 아기 기본 생활과 실제 경험은 같은 펫 파일에 함께 저장한다

- **날짜·상태:** 2026-09-26. [PR #13](https://github.com/SoulJ-K/My-Jarvis/pull/13)의 아기 먹기·자율 수면·기본 경험 구현과 자동 검사 통과. 사용자 직접 조작과 장기간 사용은 미검증.
- **선택·이유:** LLM 없이 배고픔·졸림·자율 수면을 유지하고, 가상 먹이 한 종류의 식사·접촉·완료 수면 시간을 최소 경험으로 남긴다. 생활 상태와 경험을 같은 `pet.sqlite3`의 v4 형식에 한 번에 저장해 식사만 보이거나 경험만 남는 일을 줄인다. 첫 이름과 아기 생활 시작 시각도 같은 저장 묶음에 넣어 이름 직후 종료해도 시간이 이어지게 한다. 긴 부재는 완료된 수면 시간을 한 건으로 집계하며 가상의 돌봄 사건이나 벌점을 만들지 않는다. 저장 구조·사본·호환성은 [ADR-001](ADR-001-local-pet-storage.md)에 기록한다.
- **한계·후속:** 배고픔·먹이 등장·수면·접촉 간격은 검증용 잠정 구현값이며 제품 수치로 확정하지 않았다. v3에서 이미 이름을 지은 펫은 당시 시각 자료가 없어 v4 변환 시점부터 생활 시간을 센다. 경험 보존 기간과 이후 성격 반영 규칙, 낮·밤 행동, 실제 사용자 화면 조작·물리 절전·Windows는 미정 또는 미검증이다. 부화 준비 시간·돌봄 단축 수치는 여전히 미정이며 이 변경에서 자동 부화를 켜지 않았다.

## D-049. 아기 감정·관계는 몸 상태와 분리하고 경험만 최소 기록한다

- **날짜·상태:** 2026-09-26. [PR #14](https://github.com/SoulJ-K/My-Jarvis/pull/14)의 구현과 자동 검사 통과. 사용자 직접 조작·물리 잠금/절전·며칠 사용은 미검증.
- **선택·이유:** 기쁨·호기심·불편함은 짧은 감정, 배고픔·졸림은 몸 상태, 익숙함과 일시적 긴장은 느리게 변하는 관계로 따로 처리한다(D-028). 반복 접촉에는 잠깐 거리두기로 반응하고 시간이 지나면 회복한다(D-030). 커서 쫓기와 같은 펫의 감정구슬 놀이만 두며, 혼자 한 놀이를 사용자와 친해진 경험으로 세지 않는다. `안녕`만으로 재회라고 쓰지 않고 생활 관측 공백 뒤 명시적 인사가 있을 때 한 번 기록한다. 이는 실제 외출을 감지한 것이 아니다. 화면에는 내부 관계·감정 수치 대신 몸짓·거리·구슬만 전달한다(D-024·D-029).
- **저장·한계:** 같은 펫 파일의 v5 형식에 사회 상태와 칭찬·재회·반복 접촉·두 놀이의 종류/시각만 저장한다. 대화 원문·커서 좌표는 남기지 않고 생활·경험과 한 번에 저장한다. [ADR-001](ADR-001-local-pet-storage.md)에 v4 사본과 호환성 제약을 기록한다. 감정 6초, 거리두기 2분, 놀이 간격 5분 등은 검증용 잠정값이며 최종 감정 색상표·성격 학습·경험 보존 기간은 미정이다. 실제 사용자 DB 변환·운영체제 입력·알림 표시는 검사하지 않았다. 부화 준비 자동 판단은 계속 꺼져 있다.

## D-050. 아기의 낮·밤 표현과 복귀 인사는 저장된 관계 경험과 분리한다

- **날짜·상태:** 2026-09-26. [PR #16](https://github.com/SoulJ-K/My-Jarvis/pull/16)의 구현과 규칙·재시작·숨긴 화면 자동 검사 통과. 실제 사용자 조작·물리 절전·며칠 사용은 미검증.
- **선택·이유:** Character & Growth Design의 고정 낮·밤 방향을 기기 현지 시각의 잠정 구간(낮 07–20시, 밤 20–23시, 늦은 밤 23–07시)으로 표현한다. 밤의 자동 놀이를 줄이고 늦은 밤에는 깨어 있는 동안 졸림을 보이되 식사·자율 수면을 우선한다. 30분 이상 관측 공백·숨김·잠금·입력 유휴 뒤에는 최대 4초간 짧게 반길 수 있다. 자동 복귀 표현은 실제 외출을 확인한 사건이 아니므로 인사·돌봄·친밀도·경험을 만들어 저장하지 않는다. 기존 사용자의 명시적 인사에 따른 재회 기록과 구분한다.
- **잠정값·한계:** 시각 경계, 30분, 4초는 검증용 값이지 확정 제품 수치나 생활 패턴 학습이 아니다. 첫 등장·짧은 재시작·페이지 새로고침의 중복 인사를 막고 수면·식사·거리두기 중에는 인사를 예약하지 않는다. 시스템 시각 변경과 실제 부재를 완전히 구분할 수 없으며 실제 화면·물리 절전은 아직 확인하지 않았다. 저장 형식은 바꾸지 않았다.

**후속 선택 — 2026-09-26:** 사용자는 현재 낮 07–20시, 밤 20–23시, 늦은 밤 23–07시 시간표로 먼저 직접 테스트하기로 했다. 이 시간표를 최종 제품값으로 확정한 결정은 아니며, 화면에서 본 느낌에 따라 조정할 수 있다.

## D-051. 부화 준비 판단과 사용자가 목격하는 부화 시작을 분리한다

- **날짜·상태:** 2026-09-26. [PR #17](https://github.com/SoulJ-K/My-Jarvis/pull/17)의 정책 기반 준비 판단 구조와 메뉴 시작 구현·자동 검사 통과. **일반 실행의 자동 준비는 비활성**이다.
- **선택·이유:** 알의 누적 경과 시간과 실제 저장된 돌봄 사건만으로 준비 여부를 판단하고, 돌봄이 없어도 기본 시간이 지나면 준비되게 한다. 돌봄 단축에는 전체 상한과 인정 간격을 두어 연타만으로 시점을 크게 앞당기지 않는다. 인정되지 않은 돌봄도 실제 사건 기록에는 남긴다. 경과 시간과 준비 상태를 같은 SQLite 저장 묶음에 기록하며, 준비만으로 구슬·장면·성장 단계·이름을 진행하지 않는다. 준비 뒤 알 돌봄은 계속 가능하다. 첫 부화 장면은 사용자가 메뉴의 ‘부화 함께 보기’를 선택할 때만 열고, 단순 활성화·재실행은 알만 보여준다. 이미 목격한 장면은 기존 저장 지점부터 이어볼 수 있다.
- **미정·검증 경계:** 기본 대기 시간, touch/stroke 건당 단축량, 총 상한, 인정 간격은 사용자 결정 전이므로 제품 기본 정책을 넣지 않았다. 정책을 주입한 가짜 시계·임시 저장소·숨긴 Electron 화면, 로컬 Mac 묶음에서 경계·재시작·저장 실패·잠금 신호·메뉴 시작을 검사했다. 실제 사용자 자료 변환·마우스 조작, 물리 잠금·절전, Windows, 며칠 사용은 미검증이다. 기존 D-047의 미정 기록은 당시 상태이며 현재 구현·미정 구분은 이 항목을 따른다.

**후속 결정·구현 — 2026-09-26 / [PR #19](https://github.com/SoulJ-K/My-Jarvis/pull/19):** 사용자는 돌봄이 없어도 24시간이 지나면 준비되고, 저장된 클릭·쓰다듬기는 인정된 직전 돌봄과 누적 경과 시간 기준으로 1시간 이상 떨어졌을 때 건당 30분씩 앞당기며, 총 단축은 6시간(최저 18시간)으로 제한하는 기준을 선택했다. 연타를 시간 단축으로 세지 않으면서 실제 돌봄 기록은 보존하기 위한 선택이다. 일반 앱 시작·돌봄·주기 확인·절전 복귀에 이 기본 정책을 연결했다. 준비돼도 알로 기다리고 첫 장면은 사용자가 메뉴를 선택해야 시작한다. 임시 자료를 사용한 경계·재시작·장기 부재·메뉴 시작 자동 검사와 전체 회귀 검사, 로컬 Mac 앱 묶음 검사가 통과했다. 실제 사용자 마우스·메뉴 조작, 물리 절전, 며칠 생활은 아직 직접 확인하지 않았다. 위 미정·비활성 설명은 PR #17 당시 상태다.

**실기기 후속 확인 — 2026-09-26:** 별도 임시 펫에서 알 표시·드래그·투명 영역 클릭 통과·다른 앱 입력·화면 가장자리·처음 위치 이동을 사용자가 확인했다. 임시 경과 기록을 24시간으로 진행한 뒤 재실행해도 첫 장면은 자동으로 열리지 않았고, 메뉴 선택 후 부화·이름 입력까지 진행했다. 이름 입력 전 종료·재실행 시 같은 단계가 이어졌으며 이름 저장 후 아기 화면을 확인했다. 실제 18~24시간을 기다린 관찰과 물리 절전은 아직 하지 않았다. 이 과정에서 쓰다듬기 인식과 한글 입력 직후 첫 클릭 문제가 발견돼 D-052에서 분리한다.

## D-052. 실기기에서 드러난 쓰다듬기와 한글 버튼 첫 클릭을 보완한다

- **날짜·상태:** 2026-09-26. [PR #20](https://github.com/SoulJ-K/My-Jarvis/pull/20)의 수정·자동 검사와 별도 임시 펫의 사용자 재확인 통과.
- **발견:** 사용자가 밝아진 알을 짧게 좌우로 문질렀지만 두 번 모두 `stroke` 사건과 눌렸다 돌아오는 반응이 없었다. 이름 저장과 입력창 ‘보내기’는 한글을 적은 뒤 첫 클릭이 무시되고 두 번째에 처리됐다. 원인 중 하나로 한글 조합 종료 직후 100ms 차단이 명시적 마우스 클릭까지 막는 것을 코드에서 확인했다. 쓰다듬기 누락의 정확한 운영체제 이벤트 경로는 아직 단정하지 않는다.
- **수정·이유:** 누르고 있는 알이 쓰다듬기 상태일 때만 메인 프로세스가 운영체제 커서를 짧은 간격으로 살펴, 화면 이벤트가 합쳐져도 왕복을 판정하도록 보완했다. 짧은 왕복의 이동 범위를 조금 넓히되 단순 클릭·즉시 드래그·큰 이탈·취소는 구분한다. 커서 좌표는 저장하지 않는다. 한글 조합 확정 Enter는 계속 제출하지 않지만, 이름 저장·요청 보내기·알림 내용 확인 버튼을 사용자가 직접 클릭하면 조합 종료 직후라도 첫 클릭을 처리한다.
- **검증 경계:** 전체 `npm test`, 로컬 Mac 묶음 검사, 한글 조합 직후 명시적 버튼 클릭과 화면 이동 이벤트 없이 커서만 움직인 쓰다듬기 자동 검사가 통과했다. 사용자도 새 임시 알의 쓰다듬기 반응과 저장된 `stroke`, 한글 ‘보내기’와 첫 이름 저장의 첫 클릭을 확인했다. 이 손동작 범위에서 수정 동작은 검증됐으나 다른 입력 장치·Mac·Windows까지 확장해 주장하지 않는다. 기존 펫 자료와 저장 형식은 바꾸지 않는다.

## D-053. 사용자가 요청한 구슬 놀이는 자동 놀이와 별도 간격으로 처리한다

- **날짜·상태:** 2026-09-26. 코드·전체 자동 검사·로컬 Mac 묶음 검사와 기존 임시 펫 자료를 이용한 사용자 화면 확인 통과.
- **발견·이유:** 직접 화면 시험에서 `구슬 놀이`를 보내도 ‘잠깐 쉬고 싶대요’가 반복됐다. 같은 종류의 경험 기록이 정확히 5분마다 생겼지만, 이는 명령 처리의 증거가 아니라 자동 놀이의 기록이었다. 자동 놀이가 공용 쉬는 시간의 끝을 바로 선점하면 사용자가 명령할 기회가 거의 없다. 앞서 기록을 명령 처리로 해석한 설명을 정정한다.
- **수정·범위:** 사용자가 요청한 구슬 놀이의 5분 간격을 자동 놀이와 분리한다. 자동 놀이가 진행 중이어도 명시적 요청은 한 번 시작할 수 있고, 명시적 요청을 연달아 반복해 놀이는 무한히 연장할 수 없다. 기존 v5 저장 자료에 새 선택 필드가 없어도 읽을 수 있다. 놀이 종류·관계 수치 노출·권한·성장 범위는 바꾸지 않는다.
- **검증 경계:** 자동 놀이 직후 명시적 요청, 즉시 반복 제한, 기존 저장 상태를 재현하는 규칙 검사와 전체 `npm test`, `npm run test:mac-package`가 통과했다. 사용자가 수정 앱에서 실제 마우스로 첫 요청을 보내 ‘데굴데굴’과 구슬 움직임을 확인했다. 기존 임시 저장 자료에 요청 간격이 새로 저장된 것도 대조했다. 다른 기기·입력 장치·며칠 사용까지 검증한 것은 아니다.

## D-055. 비서 요청은 한 입력창에서 받고 날짜 알림은 확인 후 저장한다

- **8번 선택·이유:** 사용자가 확인한 넓은 생활 공간 안에서 아기가 천천히 먹이에 접근하고 입에서 조금씩 먹는 흐름을 유지한다. 창 크기 420×300, 접근 8~20초, 섭취 5.5초는 승인된 시안의 현재 구현값이며 최종 외형·크기 결정을 대신하지 않는다. 가장자리 먹이는 가장 가까운 도달 가능 위치로 조정한다. 먹은 자리에 남되 좌표는 현재 실행에만 유지한다. `food_offered`는 놓았을 때, `meal_finished`는 먹기 종료 뒤에 기록한다. 기존 저장 자료와 식사 중 재시작을 읽을 수 있게 유지한다.
- **통합 보완:** 사용자의 추가 확인에 따라 이름표·감정구슬도 이동하는 아기에 붙인다. 이름표는 이름 길이에 맞추고 긴 이름·구슬은 생활 공간의 가장자리에서 잘리지 않게 제한한다. 움직인 몸에 수면 기호를 붙이고 그림자도 같은 접근 속도로 움직인다. 아기 클릭 검사를 새 위치에 맞추며, 타이머 취소 후 조작으로 예전 등록 성공 문구가 되살아나는 문제를 수정한다.
- **통합 검사:** 임시 자료의 규칙·저장·재시작 검사 124개와 `baby-smoke`, `baby-social-smoke`, `schedule-smoke`, `timer-smoke` 순차 화면 검사를 통과했다. 초읽기의 첫 실제 화면 검사는 7초 표시 기대와 달랐으며 백그라운드 창의 실행 지연이 원인으로 추정된다. 검사 창의 백그라운드 시간 제한만 해제해 재실행했으며, 지연된 갱신에서 남은 시간을 다시 계산하는 경로는 별도 가짜 시계 검사로 확인했다. 종료 정리 경고·예외는 이 순차 화면 검사에서 관측되지 않았다. 원본의 기존 변경을 시험 적용한 알 제스처·아기 생활·앱 시작 관련 33개 검사도 통과했다. 이름표·감정구슬도 이동하는 아기를 따르도록 사용자 확인을 받았다. 원본 반영·실사용 확인은 별도 단계다. 실제 펫 자료·알림 권한을 변경하거나 펫을 재시작하지 않았다. 사용자 직접 조작·물리 절전·장기 생활·Windows·실제 알림 배너·소리는 미검증이다.

- **추가 배치 검사 — 2026-09-30:** 이름표·감정구슬 동반 이동을 반영한 뒤 원본의 기존 변경을 함께 적용해 아기 생활·반복 클릭·창 조작 화면 검사를 다시 통과했다. 이동 중과 식사·수면 후 이름표 정렬, 긴 이름 및 구슬의 가장자리 표시, 수면 기호, 기존 한글 입력·접촉·드래그 경로를 확인했다. 화면 캡처도 검수했다. 개별 변경은 [PR #30](https://github.com/SoulJ-K/My-Jarvis/pull/30)·[#31](https://github.com/SoulJ-K/My-Jarvis/pull/31)·[#32](https://github.com/SoulJ-K/My-Jarvis/pull/32)·[#33](https://github.com/SoulJ-K/My-Jarvis/pull/33)으로 보존한다. 사용자 실사용 확인은 남아 있다.

## D-060. 판타지형 알과 같은 투명창의 부화 흐름

- **날짜·상태:** 2026-09-30. 10~12번 사용자 시안 확인과 개별 워크트리 구현·임시 자료 검사. 9번 기상 동작과의 통합, 원본 반영·실사용 확인은 대기.
- **외형·크기:** 브라우저 시안의 남색 알·금색 별무늬·보랏빛 외곽빛을 채택하고 알과 아기의 보이는 외형을 기존 대비 약 80%로 한다. 180×200 알 창과 420×300 아기 생활 창, 먹이 좌표·입 위치·클릭 영역은 외형 크기와 별도로 다룬다. 이는 사용자가 두 크기를 같은 조건에서 비교하고 작은 쪽을 고른 결과다.
- **부화·이름:** 메뉴의 ‘부화 함께 보기’가 첫 장면의 시작점이다. 전조→금→구슬→껍질→아기→첫 교감은 차분하게 자동 연결하며, 보인 장면의 저장이 성공해야 다음으로 간다. 아기가 나온 뒤에만 같은 투명창을 넓히고 화면상 펫 중심을 유지한다. 첫 교감 뒤 아기 아래 작은 카드에서 이름을 저장하고 같은 창의 생활 화면으로 잇는다. 별도 부화 팝업이나 자동 말풍선은 쓰지 않는다.
- **기술 이유·한계:** 기존 생애 단계와 저장 지점·개체 식별자·돌봄 기록·준비 정책을 유지한 채, 부화 화면을 기존 펫 창에 겹쳐 창 교체에 따른 위치 단절을 피한다. 미리보기 장면은 펫 저장 자료와 분리했다. 숨긴 Electron 창의 임시 자료로 단계별 재실행·저장 실패·같은 개체·이름 뒤 생활 연결과 화면 위치를 검사했다. 실제 손 조작·물리 잠금·다중 모니터·원본 펫 자료는 확인하지 않았다.
