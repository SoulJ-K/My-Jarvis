이 문서는 **실제로 수행한 구현·통합·검사와 발견한 문제**를 날짜순으로 기록한다. 제품 범위와 완료 기준은 [PRD](Jarvis_Pet_PRD_v0.1.md), 선택과 이유·변경 이력은 [Decision Log](Jarvis_Pet_Decision_Log_v0.1.md), 구조와 검증 방법은 [Technical Design](Jarvis_Pet_Technical_Design_v0.1.md)을 따른다. 2026-10-01 이전 README 원문은 [보관본](../README_archive_2026-10-01.md)에 글자 그대로 남아 있다.

## 과거 기록을 읽는 기준

- 아래의 `미구현`, `미통합`, `미병합`, `미검증`은 **각 기록을 작성한 당시**의 상태다. 후속 결과가 바뀌면 날짜와 PR을 이어 적었다. 당시 개별 브랜치 검사, 통합 자동 검사, 사용자 macOS 화면 확인을 서로 대신하는 근거로 쓰지 않는다.
- 검사 수는 당시 실행한 묶음에만 적용된다. 뒤의 검사 수가 앞의 검사 수에 더해진 전체 누계라는 뜻은 아니다. `가짜 시계`, 숨긴 Electron 창, 임시 SQLite 파일로 한 검사는 실제 시간 경과·운영체제 알림·사용자 손동작을 증명하지 않는다.
- 이 문서의 PR 병합 언급은 목표 브랜치가 출발한 로컬 Git 병합 이력에서 확인한 범위다. 과거 문장의 `이번 작업에서 병합하지 않는다`는 후속 병합 이전의 지시·상태로 읽는다. [협업 규칙](../AGENTS.md)에 따라 실제 펫 자료와 인증정보는 기록하지 않는다.
- **초기 기록 당시 남은 검증:** 실제 macOS 시스템 알림 배너·소리, 물리적 절전·잠금과 복귀, 자연스러운 18~24시간 부화 대기와 며칠간의 생활, 다양한 화면·입력 장치·Windows 및 정식 배포용 앱. 아래 표의 미검증 표기도 당시 범위이며, 후속 실기기 결과를 함께 읽는다.

## 2026-09-26: 개발 도구와 임시 알 창

### 개발 도구 준비 — D-037

- **당시 작업:** macOS 26.6.2 / Apple Silicon에서 Node.js 24.21.0·npm 11.19.0을 사용하고 Electron 44.4.5와 TypeScript 7.0.2를 프로젝트의 개발용 의존성으로 고정했다. 전역 설치는 하지 않았다. `package-lock.json`에 연관 패키지 버전을 남기고 `node_modules/`는 Git 기록에서 제외했다.
- **당시 확인:** `npm ls --depth=0`, TypeScript·Electron 버전 명령이 성공했고 Electron 실행 파일 다운로드를 확인했다. 설치 시 npm 취약점 조회는 0개였다. 이 단계는 앱 실행·기능 검증이 아니었고 `npm ci` 재설치 경로는 별도 검증하지 않았다.
- **출처:** [D-037](Jarvis_Pet_Decision_Log_v0.1.md), [보관본의 개발 도구 준비 상태](../README_archive_2026-10-01.md).

### 임시 알 창, 입력 유지와 위치 — D-038 / PR #1

- **당시 구현·자동 검사:** 크림색 타원형 임시 알을 투명 창에 표시하고 클릭 흔들림, 드래그 이동, 메뉴 종료와 처음 위치 복원을 연결했다. `npm run typecheck`, 빌드, `npm test`로 알 표시, 화면의 Node.js 직접 접근 차단, 허용한 창 조작 요청과 발신 창 확인, 투명 픽셀·알 픽셀을 검사했다. 생성된 화면 이미지도 확인했다. 초기 그래픽은 최종 외형이 아니다.
- **사용자 화면 확인:** 사용자가 알 표시·클릭 반응·드래그를 확인했다. 알 클릭 뒤 원래 입력칸에 글을 이어 쓰지 못하는 문제가 보고돼 macOS의 비활성화 `panel` 창으로 수정했고, 자동 검사를 다시 통과했다. 사용자는 채팅 입력칸에 글 작성 → 알 클릭 → 다시 누르지 않고 이어 쓰기, 클릭·드래그 유지, 알 옆 투명 공간을 통한 뒤 폴더 클릭을 확인했다.
- **발견한 문제:** 메뉴의 처음 위치 복원은 사용자 확인을 받았으나 약 1.3초 지연이 보고됐다. 한 번의 내부 진단에서 복원 처리 자체는 1.55ms였고 실제 화면 이동 완료까지의 원인은 확정하지 못했다. 임시 진단 코드는 제거했다.
- **당시·후속 상태:** 최초 구현과 수정은 `codex/egg-window-prototype`에서 기록됐고 [PR #1](https://github.com/SoulJ-K/My-Jarvis/pull/1)의 병합 기록이 있다. 원문의 단계 1 미완료·메뉴 종료 미검증은 초기 시점의 상태다. 다른 앱·좌표·배율·다중 모니터 전반, 장시간 사용, Windows와 설치용 앱은 이 확인에 포함되지 않았다.

### 창 경계 보강 — PR #5

`codex/window-behavior-checks`는 페이지 재로딩 중 오래된 드래그가 남는 문제와 화면 작업 영역 축소 시 알이 화면 밖에 남는 문제를 숨긴 Electron 창에서 재현하고 수정했다. 타입 검사, 기존 19개 검사, 화면 연결 검사와 새 창 검사를 통과했다. 5/6 DIP 이동 경계, 둥근 모서리, 재로딩 취소, 네 가장자리·음수 원점·1/1.25/2 배율 및 모니터 제거 가정은 내부 입력·화면 정보 대체로 검사했다. 실제 물리 모니터 변경과 다른 앱의 클릭·입력 보존은 이 검사로 확인하지 않았다. 당시 별도 검토 브랜치였고 이후 [PR #5](https://github.com/SoulJ-K/My-Jarvis/pull/5)의 병합 기록이 있다. 구조와 이유는 [D-038 후속](Jarvis_Pet_Decision_Log_v0.1.md)에 남긴다.

## 2026-09-26: 같은 알 저장, Pet Brain, 돌봄

### SQLite 저장·복원 — D-039 / PR #2

- **당시 개별 결과:** `codex/egg-persistence`에서 Electron의 내장 `node:sqlite`를 사용해 앱 전용 `userData/pet/pet.sqlite3`에 알 식별자·생성 시각·단계·형식 번호를 저장했다. 재시작 후 같은 알을 복원하고 손상·빈 파일·미지원 형식·저장 실패에서는 기존 파일을 보존하며 시작을 멈추도록 했다. 타입 검사, 저장 검사 8개, 실제 Electron 시작 검사 5개와 화면 요청 검사를 임시 자료로 통과했다. 실제 정전·디스크 소진·장기간 보존은 미검증이었다.
- **상태 연결:** 이 브랜치의 `미통합·병합 금지`는 당시 지시다. 저장 방식의 근거와 복구 한계는 [ADR-001](ADR-001-local-pet-storage.md), 후속 통합과 병합은 아래 PR #4 기록을 따른다. 당시에는 이름·부화·아기 경험·위치를 저장하지 않았다.

### AI 없는 대기·클릭 반응 — D-040 / PR #3

`codex/egg-brain`은 쉬기 → 약 480ms 클릭 반응 → 다시 쉬기 규칙을 화면·SQLite·외부 AI와 분리했다. 가짜 시계의 규칙 검사 4개와 실제 Electron 연결 검사에서 반복 클릭, 대기 복귀, 페이지 재로딩과 이전 상태 무시, 종료 취소 및 다른 창 요청 거절을 확인했다. 당시 저장 브랜치와 통합하지 않았고 실제 사용자의 macOS 마우스 조작·장시간 사용은 미검증이었다. 브랜치의 별도 검토 상태와 후속 통합은 다음 기록을 구분해 읽는다.

### 저장 + 반응 통합 — D-041 / PR #4

- **당시 통합 자동 검사:** `codex/egg-integration`에서 저장 PR #2의 `2d2fd59`와 Brain PR #3의 `b0a380d`를 함께 연결했다. `npm run typecheck`, `npm test`, `git diff --check`를 통과했다. 규칙 4개 + 저장 8개 + 실제 앱 시작·통합 7개 = **19개**와 화면 연결 검사를 수행했다. 숨긴 Electron 창의 페이지 클릭 → 반응 → 재로딩 → 대기, 종료·재시작 후 같은 식별자 복원·재클릭, 반응 중 강제 종료 후 대기 복원, 손상·쓰기 실패 시 원본 보존을 확인했다. 반응 전후 SQLite 내용이 같다는 검사도 포함했다.
- **발견·수정:** `npm start`에서는 `require.main === module` 조건 때문에 앱 초기화가 실행되지 않았고 기존 검사 도우미가 시작 함수를 직접 불러 이 누락을 놓쳤다. 실제 시작 파일에서 초기화를 호출하도록 분리하고 검사를 고친 뒤 타입·19개 검사·화면 연결 검사, 일반 실행 시작과 앱 전용 저장 파일을 확인했다.
- **사용자 화면 확인:** 일반 실행한 통합본에서 사용자가 클릭 반응·대기 복귀·메뉴 종료와 복원된 알의 재클릭 반응을 확인했다. 식별자·생성 시각·단계가 종료 전후 같고 알이 하나임을 읽기 전용으로 대조했다. 당시 실행 앱은 통합 워크트리 버전이었다.
- **상태 연결:** 초기 `미병합` 기록 뒤 사용자가 개별 PR #2·#3 종료와 통합 [PR #4](https://github.com/SoulJ-K/My-Jarvis/pull/4) 병합·원본 동기화를 승인했고, 로컬 병합 이력에서 PR #4를 확인했다. 실제 운영체제 커서의 이 통합본 드래그·입력 유지, 설치용 앱·Windows·장시간 사용까지 검증한 것은 아니다.

### 알 돌봄과 경과 기록 — D-042 / PR #6

- **당시 개별 결과:** `codex/egg-care-life`에서 바로 끌기는 창 이동, 잠깐 누른 뒤 문지르기는 쓰다듬기로 구분하고 클릭·쓰다듬기 사건과 경과 시간을 같은 SQLite 파일에 저장했다. 가짜 시계와 임시 DB를 사용한 규칙·생활·저장 검사 20개, 실제 앱 검사 8개와 화면 연결 검사(**합계 28개**)를 통과했다. 화면 캡처에서 알과 저장 실패 안내를 확인했다. 당시 브랜치는 개별 검토 대상이었고 부화·아기·타이머·입력창은 범위 밖이었다.
- **통합 후:** 알 돌봄·입력·타이머 세 작업을 합친 임시 통합 브랜치에서 실제 페이지 클릭으로 돌봄 사건을 저장하고 5분 타이머를 등록·재시작해 같은 알·돌봄 사건·예약을 확인한 뒤 취소했다. 타입 검사와 규칙·저장·재시작 **43개** 및 Electron 화면 검사 묶음을 통과했다. 공통 `windows.ts`에는 재로딩·화면 변경 때 돌봄 준비 취소를, `app.ts`에는 두 저장 흐름과 종료 처리를 함께 유지했다. 앱 시작 때 경과 시간을 기록하므로 타이머 검사의 `펫 DB 바이트 불변` 전제를 식별 정보·돌봄 사건 불변으로 고쳤다([D-044](Jarvis_Pet_Decision_Log_v0.1.md)). 이후 [PR #6](https://github.com/SoulJ-K/My-Jarvis/pull/6)의 병합 기록이 있다.

## 2026-09-26: 입력·시간 요청과 Mac 앱 묶음

### 입력창과 5분 타이머 — D-043 / PR #7

- **당시 개별 결과:** `codex/prompt-five-minute-timer`는 메뉴의 `입력 / 타이머`에서 여는 창, `5분 타이머` 등록·취소, 초점을 가져가지 않는 앱 안내, 종료 중 지난 예약의 미확인 목록 복원을 구현했다. 예약은 펫 DB와 분리된 `assistant/timers.sqlite3`에 저장하고 입력 원문은 저장하지 않았다. 이 단계에서는 한 개의 5분 타이머만 지원했으며 알람·다른 길이·아기 대화는 미구현이었다.
- **검사·수정:** 기존 19개에 규칙 11개·실제 앱 재시작 3개를 더한 **33개**와 알·입력·타이머 Electron 화면 검사를 통과했다. 등록 전 저장, 중복·미지원 요청, 취소, 시각 변경·절전 복귀 가짜 시계, 지난 예약·전달 중단·실패 상태·사용자 확인, 조합 중 Enter 방지와 Esc·등록 뒤 8초 자동 닫기·다른 창 초점 유지를 포함했다. 숨긴 Electron 창에서는 화면의 `document.hidden`만으로 실제 표시 여부를 판단할 수 없어 메인 영역의 창 표시 상태도 확인하도록 수정했다. 실제 5분 대기와 운영체제 한글 입력기를 대신 확인한 것은 아니다.
- **발견·후속:** 당시 개발용 Electron의 시스템 알림 요청은 `failed` / `UNErrorDomain 오류 1`이었고 서명 읽기 검사도 실패했다. 실제 macOS 알림 표시 성공을 주장하지 않는다. 개별 초안 PR·미병합 설명은 [PR #7](https://github.com/SoulJ-K/My-Jarvis/pull/7) 병합 이전의 상태다. 완전 종료·절전 중 정시 전달은 보장하지 않고 다시 열 때 지난 항목을 보여준다.

### 격리된 Mac 미리보기 앱과 알림 — D-045 / PR #8

`codex/mac-notification-validation`은 `Jarvis Pet Preview.app`을 별도 폴더에 만들고 실제 펫 저장 자료와 분리된 경로에서 숨긴 실행·임시 서명 검사를 수행했다. 알림 결과의 중복·지연·종료 경로와 운영체제 권한을 요청하지 않는 가짜 알림 검사 **8개**를 확인했다. 원문의 개발용 Electron 알림 실패 뒤 진행한 별도 단계이며, 실제 시스템 알림 배너·소리, 정식 배포용 서명·Apple 공증·Finder 설치는 미검증이다. 이후 [PR #8](https://github.com/SoulJ-K/My-Jarvis/pull/8)의 병합 기록이 있다.

### 일회성 알람·리마인더 — D-046 / PR #10

`codex/one-shot-alarms-reminders`는 `오늘/내일/YYYY-MM-DD`와 명확한 시각·내용을 확인한 뒤 별도 `assistant/schedules.sqlite3`에 저장하고 목록·취소·지난 미확인 항목 복원을 연결했다. 실행 중 만료는 앱 안에 안내하고, 앱이 완전히 종료된 동안 정시 전달은 약속하지 않는다. 입력 당시 현지 시각·시간대·UTC 오프셋을 함께 저장하는 것은 당시 구현 가정이며 장기 제품 정책으로 확정하지 않았다. 통합 때 실제 알람의 운영체제 알림 요청 연결점을 추가하고 가짜 알림으로 결과를 검사했다. 실제 표시·권한, 물리 절전·잠금과 실제 한글 입력기는 미검증이다. [PR #10](https://github.com/SoulJ-K/My-Jarvis/pull/10)의 병합 기록이 있다.

### 2026-09-30: 실사용 수정 1~4번과 입력창 — D-055·D-057

단일 입력창은 타이머·짧은 대화·날짜 알림을 한 칸에서 받고 알림 확인 카드의 명시적 등록 전에는 저장하지 않도록 했다. 별도 임시 자료의 `schedule-smoke`, `timer-smoke`, `baby-social-smoke` 검사에서 한글 조합, 초안 폐기·중복 전송, 재시도와 기존 경로 연결을 확인했다. 실제 사용자 화면 재확인은 당시 남았다. 펫을 클릭해도 가려진 입력창이 앞으로 오지 않는 문제는 `isVisible()`만 보는 조건에서 재현했고, 작성 내용·선택 범위를 보존하며 같은 창을 앞으로 가져오도록 고쳤다. 검사 종료의 임시 폴더 삭제에서 `ENOTEMPTY` 예외가 나와 오류창이 떴던 문제는 종료 정리에 제한된 재시도·경고를 추가하고 오류 주입으로 확인했다. 실제 macOS 경합 순서는 미확정이다.

실사용 수정 1~4번은 [PR #24](https://github.com/SoulJ-K/My-Jarvis/pull/24)·[#25](https://github.com/SoulJ-K/My-Jarvis/pull/25)·[#26](https://github.com/SoulJ-K/My-Jarvis/pull/26)·[#27](https://github.com/SoulJ-K/My-Jarvis/pull/27)을 순서대로 합쳤다. 별도 통합 공간에서 규칙·저장·시작·재시작 **117개**와 순차 화면 검사, Mac 앱 임시 서명·숨긴 실행·허용 파일 **44개** 일치를 통과했다. 화면 오류 때 같은 창을 최대 두 번 재로딩하고 30초 정상 동작 뒤 횟수를 초기화하는 경로, 알림 표시 뒤 실패 신호 기록, 수면 중 반복 접촉의 기상 뒤 거리두기, 입력창 재표시를 연결했다. 패키지 종료 주변에 Chromium 임시 캐시 경고가 있었지만 검사 종료 코드는 0이었다. 원본의 기존 미커밋 변경을 시험 적용한 창 조작·알 제스처·아기 대화 검사도 통과했다. 실제 펫을 검사 편의로 초기화·종료·재시작하지 않았다. 사용자 실제 조작·실제 알림·물리 잠금·절전·장기 생활은 남았다.
