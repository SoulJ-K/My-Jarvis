이 문서는 **실제로 수행한 구현·통합·검사와 발견한 문제**를 기록한다. 최신 작업 묶음을 상단에 펼쳐 두고, 이전 기록은 날짜순으로 보존한다. 제품 범위와 완료 기준은 [PRD](Jarvis_Pet_PRD.md), 선택과 이유·변경 이력은 [Decision Log](Jarvis_Pet_Decision_Log.md), 구조와 검증 방법은 [Technical Design](Jarvis_Pet_Technical_Design.md)을 따른다. 2026-10-01 이전 README 원문은 [보관본](https://github.com/SoulJ-K/My-Jarvis/blob/c0a8cfc35d3a555732db23d24b208938270c64a7/README_archive_2026-10-01.md)에 글자 그대로 남아 있다.

## 문서 작성·읽기 규칙

- **역할:** 실제 구현·통합·검사·발견한 문제를 기록한다. 제품 범위와 완료 기준은 PRD, 결정 이유는 Decision Log, 현재 구조와 검증 방법은 Technical Design에 맡기고 연결한다.
- **갱신 시점:** 의미 있는 작업·검사 또는 사용자 확인 뒤 날짜별 기록을 추가하고 상단 요약은 최신 내용으로 교체한다. 이전 요약을 상단에 누적하지 않으며 근거·이력은 날짜별 본문에 보존한다. 계획·제안과 실행 사실을 구분한다.
- **작성 순서:** `결과 → 당시 작업·검사 조건과 근거 → 실패·미검증·후속 결과` 순서로 쓴다. 브랜치·기준 커밋·기존 미커밋 변경, 환경·시험 자료·검사 범위를 가능한 근거 안에서 명시한다.
- **검증 구분:** 개별 검사·통합 검사·원본 반영·사용자 확인을 구분한다. 자동 검사·실제 화면·운영체제 알림·자연 경과 생활은 서로 대신하지 않으며 검사 수는 실행별로 기록하고 누적 합산하지 않는다.
- **과거와 후속:** 과거의 대기·미검증은 당시 상태로 보존하고 후속 결과에 연결한다. 재검사 통과로 최초 실패·당시 한계·미확정 원인을 지우지 않는다. 제품 기준이나 미정 정책을 개발 결과만으로 새로 확정하지 않는다.
- **근거 보존:** 반복 설명은 요약하되 날짜·조건·관찰·판단 이유·참조를 추적할 수 있게 남긴다. 다른 문서가 참조하는 연결 지점을 유지하고, 표시 형식 변경을 새 검증으로 기록하지 않는다. 실제 펫의 개인 기억·대화 원문과 인증정보는 포함하지 않는다.

- **펼침·접기:** 문서 제목·작성 규칙·최신 요약·최신 기록은 항상 보이게 두고 새 최신 작업 묶음을 상단에 배치하고 이전 기록은 날짜·작업 묶음별로 접는다. 오래됐다는 이유로 당시 결정이 무효가 되는 것은 아니며, 변경 여부는 후속 결정과 근거로 판단한다. 접기 영역은 중첩하지 않는다.

### 8.10 실사용 알림 클릭의 앱 연결 보정 — 2026-10-07

`package-mac.mjs`는 실사용 저장 위치를 기준으로 고정된 `companion` 식별값을 만들고, Preview·Validation 생성본의 식별값과 분리한다. 같은 저장 위치의 재빌드는 같은 권한을 사용한다. `--activate <앱 절대경로>`는 서명·식별값을 확인하고 해당 식별값의 등록 경로만 선택한 앱으로 갱신한다. macOS 기본 실행 경로와 등록 목록이 선택한 앱만 가리키는지 확인하며 실패 시 이전 등록 복구를 시도한다. 앱 생성·활성화 자체는 펫 DB를 읽거나 수정하지 않는다(생성 시 기존 DB 파일의 메타데이터 확인은 수행). 기존 자료는 동일한 경로를 사용하며 버전 전환 백업을 보존한다.

검사는 합성 펫 자료로 식별값 분리·같은 펫 식별값 유지·선택 앱 등록·동일 식별값의 이전 앱에서 새 앱으로 교체·과거 Preview 등록 보존·서명·숨김 실행·같은 펫과 예약 보존을 확인했다. 첫 실행은 정리 단계에서 이미 해제된 등록을 다시 해제해 실패했고, 실제 등록 목록을 확인하도록 보완한 두 번째 실행은 종료 코드 0으로 통과했다. 종료 중 나타난 기존 IPC 처리기 해제 로그도 보존한다. 기록은 로컬 `notification-routing-package-01.log`와 `notification-routing-package-02.log`이며 실제 사용자의 새 알림 허용·배너·소리·클릭 후 앱 연결은 별도 확인 대상이다. 이전 배너는 옛 식별값을 가리킬 수 있어 새로 등록한 시험 타이머로 확인한다.

### 8.12 결과 확인 말풍선 — 2026-10-07

8.11 수정본을 키우는 아기에 적용한 뒤 사용자는 가장자리에서 즉시 멈춤, 이름·감정구슬의 동시 표시를 확인했다. 시스템 배너 클릭에서는 작성창과 결과 카드가 겹쳤고, 카드 외형은 재수정하기로 했다. 이는 이전 자동 검사 통과와 별개의 실사용 실패다.

사용자 결정에 따라 결과 카드를 작은 말풍선으로 변경했다. 일정 제목과 **했어요 / 아직이에요 / 취소할게요**를 바로 표시하며 ‘더 보기’는 제거한다. 아기 위를 우선하고 공간이 부족하면 옆에 배치한다. ‘아직이에요’는 같은 말풍선에서 5분·30분·직접 입력을 선택하고, ‘돌아가기’로 선택을 닫을 수 있다. 취소는 해당 일정의 재알림·재촉만 해제한다. 시스템 알림 클릭으로 현재 아기의 결과를 확인할 때 작성창을 숨기되 작성 중인 내용은 보존한다. 알림 확인과 실제 일 완료는 여전히 별개다.

**이번 자동 확인:** 빌드(타입 검사 포함), 결과·재알림 관련 16개 검사, 숨김 창 검사 2종 통과. 실제 앱이 등록한 타이머 알림 클릭 처리로 작성창 숨김·초안/커서 보존을 검사했다. 말풍선 세 버튼의 한 줄 배치·크기·재알림 선택과 복귀·완료/되돌리기·취소 시 다른 타이머 유지·창 파괴 후 정리를 검사하고 실제 렌더링 이미지를 확인했다. 시스템 배너·소리는 이번 자동 검사에서 발생시키지 않았다.

**실패와 한계:** 최초 말풍선 검사에서 취소된 항목이 활성 목록에 남는다고 잘못 가정해 실패했다. 목록에서 제거되고 후속 기록이 취소 상태인지로 바로잡은 재실행은 통과했다. 최초 종료 중 닫힌 창을 조회하는 부수 오류도 발견해 요청 검사에 창 생존 확인을 추가했다. 최초 실패와 재실행은 로컬 `bubble-*` 로그에 각각 보존한다. 후속 실사용에서 사용자는 배너 클릭 시 작성창 없이 말풍선만 표시, 재알림 선택·돌아가기·취소를 확인했다. 외형 전체에 대한 최종 디자인 승인을 뜻하지 않으며, 커밋·푸시는 남은 실사용 확인 후 진행한다.

### 8.13 재촉 중 말풍선 고정과 점프 조정 — 2026-10-07

8.12 적용 후 사용자는 배너 클릭 시 말풍선만 표시, 재알림 선택·돌아가기·취소를 확인했다. 이후 ‘구슬놀이’의 Enter 제출과 구슬 움직임, 약한 재촉의 확대·분홍색·1분 재알림, 강한 재촉의 빨간색을 확인했다. 다만 강한 동작은 통통 뛰기보다 빠르게 달리는 듯했고, 말풍선까지 따라 움직여 버튼을 누르기 어렵다는 실사용 실패가 있었다. ‘저절로 끝남’ 발언은 사용자가 정정했으므로 자동 완료 오류로 판단하지 않는다.

**사용자 결정:** 말풍선이 열려 있어도 아기의 재촉 행동은 계속한다. 말풍선은 열릴 때의 위치를 기준으로 유지하여 버튼을 누를 수 있게 한다. 펼침/접힘의 크기 조정은 해당 위치 기준이며, 닫힌 뒤 다시 열릴 때만 현재 아기 위치를 새로 기준으로 삼는다. 아래 통통 뛰기는 몸 전체가 한 궤적으로 이동하고, 약 700ms 도약·300ms 착지 대기·한 번에 145px 이동·32px 높이로 조정했다. 이는 표현 조정값이며 재촉 단계, 5초 행동·반복 간격, 완료/취소 해제 조건은 바꾸지 않았다. 커서 근처 행동 선호도 유지한다.

**이번 검사:** 빌드(타입 검사 포함), 생활·재촉 24개 검사, 숨김 창 검사 2종 통과. 열린 말풍선과 재알림 선택창의 위치 유지, 동작 중 응답 처리, 566px 가로 이동과 도약·착지 대기를 확인했다. 후속 실사용에서 사용자는 깡총깡총 뛰는 느낌, 아기가 움직이는 동안 말풍선 고정, ‘했어요’ 클릭 후 평소 색·크기 복귀를 확인했다. 최초 `hop-red-01`은 말풍선 이동 실패 재현이다. `hop-green-01/02`는 이동 폭 검사 실패로, 이전 동작 정리와 시험 시작 위치를 분리한 뒤 `03`이 통과했다. 화면 끝에서 되돌아온 이동을 처음에는 누락해 판정했으며, 각 로그와 확인한 궤적은 로컬에 보존한다. 시스템 알림·실제 휴지통을 자동 검사에 사용하지 않았다.

**8.13 당시 다음 실사용 확인(후속 결과는 8.14절):** 휴지통 간식은 잠든 아기에게 요청하면 먹을 수 없다는 안내가 나오는 것까지 사용자가 확인했다. 준비한 시험 파일 2개는 그대로 존재한다. 자연스럽게 깨어난 뒤 파일 선택 → 최종 확인의 취소/승인 → 시험 파일 삭제·먹기 → 즉시 다시 요청 시 간격 차단을 확인한다. 실제 기존 휴지통 자료는 시험 대상으로 삼지 않는다. 이번 변경의 통과 항목을 새 실패나 영향 있는 수정 없이 반복하지 않는다. 자연 부화·며칠 생활은 별도 세션, 일부 생활 조건·잠금/절전·추가 화면 환경은 앞선 미검증 범위를 유지한다.

### 8.14 휴지통 간식 전용 선택창 — 2026-10-07

실사용에서 운영체제 파일 선택창이 휴지통 목록을 보여주지 않았고, 사용자가 숨김 경로를 입력해도 목록으로 이동하지 못했다. 선택 화면 진입의 실사용 실패로 기록하며 삭제 검증 통과로 세지 않는다. 사용자 승인으로 경로 탐색을 없애고 앱 전용 목록·파일 이름 검색·최대 2개 선택·최종 영구삭제 확인으로 변경했다.

간식 요청 시에만 홈 휴지통 한 단계의 일반 파일 이름과 검증용 메타데이터를 읽는다. 폴더·심볼릭 링크·하드 링크·안전하게 표시할 수 없는 이름을 제외한다. 화면에는 이름과 임시 식별자만 전달하고 파일 경로는 메인 영역에 둔다. 목록 조회 실패와 선택 가능한 파일 없음은 구분한다. 목록 뒤 파일이 변경되거나 식사 조건을 잃으면 진행하지 않으며, 최종 확인 이후 기존 이동·재검증·개별 삭제 절차를 유지한다. 입력 요청과 Dock 요청은 같은 선택 흐름을 사용한다. 파일 내용·폴더 내부·외장 휴지통은 탐색하지 않는다.

**이번 검사:** 빌드·최소 CI 185개와 숨김 통합 화면 검사 통과. 목록의 대상 제한·식별자/파일 변경 거부, 다른 창의 요청 거부, 세 개 선택 거부, 선택 취소/최종 취소 시 보존, 승인한 합성 파일 두 개만 삭제·나머지 보존·먹기·15분 차단을 확인했다. 실제 렌더링을 확인했다. 최초 화면 검사는 첫 선택 후 갱신되기 전 요소를 다시 누른 검사 코드 때문에 실패했으며, 현재 요소를 찾도록 보완한 재실행이 통과했다. 실패와 재실행은 로컬 `snack-picker-*` 로그에 각각 보존한다. 이 자동 검사 당시 실제 앱의 휴지통 접근과 시험 파일 삭제 실사용은 적용 후 확인 대상이었다. 아래 후속 결과와 구분하며 사용자 기존 파일을 검사 대상으로 사용하지 않았다.


**후속 실사용 — 같은 날:** 전용 목록에서도 휴지통 접근이 거부됐고 동일 요청 재검사도 실패했다. macOS 권한 기록에서는 개발 실행을 시작한 Codex가 접근 책임 대상으로 판정됐다. 사용자에게 권한 범위를 설명한 뒤 **Jarvis Pet에만 전체 디스크 접근 권한**을 허용했다. 시스템 설정의 해당 앱 켜짐과 다른 앱의 기존 상태 유지를 확인하고, 같은 앱을 정상 종료·자료 백업·앱으로 다시 열었다. 같은 개체·이름·단계와 기존 돌봄·생활·상호작용 기록의 보존을 확인했다. 실행 중 첫 백업은 종료 과정에서 임시 소켓이 사라져 불완전하게 끝났으며, 종료 후 새 백업은 82개 파일의 내용 일치와 저장소 무결성을 확인했다. 개인 자료와 로컬 기록은 Git에 포함하지 않는다.

### 입력창과 5분 타이머 — D-043 / PR #7

- **당시 개별 결과:** `codex/prompt-five-minute-timer`는 메뉴의 `입력 / 타이머`에서 여는 창, `5분 타이머` 등록·취소, 초점을 가져가지 않는 앱 안내, 종료 중 지난 예약의 미확인 목록 복원을 구현했다. 예약은 펫 DB와 분리된 `assistant/timers.sqlite3`에 저장하고 입력 원문은 저장하지 않았다. 이 단계에서는 한 개의 5분 타이머만 지원했으며 알람·다른 길이·아기 대화는 미구현이었다.
- **검사·수정:** 기존 19개에 규칙 11개·실제 앱 재시작 3개를 더한 **33개**와 알·입력·타이머 Electron 화면 검사를 통과했다. 등록 전 저장, 중복·미지원 요청, 취소, 시각 변경·절전 복귀 가짜 시계, 지난 예약·전달 중단·실패 상태·사용자 확인, 조합 중 Enter 방지와 Esc·등록 뒤 8초 자동 닫기·다른 창 초점 유지를 포함했다. 숨긴 Electron 창에서는 화면의 `document.hidden`만으로 실제 표시 여부를 판단할 수 없어 메인 영역의 창 표시 상태도 확인하도록 수정했다. 실제 5분 대기와 운영체제 한글 입력기를 대신 확인한 것은 아니다.

### 후속 결과와 남은 확인

- **수면 중 접촉 — 2026-09-30 수정:** 위 행의 “자는 동안 거리두기가 끝날 수 있음 / 일괄 수정 대기”는 수정 전 관찰이다. D-057과 아래 실사용 수정 1~4번의 통합 기록에 기상 뒤 거리두기 연결이 남아 있다. 2026-10-06 [관계 규칙 코드](../src/pet/baby-social.ts)에서 예정 기상 시각 이후까지 거리두기를 유지하는 계산과 [검사 코드](../tests/baby-social.test.ts)의 수면·재시작·자연 기상 경로를 확인했다. 실제 사용자의 자연 수면·기상 확인은 별도로 남는다.
- **갑작스러운 종료 — 2026-09-30 일부 복구 보완:** 후속 통합에서 화면 처리 오류의 제한된 재로딩을 추가했다. 이것만으로 위 관찰의 앱 종료 원인이 밝혀지거나 물리 절전·잠금 문제가 해결됐다고 판단하지 않는다. 주 실행 프로세스 종료와 화면 오류는 구분한다.
- **이름표 — 2026-09-30 후속 통합:** 위의 짧은 이름 `테스트` 확인은 초기 폭 수정의 사용자 확인 기록이다. D-058과 실사용 수정 5~8번 통합에서는 움직이는 아기에 이름표를 붙이고 긴 이름의 가장자리 잘림도 제한했다. 10월 6일 코드 검토에서 현재의 구체적인 이름표 규칙이 초기 폭 수정을 포함함을 확인했다. 이후 위치·긴 이름의 모든 실제 화면을 사용자가 확인했다는 뜻은 아니다.
- **입력·알림 — 2026-10-01 일부 실기기 확인:** 아래 시험용 Mac 앱 기록에서 입력창 접근, 타이머 배너, 일회성 알람 배너·소리, 예정 시각 전 재실행한 타이머 진행 상태, 전달된 알람의 미확인 복원과 확인 후 재실행 유지가 확인됐다. 따라서 위 표의 사용자 확인 대기는 해당 범위에 한해 후속 결과가 있다. 모든 자연어 문법·닫힘 초읽기·리마인더 전달·종료 중 만료 복원까지 확인한 것으로 확대하지 않는다.
- **계속 남은 항목:** D-054 보정 후 실제 손동작, 외형·부화·먹이 이동·기상 동작의 각 미확인 범위, 물리 절전·잠금, 자연 경과 부화·며칠 생활, 재부팅 자동 실행 정책은 별도 확인·결정 대상이다. 구체적인 후속 자동 검사·실기기 결과는 이어지는 날짜별 기록을 따른다.

### 2026-09-30: 실사용 수정 1~4번과 입력창 — D-055·D-057

단일 입력창은 타이머·짧은 대화·날짜 알림을 한 칸에서 받고 알림 확인 카드의 명시적 등록 전에는 저장하지 않도록 했다. 별도 임시 자료의 `schedule-smoke`, `timer-smoke`, `baby-social-smoke` 검사에서 한글 조합, 초안 폐기·중복 전송, 재시도와 기존 경로 연결을 확인했다. 실제 사용자 화면 재확인은 당시 남았다. 펫을 클릭해도 가려진 입력창이 앞으로 오지 않는 문제는 `isVisible()`만 보는 조건에서 재현했고, 작성 내용·선택 범위를 보존하며 같은 창을 앞으로 가져오도록 고쳤다. 검사 종료의 임시 폴더 삭제에서 `ENOTEMPTY` 예외가 나와 오류창이 떴던 문제는 종료 정리에 제한된 재시도·경고를 추가하고 오류 주입으로 확인했다. 실제 macOS 경합 순서는 미확정이다.

실사용 수정 1~4번은 [PR #24](https://github.com/SoulJ-K/My-Jarvis/pull/24)·[#25](https://github.com/SoulJ-K/My-Jarvis/pull/25)·[#26](https://github.com/SoulJ-K/My-Jarvis/pull/26)·[#27](https://github.com/SoulJ-K/My-Jarvis/pull/27)을 순서대로 합쳤다. 별도 통합 공간에서 규칙·저장·시작·재시작 **117개**와 순차 화면 검사, Mac 앱 임시 서명·숨긴 실행·허용 파일 **44개** 일치를 통과했다. 화면 오류 때 같은 창을 최대 두 번 재로딩하고 30초 정상 동작 뒤 횟수를 초기화하는 경로, 알림 표시 뒤 실패 신호 기록, 수면 중 반복 접촉의 기상 뒤 거리두기, 입력창 재표시를 연결했다. 패키지 종료 주변에 Chromium 임시 캐시 경고가 있었지만 검사 종료 코드는 0이었다. 원본의 기존 미커밋 변경을 시험 적용한 창 조작·알 제스처·아기 대화 검사도 통과했다. 실제 펫을 검사 편의로 초기화·종료·재시작하지 않았다. 사용자 실제 조작·실제 알림·물리 잠금·절전·장기 생활은 남았다.

### 2026-09-30: 실사용 수정 5~8번 — D-058 / PR #30~#34

자연스러운 한국어 알람 시각과 오전·오후 선택, 성공 결과의 닫힘 초읽기, 자동 생활 문구 대신 수면 `zZ`, 먹이로 다가가 먹는 움직임과 이름표·감정구슬 동반 이동을 통합했다. 임시 자료에서 규칙·저장·재시작 **124개**와 순차 `baby-smoke`, `baby-social-smoke`, `schedule-smoke`, `timer-smoke`를 확인했다. 첫 초읽기 화면 검사는 기대한 7초 표시와 달랐고 백그라운드 창 지연이 원인으로 추정됐다. 검사 창의 백그라운드 시간 제한을 해제해 재실행했으며, 지연 후 남은 시간 재계산은 별도 가짜 시계 검사로 확인했다. 원인은 확정하지 않았다. 원본의 기존 알 제스처·아기 생활·시작 관련 33개 검사와 이름표·구슬 화면 연결도 확인했다.
