## 문서 작성·읽기 규칙

1. **결정과 이유를 기록한다.** 무엇을 선택했고 왜 선택했는지, 적용 범위와 중요한 대안을 남긴다.
2. **상태를 구분한다.** 확정 결정, 가설, 잠정 구현값, 미정 사항을 명시한다. 결정 확정을 구현·검증 완료로 표현하지 않는다.
3. **결정이 바뀌거나 구체화될 때 갱신한다.** 단순 작업 진행은 개발 기록에 남긴다. 기존 결정 번호를 유지하고, 같은 결정의 보완은 해당 항목에 날짜·근거와 함께 적는다. 별도 결정이 필요하면 새 번호를 부여하고 이전 결정과의 관계를 남긴다. 다른 문서의 연결을 위해 기존 제목도 가능한 한 유지한다.
4. **과거와 현재를 연결한다.** 후속 결정으로 바뀐 부분을 명시하고, 당시 선택 이유와 검증 한계를 지우지 않는다. 과거의 ‘미구현·미통합·미검증’에는 당시 상태임을 표시한다.
5. **문서별 역할을 지킨다.** 기능·완료 기준은 PRD, 행동 표현은 행동·성장 설계, 구현 구조는 기술 설계, 작업·검사 결과는 개발 기록으로 연결한다. 이 문서에는 결정을 이해하는 데 필요한 요약만 남긴다. 저장 방식의 대안·제약·호환성은 ADR(기술 선택과 이유를 남기는 기록)을 함께 참조한다.
6. **정보를 보존하며 정리한다.** 내용을 줄이거나 다른 문서로 옮길 때 중요한 근거·한계가 보존됐는지 확인한다. 추천안을 승인된 결정으로 바꾸지 않는다. 다른 문서에 없는 정보는 대상 문서에 보존하기 전까지 삭제하지 않는다.

7. **최근 요약은 교체하고 결정 이력은 보존한다.** 제목·이 규칙·최근 변경 요약·최신 기록은 펼쳐 두고 이전 기록은 날짜·주제별로 접는다. 오래된 결정도 변경·대체가 명시되지 않은 범위에서는 유효하다. 새 변경 때 상단 요약을 교체하고 이유와 변경 관계는 해당 결정에, 실행 결과는 개발 기록에 남긴다.
8. **프로젝트 문서를 원본으로 관리한다.** 최종 원본은 `/Users/rkfrk/Desktop/My Jarvis`의 프로젝트 문서다. GitHub는 승인된 변경 기록을 확인하는 곳이며 Notion은 읽기용 사본이다. 수정은 프로젝트 문서에서 하고 검토 후 사본에 반영한다. 작업 폴더의 수정본은 통합 검수 후 원본에 반영한다. Notion 가져오기의 접기·펼침 보존은 별도 변환·화면 확인 전에는 보장하지 않는다.

새 항목은 `결정 날짜·상태 → 결정 → 이유 → 적용 범위·미정 → 후속 변경 → 검증 기록` 순서를 기본으로 한다. 필요 없는 칸을 채우려고 새로운 결정이나 검증 사실을 만들지 않는다.

## D-054. 알 쓰다듬기는 대각선 왕복과 알 경계 밖 놓기를 인정한다

- **발견·이유:** 기존 좌우 좌표만 보는 판정은 대각선 왕복을 놓쳤고, 시작점에서 멀리 벗어나면 왕복해도 무효로 처리했다. 알 요소에만 손 떼기 신호를 받는 구조 역시 알 모양 바깥에서 끝나는 조작을 놓칠 수 있었다. 사용자는 큰 좌우 왕복, 대각선 왕복, 알 바깥에서 손 떼기를 돌봄으로 기대한다.
- **수정·범위:** 350ms 동안 움직이지 않고 누른 뒤 시작한 쓰다듬기에서 첫 의도적인 이동 방향을 기준으로 평면상의 되돌림을 판정한다. 이동 총량과 되돌림의 작은 흔들림 방지 기준은 유지하되 시작점에서 멀어졌다는 이유만으로 취소하지 않는다. 손 떼기 신호는 알 요소뿐 아니라 같은 투명 창 전체에서 처리한다. 누르자마자 이동한 창 드래그, 한 방향 이동, 조작 취소는 계속 돌봄으로 저장하지 않는다. 저장 형식·부화 시간 정책은 바꾸지 않는다.
- **이전 결정과의 관계:** D-042·D-052의 좌우 전용·거리 제한은 각 결정 당시의 구현 기준이다. 이 결정은 평면상 왕복과 같은 창 안에서의 놓기로 인식 범위를 보정하며, 창 바깥의 운영체제 입력까지 검증됐다는 뜻은 아니다.
- **검증 경계·이력:** 자동 검사와 실제 손동작 확인을 구분한다. 과거 전체 검사 보고의 근거 범위는 [2026-09-27 개발 기록](Jarvis_Pet_Development_Log.md#stroke-adjustment-2026-09-27), 원본 미커밋 코드의 재검사 결과는 [2026-10-06 검토 기록](Jarvis_Pet_Development_Log.md#uncommitted-review-2026-10-06)을 따른다. 실제 마우스의 창 밖 놓기·다른 입력 장치·장시간 생활은 별도 사용자 확인 대상이다.

- **후속 사용자 확인 — 2026-10-06:** [개발 기록](Jarvis_Pet_Development_Log.md)의 「PR #39 병합 후 쓰다듬기 사용자 실사용 확인」에는 현재 Mac과 입력 장치에서 클릭·즉시 이동·좌우 왕복·대각선 왕복·알 테두리 바로 밖 놓기·한 방향 이동의 여섯 동작을 사용자가 확인한 결과가 있다. 병합 전 검증으로 소급하지 않으며 투명 창 바깥의 운영체제 입력, 다른 장치·화면 환경까지 확대하지 않는다. 이 손동작 확인 자체에는 돌봄 저장 조회·재시작이 포함되지 않았고, 같은 시험 알의 저장 유지·재실행은 해당 개발 기록의 별도 후속 절을 따른다.

## D-001. 프로젝트 정체성은 게임이 아니다

- **배경/이유:** 처음부터 경험치·미션을 중심에 놓으면 제품 방향이 게임으로 고정되기 쉽다. 핵심 경험은 펫과 관계를 맺고, 성장에 따라 도움을 받는 데 있다.

- **영향/후속 조치:** PRD와 포트폴리오에 같은 세 분류를 사용한다. 구현하지 않은 기능을 완성된 기능처럼 쓰지 않는다.

## D-003. 펫은 AI 없이도 동작한다

- **날짜:** 2026-09-25
- **상태:** 확정
- **결정:** Pet Brain은 외부 AI 언어 모델(LLM) 없이도 펫의 정체성·상태·감정·행동·관계·기억·성장·간단한 반응을 유지한다.
- **배경/이유:** 어린 성장 단계에는 AI 기능이 적어도 펫 자체의 존재감이 있어야 한다. 인터넷이나 AI 서비스가 멈췄을 때 펫 전체가 작동하지 않는 상황도 피해야 한다.
- **영향/후속 조치:** 기본 상태 변화와 반응을 AI 호출 없이 처리한다. 어린 단계의 핵심 경험을 별도로 정의한다.

## D-004. Pet Brain과 AI를 분리한다

- **날짜:** 2026-09-25
- **상태:** 확정(구조 원칙)
- **결정:** 펫의 정체성·상태·행동·감정·관계·기억·성장을 다루는 Pet Brain과 선택적으로 쓰는 AIService를 분리한다. Codex는 Pet Brain 전체가 아니라 사용자가 시작하는 로컬 작업을 돕는 Agent/도구 후보다. 구체적인 모듈 경계는 설계 단계에서 정한다.
- **배경/이유:** AI 언어 모델이 펫의 성격과 상태 전체를 결정하면 AI 장애나 제공자 변경에 따라 같은 펫의 연속성이 흔들릴 수 있다.
- **영향/후속 조치:** 기본 상태 변화는 Pet Brain에서 관리하고, 외부 AI는 자연어 생성·복잡한 추론·고난도 작업에만 선택적으로 쓴다. 상세 구조 확정 시 ADR을 작성한다.

## D-005. 특정 AI Provider에 종속되지 않고, One Provider First로 간다

- **날짜:** 2026-09-25
- **상태:** 확정(구조 원칙); 일반 대화용 첫 제공자 미정
- **결정:** AI 제공자를 교체할 수 있는 연결 경계를 고려하되, MVP에서 여러 제공자를 동시에 연동하지 않는다. Codex 작업 경로는 일반 대화용 AIProvider와 별도로 판단한다.
- **배경/이유:** 여러 제공자를 처음부터 모두 연동하면 범위가 커진다. 반대로 한 제공자의 고유 기능을 펫 핵심 코드에 직접 엮으면 이후 교체 비용이 커진다.
- **영향/후속 조치:** 제공자별 연결 방식과 펫 핵심 기능을 분리한다. 첫 일반 대화용 제공자는 아직 선택하지 않는다. Codex의 조건부 작업 경로와 Claude·Gemini 보류 판단은 D-019에 기록한다.

## D-006. Local-first & User-owned Memory

- **날짜:** 2026-09-25
- **상태:** 확정(저장 원칙); SQLite 선택은 D-039, 세부 방식은 ADR-001
- **결정:** 펫의 감정·관계·성장·기억·리마인더 등 핵심 데이터는 기본적으로 사용자 기기에 저장하고, 특정 AI 제공자의 기억 기능에 종속시키지 않는다.
- **배경/이유:** 기억을 사용자가 소유해야 AI 제공자를 바꿔도 펫의 연속성을 유지할 수 있다. 개인정보 보호, 오프라인 동작, 초기 서버 비용 절감에도 맞는다.
- **영향/후속 조치:** 로컬 저장·내보내기·복구 방안을 검토한다. SQLite 선택 시 별도 ADR로 근거와 제약을 기록한다. 이후 D-039의 사용자 선택에 따라 [ADR-001](ADR-001-local-pet-storage.md)에 방식·대안·실패 처리·검증 한계를 기록했다.

## D-007. 무료 원칙을 제품의 핵심 제약조건으로 둔다

- **날짜:** 2026-09-25
- **상태:** 확정
- **결정:** '무료'는 추가 AI API 과금을 기본값으로 요구하지 않는다는 뜻이다. 기존 유료 구독 자체가 무료라는 뜻은 아니며, 모든 기존 구독을 제3자 앱에서 재사용할 수 있다는 뜻도 아니다. 이는 Jarvis Pet의 핵심 제약조건이다. 초기에는 중앙 서버·저장소 운영이나 Jarvis Pet이 사용자별 AI API 비용을 대신 부담하는 구조를 제외한다.
- **배경/이유:** 현 단계의 목표는 개인용 완성품과 실제 사용 검증이다(D-017). 기존 구독을 추가 API 요금 없이 쓰는 경로는 제공자별로 다르므로 D-019의 조사 결과를 따른다. 기존의 '초기 운영비 최소화' 결정은 이 원칙의 일부로 유지한다.
- **영향/후속 조치:** 서버가 꼭 필요한 기능만 별도 비용 근거를 세워 검토하고, 로컬에서 처리 가능한 기능을 우선한다. AI 연결 방식을 결정할 때 추가 API 과금 여부와 운영자의 사용자별 비용 부담을 필수 조건으로 확인한다(D-008).

## D-008. 기존 AI 계정의 공식 연결을 기본 전략으로 삼는다

- **날짜:** 2026-09-25
- **상태:** 연결 검토 원칙 확정; 제공자별 실제 연동 방식은 D-019에 따름
- **결정:** 기존 AI 계정과 공식 로컬 클라이언트·명령줄 도구(CLI)를 통한 연결은 해당 용도가 공식적으로 허용될 때에만 우선 검토한다. 다음으로 무료 공식 계정 범위와 로컬 모델을 보조 경로로 검토한다. API 키는 기본값이 아니며, 추가 과금 가능성을 안내받은 사용자가 원할 때만 선택하는 대체 연결 수단으로 둔다. Jarvis Pet이 사용자별 AI API 비용을 대신 부담하는 구조는 피한다.
- **배경/이유:** D-007의 무료 원칙을 지키면서 공식 허용 범위 밖의 구독 재사용을 피해야 한다. ChatGPT·Claude·Gemini의 개인용 유료 구독이 제3자 앱의 API 사용권을 뜻한다고 가정하지 않는다. 현재 제공자별 결론은 D-019에 기록한다.
- **영향/후속 조치:** 제공자별로 공식 로그인·로컬 도구 연동 가능 여부, 이용 조건, 구독 범위 및 추가 과금 여부를 확인한 뒤 지원 방식을 정한다. 공식 인증 토큰을 추출하거나 내부 API를 우회하는 등 비공식적이거나 이용 조건을 위반할 수 있는 방식은 사용하지 않는다. 사용자가 API 키를 선택하는 경우에만 예상 과금과 안전한 보관 방식을 안내·설계한다.

## D-009. 단일 펫으로 구현하되 `petId`로 멀티펫 확장을 고려한다

- **날짜:** 2026-09-25
- **상태:** 확정
- **결정:** MVP에서는 펫 한 마리만 구현한다. 데이터 식별에는 `petId`를 고려해 나중에 여러 펫을 구분할 여지를 둔다.
- **배경/이유:** 현재 멀티펫 기능은 필요하지 않지만, 펫별 데이터의 식별 방법을 나중에 추가하면 저장 구조를 크게 바꿔야 할 수 있다.
- **영향/후속 조치:** 데이터 모델 설계 시 펫 식별자를 검토하되, 멀티펫 화면·관리 기능은 MVP 범위에 넣지 않는다.

## D-010. 성장은 외형뿐 아니라 관계·사용자 이해·비서 능력의 성숙을 뜻한다

- **날짜:** 2026-09-25
- **상태:** 방향 확정; 단계는 D-022에서, 성장 방식은 D-026에서 후속 결정, 수치 조건은 미정
- **결정:** 성장을 단순한 외형 변화로 정의하지 않는다. 펫과 사용자의 관계, 사용자에 대한 이해, 수행할 수 있는 비서 업무도 함께 성숙하는 경험을 지향한다.
- **배경/이유:** 어린 펫의 기본 행동에서 시작해 대화·기억·상황 이해·업무 수행으로 이어져야 성장이 제품 경험으로 느껴진다. 단순한 기능 잠금 해제만으로는 이 의도가 전달되기 어렵다.
- **영향/후속 조치:** 단계별 이해·제안·수행 능력과 구체적 성장 조건은 사용자 경험과 구현 가능성을 확인하며 후속 설계에서 정한다. 실제 실행 권한은 성장 단계와 별개로 사용자가 허용한 범위에서만 주어진다(D-032).

## D-011. 이미 존재하는 기능 자체를 차별점으로 주장하지 않는다

- **날짜:** 2026-09-25
- **상태:** 확정(표현 원칙)
- **결정:** 움직이는 펫, 감정, 기억, 여러 AI 연동, 로컬 저장, 알람, 성장 같은 기능 하나만으로 독창성을 주장하지 않는다.
- **배경/이유:** 앞선 대화에서 NekoAI, Miru, Pet Mochi, desktop-pet 등 유사 사례를 비교 대상으로 확인했다. 개별 기능의 존재만으로 차별화가 검증되지는 않는다.
- **영향/후속 조치:** 경쟁 분석에서 각 제품의 실제 제공 범위를 확인하고, 차별성은 기능의 조합·성장 과정·사용자 경험을 근거로 평가한다.

## D-012. 현재 차별화는 가설 상태로 유지한다

- **날짜:** 2026-09-25
- **상태:** 가설
- **결정:** ‘펫이 사용자와 함께 성장하면서 이해·제안·수행 능력을 넓히고, 장기적으로 여러 AI와 도구를 조율하는 개인 비서가 된다’는 방향을 차별화 가설로 둔다. 실제 실행 권한은 성장 단계와 별개로 사용자가 허용한 범위에서만 주어진다.
- **배경/이유:** 이 조합이 의미 있는 경험인지, 경쟁 제품과 실질적으로 어떻게 다른지는 아직 충분히 검증되지 않았다.
- **영향/후속 조치:** 경쟁 분석과 최소 기능 제품 검증 전에는 확정된 차별점으로 표현하지 않는다. 검증 결과에 따라 가설을 수정하거나 폐기하고 새 결정을 기록한다.

## D-013. 태어난 펫의 정체성은 교체하지 않는다

- **날짜:** 2026-09-25
- **상태:** 확정(제품 원칙); 구체적인 외형·구현 방식 미정
- **결정:** 한 번 태어난 펫은 성장 과정에서 다른 캐릭터로 교체하지 않는다. AI 제공자나 외형이 변해도 같은 개체로 이어진다.
- **배경/이유:** 사용자가 펫에게 쌓은 기억과 애착은 특정 외형이나 AI 제공자보다 오래 지속되어야 한다. NekoAI를 AI 연결 없이 써본 경험에서도 캐릭터 교체 구조가 애착을 약하게 느끼게 했다.
- **영향/후속 조치:** 캐릭터 교체를 기본 경험으로 설계하지 않는다. 액세서리·꾸미기는 펫의 정체성을 바꾸지 않는 범위에서만 검토한다.

## D-014. 관계의 지속성을 외형 선택권보다 우선한다

- **날짜:** 2026-09-25
- **상태:** 확정(사용자 경험 원칙)
- **결정:** 외형이 취향에 완전히 맞지 않더라도 “못생기고 못나도 내가 키운 내 펫”이라는 관계와 애착을 우선한다.
- **배경/이유:** 원하는 외형을 계속 고르고 바꿀 수 있는 선택권보다, 태어난 개체와 함께 살아온 시간이 펫 경험의 중심이어야 한다.
- **영향/후속 조치:** 외형 선택·꾸미기 기능을 검토할 때 관계의 연속성을 해치지 않는지 확인한다. 구체적인 외형과 꾸미기 범위는 별도로 정한다.

## D-015. 성장에서 예측하지 못한 개체 고유성을 허용한다

- **날짜:** 2026-09-25
- **상태:** 확정(방향); 표현 방식 미정
- **결정:** 성장 과정에서 미리 정해진 외형·행동만 반복하기보다, 함께 지낸 결과로 예상하지 못한 개체 고유성이 드러나는 것을 허용한다.
- **배경/이유:** 모든 펫이 같은 결과로 수렴하면 사용자가 키운 한 개체라는 감각이 약해질 수 있다. 관계와 경험이 쌓이는 과정이 성장에 반영되어야 한다.
- **영향/후속 조치:** 성격·행동·말투 등에서 개체성을 표현할 수 있는 방안을 검토하되, 성장 조건과 구현 방식은 검증 후 결정한다.

## D-016. 성장의 최종 목표는 애착과 높은 업무 수행 능력의 결합이다

- **날짜:** 2026-09-25
- **상태:** 확정(장기 목표); 구체적인 능력과 사용자 허용 범위의 설계 미정
- **결정:** 펫은 관계와 개체성을 유지하면서 사용자 이해, 비서 능력, 업무 수행 주도성(Agency)이 성장해 믿고 일을 맡길 수 있는 개인 비서·에이전트가 된다. 최종상은 “일 완전 알잘딱깔쎈 내 펫”이다.
- **배경/이유:** 외형 변화나 친밀감만으로는 Jarvis Pet의 개인 비서 비전을 달성할 수 없다. 반대로 업무 능력만 높아져도 함께 키운 펫이라는 의미가 약해진다.
- **영향/후속 조치:** 성장 단계별로 관계 경험과 이해·제안·수행 능력을 함께 설계한다. 실제 작업 실행 권한은 성장과 별개로 사용자 허용 범위에 따라 정한다(D-032).

## D-017. 개인용 완성품을 먼저 만든다

- **날짜:** 2026-09-25
- **상태:** 확정(현재 범위)

- **배경/이유:** 실제로 끝까지 만들고 써볼 수 있는 범위가 먼저 필요하다. 배포·운영 문제를 앞당기면 핵심 펫 경험 검증이 늦어진다.
- **영향/후속 조치:** PRD의 기능을 D-002의 세 범위로 나눈다. 지인 대상 배포나 서비스화는 별도 결정 전까지 현재 MVP 목표로 쓰지 않는다.

## D-018. 기본 자동화와 사용자 오버라이드를 함께 제공한다

- **날짜:** 2026-09-25
- **상태:** 확정(사용자 경험 원칙); 구체적 설정 화면 미정
- **결정:** 기본 사용은 자동화하고 기술 설정을 단순하게 한다. 사용자가 체감하는 선택권은 펫의 외형·탄생·키우는 방식·관계에 집중하되, 명시적 요청과 고급 설정으로 AI 제공자·모델·사용 시점·허용·금지 조건을 제어할 수 있게 한다. 우선순위는 **사용자 명시 제약 > 고급 설정 > 작업별 선호 > 자동 Router 판단**이다.
- **배경/이유:** 자동 선택은 편리하지만 사용자의 명시적 금지나 선택을 덮어쓰면 신뢰를 해친다. 반대로 모든 기술 결정을 먼저 요구하면 펫과 관계를 맺는 경험이 약해진다.
- **영향/후속 조치:** 자동 Router는 미래 확장으로 두고, 도입 시에도 이 우선순위를 지킨다. 고급 설정의 구체적 범위와 화면은 별도로 설계한다.

## D-019. 기존 구독 재사용은 Codex 작업 경로만 조건부 후속 후보로 둔다

- **날짜:** 2026-09-25
- **상태:** 조사 기반 조건부 판단; v0.1 필수 구현 아님, 실제 연동·이용 조건 재검증 필요
- **결정:** 기존 유료 구독을 추가 API 과금 없이 공식 경로로 재사용하는 **후속 연결 검토 후보**는 현재 조사 기준 OpenAI Codex의 로컬 작업 경로다. 검토 범위는 사용자가 직접 시작하는 로컬 코드·파일 작업 보조로 제한한다. 일반 ChatGPT 대화를 Jarvis Pet에 그대로 임베드해 기존 구독으로 쓰는 공식 경로는 확인되지 않았다. Claude·Gemini 기존 구독을 제3자 앱에서 재사용하는 방식은 보류한다. 여러 제공자에 대응 가능한 구조는 유지하고, 향후 공식 허용 방식이 생기면 재검토한다.
- **배경/이유:** `research/`의 OpenAI·Claude·Gemini 구독 재사용 타당성 조사에서 구독과 일반 API 과금은 구분되며, 제공자별 공식 허용 범위가 다름을 확인했다. D-005·D-007·D-008의 넓은 연결 원칙을 현재 조사 결과에 맞춰 좁힌다.
- **영향/후속 조치:** Codex는 Pet Brain 전체나 일반 대화용 AIProvider가 아닌 작업 수행 Agent의 후속 후보로 둔다(D-004). 실제 제품 연동과 운영체제별 동작·사용량·이용 조건은 도입 전에 다시 확인한다. Claude·Gemini 구독 연결과 Codex 로컬 작업 연결을 v0.1 필수 기능으로 표시하지 않는다. **변경 이력:** 기존 `MVP 후보` 표현을 D-022의 최종 v0.1 잠금 범위에 맞춰 `후속 연결 검토 후보`로 정정했다.

## D-020. Pet Brain은 혼합형 구조의 독립적인 중심이다

- **배경/이유:** D-003·D-004가 정한 펫의 연속성을 유지하면서 어려운 대화와 작업에는 AI의 이점을 활용할 수 있다.
- **영향/후속 조치:** 기본 상태·반응과 AI 호출의 경계는 D-003·D-004를 따른다. Local LLM의 채택 여부·모델·실행 요구 사항은 별도 검증 후 결정한다.

## D-022. v0.1은 알에서 아기까지로 잠근다

## D-023. 돌봄의 부재가 죽음이나 성장 실패로 이어지지 않는다

## D-024. 관계와 감정은 수치 대신 행동으로 느끼게 한다

- **배경/이유:** 관계를 점수로 관리하면 살아 있는 개체와 함께 지내는 감각보다 최적화 게임에 가까워진다. 사용자는 강아지나 고양이의 마음을 알아가듯 펫의 반응을 관찰한다.
- **영향/후속 조치:** 내부 계산값이 필요할 수 있지만 사용자에게 직접 노출하지 않는다. 구체적 표현은 캐릭터 설계에서 정한다.

## D-025. 선천 기질과 후천 경험을 함께 쓰되 성격은 키우며 발견한다

- **결정:** 펫에게 약한 선천 기질을 두고, 함께 지낸 경험이 성격과 선호·비선호에 더 크게 영향을 주게 한다. 사용자가 성장 결과나 완성된 성격을 메뉴에서 직접 고르지 않는다. 취향은 오래 유지될 수 있으나 경험을 통해 서서히 변할 수 있다.

- **영향/후속 조치:** 아기 시기의 경험 기록 자체는 v0.1 필수 구현이다. 구체적인 기록 항목·보존 기간과 이후 성격에 반영하는 규칙은 후속 설계에서 검토한다. **변경 이력:** D-015의 개체 고유성 방향을 이 결정에서 형성 원칙으로 구체화했다.

## D-026. 성장은 시간과 경험을 결합한다

- **날짜:** 2026-09-25
- **상태:** 확정(후속 성장 설계 원칙); v0.1의 아기→어린이 성장 대상 아님
- **결정:** 시간 경과가 성장을 가능하게 하고, 돌봄·상호작용 경험은 성장 속도와 이후 성향에 제한적으로 영향을 준다. 방치가 성장 실패 조건이 되지 않는다.
- **배경/이유:** 경험만 필수 조건으로 삼으면 돌봄 부담이 생기고, 시간만 쓰면 함께 지낸 방식이 성장에 남지 않는다.
- **영향/후속 조치:** v0.1에서는 알→아기 부화와 아기 경험 기록에만 적용 범위를 한정한다. 아기 이후의 시간 조건과 경험 반영량은 후속 버전에서 설계한다. **변경 이력:** D-010의 미정이던 성장 조건에 방향을 정하되 수치 조건은 계속 미정으로 둔다.

## D-027. 성장과 부화의 중요한 순간은 사용자가 보게 한다

- **날짜:** 2026-09-25
- **상태:** 확정(경험 원칙); v0.1에서는 부화에 적용
- **결정:** 사용자가 없는 동안 성장 조건을 충족해도 실제 부화·성장 연출은 사용자가 보는 앞에서 일어난다. 전조를 먼저 보여 기대할 시간을 주며, 성장 뒤에는 외형뿐 아니라 행동과 비서 능력도 단계에 맞춰 달라진다.
- **배경/이유:** 사용자가 돌아왔을 때 이미 커져 있으면 자신이 키운 펫의 변화를 함께 겪었다는 감각이 사라진다. 단순 기능 해금만으로는 성장으로 느껴지지 않는다.
- **영향/후속 조치:** v0.1의 부화 흐름은 PRD와 캐릭터 설계에서 정의한다. 아기→어린이 이후 성장 연출은 후속 버전 설계로 둔다. **변경 이력:** D-010의 성장 의미를 관찰 가능한 경험 원칙으로 보강했다.

## D-028. 감정·몸 상태·관계를 구분한다

## D-029. 감정구슬은 수치판이 아닌 펫의 소지품이다

## D-030. 관계에는 변화가 있지만 영구적인 이별은 없다

## D-037. 첫 검증용 Electron·TypeScript는 프로젝트별로 설치하고 버전을 고정한다

- **날짜:** 2026-09-26
- **당시 구현·검증 상태:** 설치 요청 범위의 기술 선택·개발 도구 설치 및 버전 실행 확인 완료; 앱 기능 구현·실기기 검증 아님
- **결정:** 기존 Node.js 24.21.0·npm 11.19.0을 사용해 Electron **44.4.5**와 TypeScript **7.0.2**를 원본 프로젝트의 개발용 패키지로 설치했다. `package.json`에 정확한 버전을 지정하고 연관 패키지 버전은 `package-lock.json`에 보존한다. 두 도구를 전역 설치하거나 다른 프로젝트·시스템 설정을 변경하지 않는다.
- **배경/이유:** 다른 프로젝트에서도 사용하더라도 필요한 버전과 갱신 시점은 다를 수 있다. 전역의 한 버전을 공유하는 것보다 프로젝트별로 버전을 기록하면 업데이트 충돌을 줄이고 같은 개발 환경을 복원하기 쉽다. 당시 공개 npm registry의 안정판과 Node.js 요구 조건을 조회했으며 사용한 Node.js는 Electron의 `>=22.12.0`, TypeScript의 `>=16.20.0` 조건을 충족한다.
- **영향/후속 조치:** `package.json`은 도구 명세, `package-lock.json`은 동일 의존성 구성을 재설치하기 위한 기록으로 관리한다. 설치 직후에는 앱 실행·테스트 명령과 앱 코드가 없었다(D-038에서 후속 구현). 창·클릭·이동·입력 방해 여부, Windows, 앱 코드의 TypeScript 호환성은 미검증이다. Electron 최종 채택은 D-035의 후속 판단 대상이었고 React·SQLite 등도 당시 미정이었다. SQLite는 이후 D-039에서 선택했다. 설치 당시 원본 저장까지 진행했고 커밋·GitHub 전송은 그 작업 범위에 포함하지 않았다.

## D-038. 첫 구현은 추가 화면 도구 없이 임시 알 창으로 검증한다

- **날짜:** 2026-09-26
- **당시 구현·검증 상태:** 사용자 구현 승인 / 임시 알 표시·클릭·드래그 사용자 확인 / 자동 검사 통과 / 단계 1 일부 검증

- **배경/이유:** 한 개의 임시 알과 창 조작을 확인하는 단계에서 화면 프레임워크나 최종 그래픽 제작을 먼저 늘릴 필요가 없다. `preload`는 화면과 앱 관리 영역을 잇는 작은 연결 코드다. 여기에 허용한 창 조작만 노출하고 파일·시스템 명령 실행은 제공하지 않는다. `IPC`는 분리된 화면 영역과 앱 관리 영역이 요청을 주고받는 통로다. 요청의 종류·값·발신 창을 확인하며, 알 바깥에서는 마우스 입력을 뒤 앱으로 넘기도록 한다. 일반 창의 드래그 영역은 클릭 이벤트를 받지 않으므로 이번에는 짧은 클릭과 일정 거리 이상 이동을 구분하는 처리를 사용했다. [Electron 창 상호작용](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions), [보안 안내](https://www.electronjs.org/docs/latest/tutorial/security)
- **영향/후속 조치:** 단계 1 전체 완료와 Electron 최종 채택은 남은 창 검증 후 판단한다. 첫 구현 당시 저장·Pet Brain·쓰다듬기·굴러가기·부화·아기 생활·알림은 없었다. React·SQLite 등의 선택을 이 결정만으로 확정하지 않으며, SQLite 선택은 D-039의 후속 결정이다. 원본에 코드·검사·기록을 저장하고 `codex/egg-window-prototype`에서 도구 설치·임시 알 코드·검사·관련 문서를 기록 대상으로 묶었다.
- **변경 이력 — 2026-09-26:** 최초 구현은 `6a05df5`로 기록하고 로컬 `main`에 병합했다. 이후 사용자가 알 클릭 뒤 기존 입력칸에 글이 이어지지 않는 문제를 보고했다. macOS 일반 창의 `focusable: false`만으로 앱 활성화를 막지 못한 것으로 추정하여, macOS에만 비활성화 패널(`type: 'panel'`)을 적용했다. 입력을 가로채 복원하는 방식 대신 창 자체의 운영체제 동작을 바꾸는 작은 수정이다. [Electron 창 종류 안내](https://www.electronjs.org/docs/latest/api/base-window)에 근거하며, 패널이 모든 데스크톱 공간에 나타나는 특성은 표시 정책 확정 전 별도 확인한다. 수정 직후 자동 검사와 후속 사용자 입력 유지 확인은 [개발 기록](Jarvis_Pet_Development_Log.md)의 「임시 알 창, 입력 유지와 위치 — D-038 / PR #1」에 구분한다.
- **기록 범위 확인 — 2026-09-26:** 사용자는 “브랜치 생성해서 머지까지”가 GitHub에서의 작업을 뜻한다고 명확히 했다. 최초 구현과 후속 입력 유지 수정·검증 기록을 같은 작업 브랜치로 전송하고 PR 생성·GitHub 병합·원본 로컬 `main` 동기화까지 진행한다. 이후 같은 표현의 승인 범위는 [AGENTS.md](../AGENTS.md) 15번에 남기며, 단순한 기록 시점 추천을 업로드 승인으로 취급하는 것은 아니다. 실제 병합 결과와 커밋은 GitHub PR·Git 이력에서 확인한다.

## D-039. 같은 알의 저장·복원은 SQLite로 시작한다

- **선택 당시 미정·범위:** Electron에서 사용할 SQLite 연결 방식·라이브러리는 런타임 호환성과 테스트로 판단한다. D-006의 별도 ADR 기록 요구를 확인하고 새 문서가 필요하면 이름·필요성·내용을 먼저 안내한다. Pet Brain 생활·부화·아기·알림·LLM은 이번 저장 단계의 구현 범위 밖이다. 원본의 기존 미커밋 문서 변경을 보존하면서 결과를 통합한다.

- **후속 기술 선택:** Electron 내장 `node:sqlite`를 추가 패키지 없이 사용했다. 저장 형식·복구 한계는 [ADR-001](ADR-001-local-pet-storage.md)을 따른다.

## D-042. 알의 쓰다듬기와 이동을 나누고 최소 돌봄 사건을 보존한다

- **후속 결정 연결:** 아래 조작 수치는 2026-09-26의 잠정 기준이다. D-052에서 인식을 보완했고 D-054에서 평면상 왕복과 같은 투명 창 안 놓기로 범위를 보정했다. 시작점 이탈 제한을 현재 기준으로 적용하지 않는다. 부화 준비 시간 연결은 D-051을 따른다.
- **기록 날짜·당시 상태:** 2026-09-26. 담당 2 `codex/egg-care-life`의 구현·자동 검사 결과. 사용자 승인 범위의 개별 draft PR(검토용 변경 요청)까지이며, main·원본·기존 실행 앱·실제 펫 자료에는 반영하지 않았다.
- **조작 결정·이유:** 짧은 클릭은 기존 흔들림, 누른 직후 6 DIP 이상 움직이면 위치 이동, 350ms 동안 이동을 시작하지 않고 누른 뒤 좌우로 문지르면 쓰다듬기다. DIP은 화면 배율과 무관한 논리적 거리 단위다. 이동을 먼저 시작하면 손을 놓기 전까지 이동으로 고정한다. 쓰다듬기는 좌우 이동 합계 24 DIP 이상과 6 DIP 이상의 방향 전환을 요구하고 시작점에서 72 DIP를 넘게 벗어나면 무효다. 숫자는 **잠정 구현값**이며 실제 손맛은 통합 후 사용자 확인이 필요하다. 키보드 보조키만으로 쓰다듬기를 구분하는 안은 일반 마우스만으로 돌봄이 가능해야 한다는 조율에 따라 채택하지 않았다. 정확한 왕복 횟수·돌봄 목표·게이지는 요구하거나 표시하지 않는다.
- **표현·취소:** 눌러 준비되면 알이 조금 밝아지고 커서가 바뀐다. 툴팁·접근성 이름에 조작을 설명한다. 쓰다듬기는 480ms의 부드러운 크기·밝기 반응 후 대기로 돌아온다. 움직임 감소 설정에서는 크기 변화 대신 밝기만 사용한다. 반응 중 추가 돌봄은 누적하지 않는다. 취소·포인터 포획 해제·화면 재로딩·큰 이탈·이동은 돌봄 사건을 만들지 않는다. 굴러가는 최종 애니메이션은 아직 없다.
- **최소 저장:** 같은 SQLite 파일의 `egg_life`에 누적 경과 시간·마지막 관측 시각을, `egg_care`에는 자동 순번·종류(`touch`/`stroke`)·발생 시각·당시 경과 시간만 저장한다. 단일 펫 DB이므로 별도 사용자·기기·마우스 경로·대화 내용은 수집하지 않는다. 인식되고 반응 가능한 실제 돌봄 하나당 사건 하나만 남긴다. 사건과 경과 시간은 한 트랜잭션, 즉 전부 저장하거나 전부 취소하는 묶음으로 쓴 뒤 반응한다. 실패하면 반응 성공을 표시하지 않고 재시도 안내를 보인다. 보존 기한은 이번에 임의 설정하지 않으며 삭제·집계·성격 공식은 후속 검토다.
- **시간 결정·이유:** 실제 날짜 시각의 양의 차이를 누적해 앱 종료·장기 부재도 포함한다. 마지막 관측보다 과거 시각이면 증가시키지 않고 이전 최대 관측 시각을 유지하여 역행 후 같은 시간을 두 번 세지 않는다. 시스템 시각의 큰 순방향 변경과 실제 부재는 구분할 수 없다. 잘못 앞선 시각을 기록한 뒤 되돌리면 그 시각을 따라잡을 때까지 누적이 멈추는 한계가 있다. 이 단계에서는 기록만 하며 죽음·실패·돌봄 의무·부화 조건에 연결하지 않는다. 타이머 기능의 시간 정책도 이 결정에 포함되지 않는다.
- **당시 구조·변환:** 생활 규칙은 `src/pet/egg-life.ts`의 순수 함수, 반응은 `src/pet/brain.ts`에 둔다. 두 파일은 AI·LLM·SQLite·Electron을 알지 않는다. 앱이 시계와 저장을 연결한다. 시작·60초마다·정상 종료·돌봄 시 경과를 저장하고 재시작 때 차이를 반영한다. 형식 v1→v2 전 기존 검증된 파일을 `.v1-backup` 사본으로 남기며, 표 추가와 형식 변경은 함께 처리한다. 다른 사본이 있으면 덮어쓰지 않고 중단한다. D-039/ADR-001의 SQLite 선택을 유지하는 작은 확장이므로 새 ADR은 만들지 않고 [기존 ADR](ADR-001-local-pet-storage.md)을 갱신한다.

## D-043. 입력과 5분 타이머를 펫 행동과 분리하고 지난 예약을 복원한다

- **날짜:** 2026-09-26
- **당시 구현·검증 상태:** 담당 3의 승인된 작은 구현 / 별도 브랜치 검증 / 개별 초안 PR 검토 대상. 원본 main 반영·전체 v0.1 완료가 아니다.
- **승인 범위:** 사용자는 세 작업을 별도 워크트리·대화·브랜치에서 병렬 진행하고, 각 결과를 개별 PR로 기록한 뒤 통합 담당이 검증·순차 병합하도록 했다. 이번 담당은 입력 열기·입력·닫기/취소와 “5분 타이머”의 저장·알림·취소·복원이다. 종료 중 정시 전달은 보장하지 않는다는 이번 요청을 적용한다. PRD의 알람·리마인더 전체나 아기 대화는 구현하지 않는다.
- **결정·이유:** 메뉴 막대 `알 → 입력 / 타이머`에서 명시적으로 여는 별도 입력창을 둔다. 알 클릭과 드래그는 다른 담당이 검증 중이므로 기존 알 창·Brain을 바꾸지 않는다. 타이머 완료는 초점을 받지 않는 앱 안내와 미확인 목록으로 표현한다. 알의 발화나 감정으로 업무 결과를 대신하지 않는다.
- **저장:** 기존 `node:sqlite`로 앱 전용 `assistant/timers.sqlite3`를 사용한다. 펫 DB와 별도 파일로 두어 이번 예약 구조와 저장 실패가 펫의 식별·돌봄 구조를 변경하지 않게 했다. DB 파일 분리는 동시 개발 편의를 넘어 서로 다른 실패 영역을 보존하기 위한 선택이며, 통합 시에도 원본 펫 DB 마이그레이션이 필요 없다. 새 의존성은 없다. 입력 원문은 저장하지 않고 요청 식별자, 5분 길이, 시작·예정 시각, 상태와 전달 상태만 저장한다.
- **등록·취소:** 저장 성공 후에만 등록됨을 표시한다. 동시에 진행하는 타이머는 하나이며 같은 요청 식별자의 재전송은 중복 등록하지 않는다. 모호하거나 다른 요청은 실행하지 않고 지원 표현을 안내한다. 입력 취소·닫기는 미전송 초안을 버린다. 이미 저장한 타이머 취소는 목록의 별도 버튼이며 취소도 저장한다. 기한이 이미 지났다면 완료가 취소보다 우선한다.
- **시간 정책:** 실행 중에는 역행하지 않는 경과 시간 기준을 사용한다. 절전/복귀 이벤트가 있으면 두 이벤트 사이 경과 시간을 한 번만 포함한다. 이벤트 누락 또는 앱 재시작은 저장된 날짜·시각으로 판단한다. 따라서 재시작 사이 또는 절전 중 시스템 시각 변경의 정확한 실제 경과 시간은 보장하지 않는다. 시간대만 바뀌어도 저장된 절대 시각은 유지한다. 500ms 재확인 주기는 운영체제 정시 실행 보장이 아니다.
- **지난 예약·전달:** 종료 중/재시작 전에 지난 예약은 `recovered`(재시작 후 복원)인 미확인 항목으로 남기며 시스템 알림을 다시 보내지 않는다. 실행 중 늦게 확인한 경우에도 지연을 표시한다. 시스템 알림 요청·표시 신호·실패·미지원·결과 미확인을 별도 저장한다. 표시 신호는 사용자가 읽었다는 뜻이 아니다. 요청 후 결과 기록 전에 종료된 항목은 재시작 시 결과 미확인으로 복구하며 재전송하지 않는다. 앱 표시 기록과 사용자 확인도 별개다. 미확인 항목은 사용자가 확인할 때까지 남는다. DB와 운영체제 표시를 원자적으로 묶거나 정확히 한 번 표시됐다고 보장하지 않는다.

## D-046. 일회성 알람·리마인더는 확인 후 별도 저장한다

- **기록 날짜·당시 상태:** 2026-09-26. [PR #10](https://github.com/SoulJ-K/My-Jarvis/pull/10)의 로컬 입력·저장·복원 구현과 자동 검사 통과. 실제 macOS 시스템 알림은 미검증.
- **선택·이유:** 명확한 날짜·시각·내용을 먼저 보여주고 사용자가 등록을 누른 뒤에만 저장한다. 빠진 정보·반복 요청·존재하지 않는 시각은 추측하지 않는다. 예약은 `assistant/schedules.sqlite3`에 두어 알람 저장 오류가 펫·기존 5분 타이머 자료와 전달을 막지 않게 한다. 실행 중 완료한 항목과 재시작 후 지난 미확인 항목을 앱 안에서 보여주고, 지난 항목의 시스템 알림은 몰아 재전송하지 않는다.
- **당시 구현 가정·미결정:** 입력 당시 현지 시각·시간대·UTC 오프셋과 절대 시점을 함께 저장하고, 이후 기기 시간대가 달라져도 원래 순간에 알린다. 이는 테스트 가능한 작은 구현 가정이지 장기 제품 정책 확정이 아니다. 종료·절전 중 정시 전달을 보장하지 않는다. 통합 작업에서 운영체제 알림 요청 연결을 추가했으나 실제 표시·권한·물리 시각 변경은 아직 확인하지 않았다.

**후속 결정 — 2026-09-26:** 사용자는 앱 완전 종료 중 알람·리마인더 기한이 지나면 재실행 때 앱 안의 지난 미확인 항목으로 보여주기로 했다. 종료 중 정시 운영체제 알림은 약속하지 않는다. 당시 사용자 화면 확인의 범위는 [개발 기록](Jarvis_Pet_Development_Log.md)을 따른다.

- **후속 연결:** 단일 입력은 D-055, 자연어 요청 보완은 D-058을 따른다. 실제 시스템 알림·종료 중 만료 복원·잠금 관찰의 후속 결과는 [개발 기록](Jarvis_Pet_Development_Log.md)의 2026-10-01·2026-10-06 기록에서 항목별로 확인한다. 최초 미검증 표기를 후속 확인 전체에 그대로 적용하지 않는다.

## D-047. 부화 진행 지점은 기존 펫 파일에 같은 개체로 저장한다

- **기록 날짜·당시 상태:** 2026-09-26. [PR #9](https://github.com/SoulJ-K/My-Jarvis/pull/9)의 순서·저장·재시작 구성요소 구현·자동 검사 통과. 실제 제품 화면 연결과 자동 부화는 미구현.
- **선택·이유:** 알의 `petId`를 아기까지 유지하고 전조·금·감정구슬·껍질·아기·첫 교감·이름의 완료 지점을 기록한다. 기존 `pet.sqlite3`를 v2→v3로 확장해 단계·이름·진행 지점을 함께 저장한다. 별도 부화 DB가 기준이 되면 서로 다른 성장 단계가 남을 수 있어 피했다. 기존 v2 원본 사본을 보존하고 충돌·저장 실패·중간 종료를 검사한다. 구체적인 저장 형식과 이전 버전 호환성은 [ADR-001](ADR-001-local-pet-storage.md)에 기록한다.
- **PR #9 당시 미정·한계:** 부화 준비 시간, 돌봄이 시점을 얼마나 바꾸는지, 사용자가 실제 연출을 볼 수 있는 시작 조건, 이름 길이 정책은 확정하지 않았다. 기본 제품의 자동 부화 발동은 꺼 두고 검사에서만 명시적으로 진행한다. v3 파일은 이전 v2 앱에서 열 수 없으며 사용자 실제 DB 변환·실기기 잠금·절전·아기 생활은 미검증이다.

**후속 결정 — 2026-09-26 / [PR #12](https://github.com/SoulJ-K/My-Jarvis/pull/12):** 저장된 부화 준비 상태에서 장면 확인·이름 저장이 성공해야 진행 지점을 바꾸고 같은 `petId`의 아기 생활로 잇는다. 사용자는 첫 이름의 앞뒤 공백을 정리한 1~20자 기준을 선택했다. 부화 창의 별도 비영속 세션은 기존 알림·입력창과 권한을 분리한다. PR #9 당시의 미정·미연결 상태와 후속 검증 범위는 [개발 기록](Jarvis_Pet_Development_Log.md)을 따른다.

- **후속 결정 연결:** 준비 시간·돌봄 단축과 첫 장면 시작은 D-051, 별도 부화 창에서 같은 펫 창으로 이어지는 표현 변경은 D-060을 따른다. 위 이름 1~20자 선택과 같은 개체·저장 성공 후 진행 원칙은 별도로 보존한다.

## D-048. 아기 기본 생활과 실제 경험은 같은 펫 파일에 함께 저장한다

- **기록 날짜·당시 상태:** 2026-09-26. [PR #13](https://github.com/SoulJ-K/My-Jarvis/pull/13)의 아기 먹기·자율 수면·기본 경험 구현과 자동 검사 통과. 사용자 직접 조작과 장기간 사용은 미검증.
- **선택·이유:** LLM 없이 배고픔·졸림·자율 수면을 유지하고, 가상 먹이 한 종류의 식사·접촉·완료 수면 시간을 최소 경험으로 남긴다. 생활 상태와 경험을 같은 `pet.sqlite3`의 v4 형식에 한 번에 저장해 식사만 보이거나 경험만 남는 일을 줄인다. 첫 이름과 아기 생활 시작 시각도 같은 저장 묶음에 넣어 이름 직후 종료해도 시간이 이어지게 한다. 긴 부재는 완료된 수면 시간을 한 건으로 집계하며 가상의 돌봄 사건이나 벌점을 만들지 않는다. 저장 구조·사본·호환성은 [ADR-001](ADR-001-local-pet-storage.md)에 기록한다.
- **당시 한계·후속:** 배고픔·먹이 등장·수면·접촉 간격은 검증용 잠정 구현값이며 제품 수치로 확정하지 않았다. v3에서 이미 이름을 지은 펫은 당시 시각 자료가 없어 v4 변환 시점부터 생활 시간을 센다. 경험 보존 기간과 이후 성격 반영 규칙, 낮·밤 행동, 실제 사용자 화면 조작·물리 절전·Windows는 미정 또는 미검증이다. 당시 부화 준비 시간·돌봄 단축 수치는 미정이었고 이 변경에서 자동 준비를 켜지 않았다. 준비 정책의 후속 선택은 D-051, 낮·밤 표현은 D-050, 먹이 접근·섭취는 D-058을 따른다.

## D-049. 아기 감정·관계는 몸 상태와 분리하고 경험만 최소 기록한다

- **기록 날짜·당시 상태:** 2026-09-26. [PR #14](https://github.com/SoulJ-K/My-Jarvis/pull/14)의 구현과 자동 검사 통과. 사용자 직접 조작·물리 잠금/절전·며칠 사용은 미검증.
- **선택·이유:** 기쁨·호기심·불편함은 짧은 감정, 배고픔·졸림은 몸 상태, 익숙함과 일시적 긴장은 느리게 변하는 관계로 따로 처리한다(D-028). 반복 접촉에는 잠깐 거리두기로 반응하고 시간이 지나면 회복한다(D-030). 커서 쫓기와 같은 펫의 감정구슬 놀이만 두며, 혼자 한 놀이를 사용자와 친해진 경험으로 세지 않는다. `안녕`만으로 재회라고 쓰지 않고 생활 관측 공백 뒤 명시적 인사가 있을 때 한 번 기록한다. 이는 실제 외출을 감지한 것이 아니다. 화면에는 내부 관계·감정 수치 대신 몸짓·거리·구슬만 전달한다(D-024·D-029).
- **저장·당시 한계:** 같은 펫 파일의 v5 형식에 사회 상태와 칭찬·재회·반복 접촉·두 놀이의 종류/시각만 저장한다. 대화 원문·커서 좌표는 남기지 않고 생활·경험과 한 번에 저장한다. [ADR-001](ADR-001-local-pet-storage.md)에 v4 사본과 호환성 제약을 기록한다. 감정 6초, 거리두기 2분, 놀이 간격 5분 등은 검증용 잠정값이며 최종 감정 색상표·성격 학습·경험 보존 기간은 미정이다. 실제 사용자 DB 변환·운영체제 입력·알림 표시는 검사하지 않았다. 이 단계에서 부화 준비 자동 판단은 꺼져 있었으며 후속 연결은 D-051을 따른다. 사용자 요청 구슬 놀이 간격의 보완은 D-053을 따른다.

## D-050. 아기의 낮·밤 표현과 복귀 인사는 저장된 관계 경험과 분리한다

- **기록 날짜·당시 상태:** 2026-09-26. [PR #16](https://github.com/SoulJ-K/My-Jarvis/pull/16)의 구현과 규칙·재시작·숨긴 화면 자동 검사 통과. 실제 사용자 조작·물리 절전·며칠 사용은 미검증.
- **선택·이유:** Character & Growth Design의 고정 낮·밤 방향을 기기 현지 시각의 잠정 구간(낮 07–20시, 밤 20–23시, 늦은 밤 23–07시)으로 표현한다. 밤의 자동 놀이를 줄이고 늦은 밤에는 깨어 있는 동안 졸림을 보이되 식사·자율 수면을 우선한다. 30분 이상 관측 공백·숨김·잠금·입력 유휴 뒤에는 최대 4초간 짧게 반길 수 있다. 자동 복귀 표현은 실제 외출을 확인한 사건이 아니므로 인사·돌봄·친밀도·경험을 만들어 저장하지 않는다. 기존 사용자의 명시적 인사에 따른 재회 기록과 구분한다.
- **잠정값·한계:** 시각 경계, 30분, 4초는 검증용 값이지 확정 제품 수치나 생활 패턴 학습이 아니다. 첫 등장·짧은 재시작·페이지 새로고침의 중복 인사를 막고 수면·식사·거리두기 중에는 인사를 예약하지 않는다. 시스템 시각 변경과 실제 부재를 완전히 구분할 수 없으며 실제 화면·물리 절전은 아직 확인하지 않았다. 저장 형식은 바꾸지 않았다.

**후속 선택 — 2026-09-26:** 사용자는 현재 낮 07–20시, 밤 20–23시, 늦은 밤 23–07시 시간표로 먼저 직접 테스트하기로 했다. 이 시간표를 최종 제품값으로 확정한 결정은 아니며, 화면에서 본 느낌에 따라 조정할 수 있다.

## D-051. 부화 준비 판단과 사용자가 목격하는 부화 시작을 분리한다

- **결정 날짜·상태:** 2026-09-26. 준비 판단과 첫 장면 시작의 분리, 아래 기본 정책은 사용자 선택으로 확정했다. 실제 생활 검증 완료를 뜻하지 않는다.
- **결정:** 알의 누적 경과 시간과 실제 저장된 돌봄 사건으로 준비 여부를 판단한다. 준비 뒤에도 알 돌봄은 계속 가능하며, 첫 장면은 사용자가 메뉴의 ‘부화 함께 보기’를 선택해야 시작한다. 단순 활성화·재실행은 알만 보여주고, 이미 목격한 장면은 저장 지점부터 이어볼 수 있다.
- **선택한 기본 정책:** 돌봄 없이 24시간이 지나면 준비된다. 저장된 클릭·쓰다듬기는 인정된 직전 돌봄과 누적 경과 시간 기준으로 1시간 이상 떨어졌을 때 건당 30분을 단축하며, 총 단축은 6시간(최저 18시간)으로 제한한다.
- **이유·저장 경계:** 돌봄을 의무로 만들지 않고 연타의 영향을 제한하면서 사용자가 부화를 직접 보게 하기 위해서다. 시간 단축으로 인정하지 않은 실제 돌봄도 기록은 보존한다. 경과 시간과 준비 상태는 같은 SQLite 저장 묶음에 기록하며, 준비만으로 구슬·장면·성장 단계·이름을 진행하지 않는다.
- **변경 이력:** [PR #17](https://github.com/SoulJ-K/My-Jarvis/pull/17) 당시에는 기본 수치 미정으로 일반 실행의 자동 준비가 비활성이었다. [PR #19](https://github.com/SoulJ-K/My-Jarvis/pull/19)에서 위 정책을 일반 앱 시작·돌봄·주기 확인·절전 복귀에 연결했다. 자동 준비가 첫 장면 자동 시작을 뜻하지 않는다.
- **당시 검증 경계:** 임시 자료의 경계·재시작·장기 부재·메뉴 시작 자동 검사와 전체 회귀·로컬 Mac 앱 묶음 검사를 통과했다. 당시 실제 마우스·메뉴 조작, 물리 절전·며칠 생활은 직접 확인하지 않았다. 가짜 시계의 경계 검사를 자연스러운 18~24시간 대기 확인으로 대신하지 않는다.
- **작업·검사 이력:** [개발 기록](Jarvis_Pet_Development_Log.md)의 「부화 준비 판단, 기본 정책 — D-051 / PR #17·#19」와 후속 실기기 기록을 함께 읽는다.

## D-052. 실기기에서 드러난 쓰다듬기와 한글 버튼 첫 클릭을 보완한다

## D-060. 판타지형 알과 같은 투명창의 부화 흐름

- **기록 날짜·당시 상태:** 2026-09-30. 10~12번 사용자 시안 확인과 개별 워크트리 구현·임시 자료 검사. 9번 기상 동작과의 통합, 원본 반영·실사용 확인은 대기.
- **외형·크기:** 브라우저 시안의 남색 알·금색 별무늬·보랏빛 외곽빛을 채택하고 알과 아기의 보이는 외형을 기존 대비 약 80%로 한다. 180×200 알 창과 420×300 아기 생활 창, 먹이 좌표·입 위치·클릭 영역은 외형 크기와 별도로 다룬다. 이는 사용자가 두 크기를 같은 조건에서 비교하고 작은 쪽을 고른 결과다.
- **부화·이름:** 메뉴의 ‘부화 함께 보기’가 첫 장면의 시작점이다. 전조→금→구슬→껍질→아기→첫 교감은 차분하게 자동 연결하며, 보인 장면의 저장이 성공해야 다음으로 간다. 아기가 나온 뒤에만 같은 투명창을 넓히고 화면상 펫 중심을 유지한다. 첫 교감 뒤 아기 아래 작은 카드에서 이름을 저장하고 같은 창의 생활 화면으로 잇는다. 별도 부화 팝업이나 자동 말풍선은 쓰지 않는다.
- **기술 이유:** 기존 생애 단계·저장 지점·개체 식별자·돌봄 기록·준비 정책을 유지하며 부화 화면을 기존 펫 창에 겹쳐 창 교체로 인한 위치 단절을 피한다. 미리보기 장면은 펫 저장 자료와 분리한다. 구현 검사와 남은 한계는 [개발 기록](Jarvis_Pet_Development_Log.md)을 따른다.

- **2026-10-01 통합 중 추가 선택:** 화면 아래 끝에서 이름 카드가 아기를 가리는 문제가 재현됐다. 사용자는 이때만 아기를 필요한 만큼 위로 옮기고 카드를 아래에 유지하기로 선택했다. 이름 단계에서 필요한 공간만 확보하며 일반 위치와 다른 부화 장면의 위치 유지 규칙은 그대로 둔다.

- **후속 통합 — 2026-10-01:** 위 통합 대기는 개별 작업 당시 상태다. D-061과 [개발 기록](Jarvis_Pet_Development_Log.md)의 「기상 동작·판타지형 알·같은 창 부화 — D-059~D-061 / PR #35~#37」에 후속 통합과 병합 이력이 있다. 당시 검사 실패·재검사·건너뜀을 포함해 읽으며 실제 펫의 실사용 완료로 해석하지 않는다.

## D-061. 기상 동작과 알 외형·같은 창 부화 통합 검사

## D-062. v0.2는 복수 타이머와 선택 가능한 메뉴바 표시·단정한 입력창을 제공한다

- **결정 날짜·상태:** 2026-10-07 사용자 합의. v0.2 구현 예정이며 문서 검토 초안이다. 코드 구현·앱 검증 기록이 아니다.
- **결정:** 시·분·초·조합과 자유 제목의 복수 타이머에 남은 시간·일시정지·재개·취소·재시작을 제공한다. 생성 시 메뉴바 표시를 기본(3분 이하부터), 처음부터 고정, 표시하지 않기 중 선택한다. 제목과 남은 시간을 표시하며 고정 하나를 최우선으로, 고정이 없으면 표시 자격 중 잔여시간 최소를 선택한다. 다른 고정은 교체 확인을 받고 종료 시 고정을 해제·다음 대상으로 전환한다.
- **교체 경계:** 교체는 표시만 바꾼다. 기존 타이머·알림은 계속된다. 교체 시 기존 타이머가 **3분 미만**이면 이후 자동 메뉴바 표시에서 제외하고, 그 외는 기본 규칙을 적용한다. 기본 표시의 **3분 이하**와 이 제외 경계를 구분한다. 숨김·교체·고정은 알림 전달에 영향을 주지 않는다.
- **입력·목록:** 알에서는 아기 도움말을 숨기고 기존 메뉴바·아기 클릭 진입을 유지한다. 알 우클릭 진입안은 철회한다. 한글 조합 중 누락·중복 전송 없는 Enter 처리와 구슬놀이/구슬 놀이 등 간단한 표현 변형을 지원한다. 진행 중 일정은 위에서 종료·예정 시각순, 지난 미확인 알림은 아래에서 보여주며 새로 등록한 항목이 지난 미확인 알림 아래로 밀리지 않게 한다. 새 항목도 진행 중 구역의 종료·예정 시각순을 따른다. 상태는 짧은 글과 단정한 두 구역으로 표현한다.
- **이유·이전 결정과의 관계:** D-043의 5분·동시 하나 제한을 v0.2에서 확장한다. 필요한 타이머만 메뉴바에서 보고 입력 위치·기능을 먼저 고르는 부담을 줄인다. D-052의 한글 마우스 클릭 보정 이력을 지우지 않고 Enter 경로를 보완한다. D-055·D-058의 단일 입력·날짜 알림 등록 전 확인을 유지한다.
- **미정·참조:** 입력 상한·제목 예외·긴 제목·1시간 이상 표기·정지 중 표시·동일 시간 정렬은 구현 검토 사항이다. 수용 기준은 [기술 설계 8.3·8.8절](Jarvis_Pet_Technical_Design.md#v02-implementation-plan), 실제 검사 결과는 후속 개발 기록에 남긴다.

## D-063. 알림 확인과 실제 완료를 나누고 아기의 결과 카드와 재알림을 연결한다

- **결정 날짜·상태:** 2026-10-07 사용자 합의. v0.2 구현 예정·앱 미검증.
- **결정:** 세 종류 일정 모두 시스템 배너·소리를 전달하도록 한다. 최초 알림과 동시 자동 앱 팝업은 없으며 알은 전달 성공·실패·불명확 모두 시스템 알림만, 앱 안 기록 유지로 처리한다. 아기는 최초 알림 뒤 2분 미확인이면 머리 위 작은 카드, **배너 클릭 시 해당 카드 즉시 열기**로 결과 입력 기회를 제공한다. 알은 배너 클릭으로 기존 앱에서 알림을 확인한다.
- **확인·완료:** 배너 클릭 또는 앱의 명시 확인만 알림 확인으로 본다. 표시 신호 `shown`, 창 열기, 배너 사라짐은 사용자 확인·실제 완료가 아니다. 카드의 제목·했어요/아직이에요로 결과를 받고 했어요는 실제 완료 기록과 짧은 되돌리기를 제공한다. 아직이에요는 같은 카드의 5분·30분·직접 입력에서 매번 시간을 선택한다. 선택한 재알림 시각에는 시스템 배너·소리와 카드를 즉시 표시하며 다시 2분 기다리지 않는다.
- **여러 일정·종료:** 카드 하나에서 가장 오래 기다린 일정부터, 나머지 개수를 묶어 보여주고 각 일정에 답한다. 진행 중 목록의 예정 시각순과 구분한다. 지난 일정도 카드 추가 메뉴에서 취소할 수 있다. 완료·취소는 해당 일정의 재알림·재촉·생활 보류를 풀고, 다른 일정 조건이 없으면 평소로 돌아간다. 취소를 완료로 기록하지 않는다.
- **이유·이전 결정과의 관계:** 알림을 봤어도 실제 행동을 미루는 제품 문제를 다룬다. D-043의 자동 앱 안내와 지난 타이머의 취소보다 만료 우선인 당시 정책, D-046의 지난 일정 확인 경로를 v0.2의 단계별 카드·지난 일정 취소로 보완·대체한다. D-057의 운영체제 표시와 사용자 확인 구분은 유지한다. 대화 중의 **실패 때만 카드** 안은 성공·실패·불명확 모두 2분 미확인으로 대체하고, **10분 재알림** 안은 매번 5분·30분·직접 선택으로 대체한다.
- **미정·한계:** 앱 명시 확인 후 카드 진입, 완료 되돌리기 시간·복원 범위, 재알림 직접 입력 제한·대기 순서·종료/복귀 처리는 검토한다. 운영체제 제한·완전 종료·절전 중 정시 전달을 보장하지 않으며 기존 지난 예약 복원·결과 기록을 보존한다. [캐릭터 설계 6.3절](Jarvis_Pet_Character_and_Growth_Design.md#v02-baby-followup)과 기술 설계 8.4·8.8절를 기준으로 전달·확인·완료를 각각 검증해야 한다.

## D-064. 명시적 미완료 응답에 따라 재촉하고 일정과 먹기·수면의 우선순위를 정한다

- **결정 날짜·상태:** 2026-10-07 사용자 합의. v0.2 구현 예정·앱 미검증.
- **결정:** 최초 아직이에요에서 재알림 예약과 약한 재촉을 함께 시작하고, 재알림에서 다시 아직이에요를 선택하면 강한 재촉으로 올린다. 무응답·시간 경과만으로 강화하지 않는다. 약한 재촉은 기본 대비 10%, 강한 재촉은 20% 확대하며 두 단계 모두 몸의 붉은 변화를 표현하고 완료·취소까지 유지한다. 여러 일정이면 가장 강한 단계 하나만 적용한다. 잠깐 붉어진 뒤 자동 평소 복귀하거나 누적 확대하지 않는다.
- **행동·기억:** 강한 행동 A(화면 아래 통통 뛰기)·B(커서 근처를 따라갔다 바라보기) 중 아기별 선호 행동을 유지하고 재시작 후에도 보존한다. 모든 아기가 번갈아 하도록 바꾸지 않는다. 행동은 한 번 5초, 간격은 60→45→30→최소 15초다. 재알림에서 다시 아직이에요를 명시 선택할 때만 단축한다. 입력·클릭을 방해하지 않고 아기 드래그 중에는 멈춘다. 사용자가 옮긴 내 자리를 재시작 후에도 기억하고 재촉 종료 시 복귀하며 모니터 변경 후 화면 밖을 방지한다.
- **생활 우선순위:** 타이머·알람·리마인더가 3분 이하로 임박하거나 아직이에요 상태면 새 먹기·잠들기를 보류한다. 이미 먹는 중이면 마저 먹고 이미 자면 깨운다. 다른 일정의 조건이 남으면 유지한다. 일반 먹이와 휴지통 간식은 먹기 완료부터 공통 15분 간격이며 간격 중에는 먹지 않는다. 거부를 문자만으로 표현하지 않는다.
- **이유·이전 결정과의 관계:** 사용자가 직접 미뤘다는 응답에 맞춰 남은 일을 계속 알아볼 수 있게 하되 무응답을 벌로 다루지 않는다. D-023의 부담 없는 관계와 D-024의 비수치 감정 원칙을 유지하고, 조용한 아기 생활에는 합의된 적극 재촉 예외를 둔다. D-048~D-050의 생활·수면, D-058의 먹기 규칙에 일정 우선순위·공통 간격을 더하고, 먹은 자리 좌표가 실행 중에만 유지되던 한계와 별도로 사용자가 정한 내 자리를 보존한다. 메뉴바 화난 표정·빨간 배경안은 선택하지 않았다.
- **미정·참조:** 정확한 붉은색, 선호 행동 부여 방식은 구현 검토 사항이다. 최초 미루기부터 약함, 재알림에서 다시 미루면 강함으로 정했다. [캐릭터 설계 6.4절](Jarvis_Pet_Character_and_Growth_Design.md#v02-baby-followup)를 따르며 재시작·여러 일정·생활 연결 검사는 후속 구현 때 수행한다.

## D-065. 부화와 이름 짓기는 현재 모니터 중앙에서 이어가고 몸 기준으로 이동한다

- **결정 날짜·상태:** 2026-10-07 사용자 합의. v0.2 구현 예정·앱 미검증.
- **결정:** 부화 함께 보기를 선택하면 알이 있는 모니터 중앙으로 옮겨 부화~이름 짓기를 진행한다. 금→구슬 먼저→껍질 갈라짐→아기 주변 살핌→첫 교감→이름 순서를 연속 애니메이션으로 잇고 같은 개체·장면 저장 경계를 유지한다. 이름 카드가 화면 안에 있어야 한다.
- **표현·이동:** 이름 짓기의 구슬은 아기 좌우 중 무작위 한쪽 바닥 가까이, 장면 중 같은 위치에 두고 살짝 굴려 표현한다. 아기·이름 카드와 겹치지 않게 한다. 아기의 입은 제거하고 눈·몸짓으로 표현하며 외형 무작위 생성은 보류한다. 투명창 여백에 막히지 않고 몸이 사방 가장자리·네 구석에 도달하도록 이동하며 이름·구슬·먹이의 잘림도 검토한다.
- **이유·이전 결정과의 관계:** 중요한 장면을 사용자가 볼 수 있고 가장자리에서도 이름을 붙일 수 있게 한다. D-027·D-047·D-051의 목격·같은 개체 저장·준비 정책은 유지한다. D-060의 현재 화면상 위치 유지와 아래쪽 이름 카드 때만 이동하던 선택은 v0.2의 중앙 진행으로 대체한다. 같은 창의 연속 경험은 유지한다. D-058·D-060의 입을 기준으로 한 먹기 표현은 입 제거에 맞춰 재검토하되 기존 실제 구현 이력을 삭제하지 않는다.
- **외형 후속 결정:** 같은 날 사용자가 별도 외형 작업을 시작했다. 보류 당시 범위는 보존하며, 두 후보 시험 적용과 남은 부화 선택·저장 연결은 [D-069](#baby-appearance-decision)에서 구분한다.
- **검증 경계:** 중앙 이동·다중 모니터·겹침·사방 이동은 [기술 설계 8.6·8.8절](Jarvis_Pet_Technical_Design.md#v02-implementation-plan)의 후속 확인 대상이다. 자연 경과 부화·며칠 생활 검증 완료나 준비 시간 변경이 아니다.

## D-066. 아기는 비언어로 응답하고 감정구슬은 상호작용 수락·거부와 같은 판단을 쓴다

- **결정 날짜·상태:** 2026-10-07 사용자 합의. v0.2 구현 예정·앱 미검증. 장기 성장 방향과 현재 기능을 구분한다.
- **결정:** 뭐해·배고파·보고싶었어 같은 짧은 생활 표현에 말 대신 행동·감정구슬 색과 밝기로 응답한다. 기능적 오류·시간 안내·확인 카드 글은 아기 발화와 구분한다. Pet Brain 중심으로 외부 AI 없이 기본 생활을 유지한다.
- **구슬:** 아기 때 항상 표시한다. 빨강은 상호작용 거부·혼자 있고 싶은 상태를 나타내며 입력창 수락·거부와 같은 판단을 사용한다. 다시 받아주면 평소색으로 돌아가고 별도 임의 타이머로 빨강을 유지·해제하지 않는다. 사용자에게 남은 일이 있다는 몸의 붉은 재촉과 아기의 거부를 나타내는 구슬 빨강은 별개다.
- **장기 방향:** 알 알려주기→아기 결과 기억→유아/어린이 후속 행동→청소년 패턴 이해→성체 허용받은 수행처럼 같은 일을 점점 잘 챙긴다. 이번 아기 재알림은 v0.2에 포함하지만 아기 이후 성장 전체를 구현하지 않는다. 유아/어린이 표현만으로 기존 성장 단계에 새 단계를 확정하지 않는다. 성장으로 파일·시스템 권한을 얻지 않는다.
- **이유·이전 결정과의 관계:** 표정·몸짓을 통해 아기의 마음을 읽는 경험을 일관되게 한다. D-003·D-004·D-024·D-028의 독립성·비수치 표현·상태 구분을 유지한다. D-029의 어린 시기 구슬을 자주 두는 방향은 v0.2 아기의 항상 표시로 구체화하며 가끔 표시·숨김은 대체한다. 기존 아기의 짧은 말 표현은 생활 응답의 비언어 방식으로 대체하고 D-058의 자동 문구 제거를 잇는다. D-010·D-016·D-032의 성장·권한 분리 원칙은 유지한다.
- **미정·참조:** 수락·거부 판단 임계값과 전체 구슬 색상표는 미정이다. 긴 대화·자유 AI는 이번 범위 밖이다. [캐릭터·성장 설계](Jarvis_Pet_Character_and_Growth_Design.md)의 상호작용·두 붉은 상태 독립성을 후속 검증한다.

## D-067. 휴지통 간식은 제한된 파일을 최종 확인받아 영구삭제하는 기능으로 정의한다

- **결정 날짜·상태:** 2026-10-07 사용자 합의. v0.2 요구사항 확정·기술 가능성 검토 필요·구현 예정. 이번 문서 작업의 실제 휴지통 접근·삭제 승인이 아니다.
- **결정:** 아기를 macOS 휴지통으로 드래그하거나 간식먹어/간식먹을래?로 시작한다. 폴더를 제외하고 사용자가 자신의 휴지통에서 먹일 일반 파일 최대 2개를 직접 선택한다. 2026-10-07 후속 합의로 가장 오래된 순서의 자동 선택안을 대체했다. 대상 이름과 영구삭제 의미를 보여준 뒤 최종 명시 확인을 받아 실제 완전삭제한다. 한 번 확인을 전체 휴지통·향후 삭제의 권한으로 확대하지 않는다. 일반 먹이와 공통인 15분 간격·일정에 따른 생활 우선순위를 적용한다.
- **이유·기존 결정과의 관계:** 사용자 요청의 간식 행동을 실제 제한된 작업과 연결하면서 D-031·D-032의 피해 방지·실행 허용 원칙을 지킨다. 일반 파일 자동 정리나 PC 전체 자동화로 범위를 늘리지 않는다. D-058의 일반 먹이 표현과 구분하며 새 영구삭제 동작이라는 사실을 숨기지 않는다. 했어요의 짧은 되돌리기는 이 파일 삭제의 복구 기능이 아니다.
- **2026-10-07 권한 결정:** 휴지통 열거가 macOS에서 거부돼, 사용자에게 전체 디스크 접근 권한이 휴지통보다 넓은 권한임을 설명하고 **Jarvis Pet에만 허용**을 명시 승인받았다. 시스템 설정에서 현재 펫의 앱에만 적용하고 자료 백업·정상 재실행 후 목록 접근을 확인했다. Codex나 다른 앱의 권한을 확대하지 않았다. 이 권한은 파일 삭제 동의와 별개이며 매번 선택한 최대 2개에 대한 최종 확인을 유지한다. 재빌드·앱 교체 뒤 권한 유지와 다른 Mac은 별도 확인 대상이다. [Apple의 휴지통 접근 설명](https://developer.apple.com/videos/play/wwdc2019/701/?time=1460)을 따른다.
- **2026-10-07 실사용 후 선택 화면 변경:** 운영체제 파일 선택창에서 숨김 휴지통 경로를 찾게 하는 흐름이 막혀, 사용자 승인으로 앱 전용 목록에서 이름을 보고 최대 2개를 고르는 방식으로 바꾼다. 간식 요청 때만 홈 휴지통 바로 아래의 일반 파일 이름·검증용 메타데이터를 읽고, 파일 내용·폴더 내부를 읽지 않는다. 최종 영구삭제 확인과 기존 대상 재검증은 유지한다.
- **기술 검토:** 정확한 버린 순서를 보장할 근거가 부족하여 사용자가 직접 선택하는 방식으로 변경했다. 파일 생성·수정 시각을 버린 시각으로 대체하지 않는다. 연결 파일(심볼릭 링크)·앱 묶음·외장디스크·대상 변경·부분 실패와 삭제·먹기 완료 연결 정책은 검토 사항이며 특정 구현안을 확정하지 않는다.
- **검증 경계:** [기술 설계 8.7~8.8절](Jarvis_Pet_Technical_Design.md#v02-implementation-plan)를 기준으로 승인된 격리 자료의 대상 제한·최종 확인·실패 처리를 검증한다. 이번에는 실제 휴지통 조회·삭제나 앱 검사를 수행하지 않는다.

## D-068. v0.2 요구사항과 기존 v0.1 검증·실행 승인을 분리한다

- **결정 날짜·상태:** 2026-10-07 사용자 작업 범위와 제품 범위의 기록. 문서 검토 초안이며 구현·통합 검사 완료가 아니다.
- **결정:** 기존 PRD 1~34장, v0.1 네 가지 완료 기준, 기존 결정·검증 이력을 보존한다. PRD는 프로젝트의 정체성·핵심 경험·큰 개발 범위를 설명하고, v0.2 상세 규칙·수치·검사 계획은 기존 설계 문서와 이 결정 기록에서 관리한다. 개인용 v1 후보판 이름이나 앱 패키지 버전을 바꾸지 않는다. 자연 경과 부화·며칠 아기 생활은 별도 세션의 검증이며 3일을 필수 완료 기간으로 확정하지 않는다.
- **이유·기존 결정과의 관계:** D-002·D-021·D-022의 범위와 구현 사실 구분, D-056의 개별→통합 검수 원칙을 유지한다. 새 후속 범위를 문서화했다고 기존 버전이 완성됐거나 새 실행 권한을 얻었다고 해석하지 않는다. 이전 실패·건너뜀·환경별 한계를 최신 부분 성공으로 지우지 않는다.
- **후속 문서 역할 조정 — 2026-10-07:** 첫 초안의 PRD 35장은 수정 명세가 과도하게 중복된다는 사용자 판단에 따라 제거했다. 현재 범위에 다음 개발 방향과 설계 문서 링크만 남긴다. 상세 합의 자체를 취소하는 변경은 아니다.
- **이번 작업 경계:** 각 담당은 자신의 워크트리에서 문서를 수정·검수해 인계하고, 통합 담당은 별도 통합 워크트리에서 네 문서의 정합성을 검수·보완한다. 초안 작성 당시에는 원본 반영과 커밋·외부 전송을 금지했다. 같은 날 후속 사용자 요청으로 통합 검수한 문서 4개의 원본 반영·커밋·푸시를 승인받았다. 코드 구현·앱 실행·실제 펫·휴지통 접근·PR 생성·병합은 포함하지 않는다.
- **미정·검증 기록:** 구현 전 검토값과 제외 범위는 [캐릭터 설계 8절](Jarvis_Pet_Character_and_Growth_Design.md)과 기술 설계 8절, 구현·통합 검사는 [기술 설계](Jarvis_Pet_Technical_Design.md), 실제 결과는 [개발 기록](Jarvis_Pet_Development_Log.md)에서 구분한다. 시스템 배너·소리·잠금·절전·자연 부화·장기 생활은 자동 검사 통과만으로 완료 처리하지 않는다.

### 2026-10-07 구현 중 후속 합의 — D-062~D-067

- 최초 아직이에요는 재알림 예약과 약한 재촉, 재알림에서도 아직이에요면 강한 재촉으로 확정했다.
- 앱 확인도 해당 결과 카드로 연결한다. 완료 되돌리기는 5초, 재실행 중 지난 재알림은 항목별 한 번 처리하고 기존 강도를 유지한다. 이전 버전의 이미 확인한 알림을 새 미완료 일로 되살리지 않는다.
- 휴지통 간식은 사용자가 일반 파일 최대 2개를 직접 선택한다. Dock 드래그도 이번 구현 범위이며 입력 명령만 제공하고 나머지를 미루는 안은 채택하지 않았다. 실제 파일 삭제에는 별도 최종 확인이 필요하다.
- 병렬 구현과 격리 화면 검사를 승인받았다. 기존 실제 펫·휴지통을 검사 자료로 사용하지 않으며, 코드 저장과 커밋·외부 전송은 구분한다. 구현·검사 상태는 기술 설계의 후속 결과에 기록한다.

### 2026-10-07 — Dock 드래그 연결 방식 교체

별도 Swift 프로그램으로 드래그를 넘긴 후보는 실제 손 조작에서 이동 이벤트를 거의 받지 못하고 취소됐으며, 사용자가 그림 축소·정지를 확인했다. 실패 기록을 보존하고 사용자의 승인에 따라 Electron 앱 내부에서 원래 창·실제 마우스 누름을 받는 Node-API 연결로 교체했다. 드래그 그림은 입력을 받지 않는 고정 크기 창에 표시해 위치만 이동한다. 실제 파일이나 임시 표식파일을 Dock에 전달하지 않으며, 운영체제의 삭제 동작 신호도 파일 선택 요청으로만 사용한다. 네이티브 취소는 이후 선택 요청을 차단하고 창을 복구하지만, 가짜 키 입력으로 운영체제의 드래그를 강제 종료하지 않는다. 구현·빌드 검사와 실제 Dock 동작 확인은 구분한다.

### 2026-10-07 — 실사용 펫과 시험 앱의 알림 실행 대상 분리

실사용 중 시스템 알림을 누르자 과거 시험 앱의 알이 별도로 나타났다. macOS 기록에서 15:08:36 알림 클릭과 현재 앱으로의 응답 전달 직후, 같은 `local.jarvispet.preview` 식별값을 가진 과거 앱의 실행을 확인했다. 예약 작업이나 다른 대화의 새 실행으로 판단하지 않는다. [Apple의 앱 식별값 설명](https://developer.apple.com/library/archive/documentation/General/Reference/InfoPlistKeyReference/Articles/CoreFoundationKeys.html)에 따라 실사용 앱은 정규화한 저장 경로별 고정 식별값, 시험·검증 앱은 생성본별 별도 식별값을 사용한다. 이름은 실사용 앱 `Jarvis Pet`, 시험 앱 `Jarvis Pet Preview`로 구분한다.

앱 생성만으로 운영체제 등록을 바꾸지 않는다. 별도 활성화 명령은 선택한 식별값에 한해 이전 등록 경로를 해제하고 새 앱을 등록한 뒤 기본 실행 경로를 검증한다. 앱 파일·펫 자료·다른 앱의 등록은 보존한다. 첫 전환의 알림 허용을 사용자에게 안내하고, 과거 알림은 자동으로 새 식별값으로 이동하지 않으므로 새 알림으로 클릭을 재검사한다. 이는 실사용 전환 결함 수정이며 새 기능이나 버전 번호 변경은 아니다.

## D-069. 무작위 외형을 별도 작업으로 진행하고 잎·날개 두 아기를 먼저 시험한다

- **날짜·상태:** 2026-10-07 사용자 선택과 후속 확인. 전체 기능은 **구현 중 — 두 후보 시험 앱 적용 완료, 부화 시 선택·저장 연결 예정**이다. 기존 펫 적용·원본 코드 통합 완료를 뜻하지 않는다.
- **선택과 이유:** 사용자 제공 6종 시안 중 01 잎 친구·06 날개 친구를 선택했다. 단순하고 친근한 얼굴과 명확한 실루엣을 유지하면서 부드러운 명암과 방향별 그림으로 입체감을 낸다. 사실적인 피부·잔털의 생물 디자인은 사용자가 원한 방향이 아니므로 이어받지 않는다. 아기의 입은 없으며, 먹이는 입이 있었다면 위치할 곳에서 먹는 표현을 따른다.
- **시험 경계:** 실제 기르는 테스터를 보존하고 두 외형은 별도 개체·저장 공간·실행으로 시험한다. 현재 두 후보는 완성된 그림을 고정해서 사용하며, 부품 조합·색과 무늬의 무작위 범위는 별도 결정이 남아 있다. 한 번 정한 외형 유지와 이후 성장의 특징 연속성을 원칙으로 하되, 어린이 이후 구현이나 실행 중 유료 AI·실시간 3D 엔진 도입을 승인한 것은 아니다.
- **방향 전환 후속 선택:** 정면에 고정되거나 한쪽 얼굴만 보이는 표현을 보완해 정면·좌우를 사용한다. 사용자가 이동 뒤 복귀가 느리다고 하여 대기를 0.9초에서 0.25초로 줄였고, 사용자는 시험 펫에서 적용을 확인했다. 수면과 먹이·구슬 집중을 우선하며 이 확인을 모든 동작의 최종 승인으로 확대하지 않는다.
- **기존 결정과의 관계:** D-013·D-014의 개체·관계 지속성과 D-066의 입 없는 비언어 표현·감정구슬 규칙을 유지한다. D-065에서 보류한 외형을 별도 승인 작업으로 다시 다루며, 기존 v0.2 실사용 수정 담당 범위나 제품 버전은 임의로 바꾸지 않는다.
- **남은 범위:** 부화 때 한 번 선택하고 저장 성공을 확인한 뒤 부화 장면과 아기 생활에 같은 외형을 연결해야 한다. 종료·저장 실패 복구 및 이전 자료 호환은 추가 구현·검증 대상이다. 기존 기르는 펫의 외형은 자동 변환하지 않으며 다시 뽑는 기능도 추가하지 않는다. 별도 외형 펫 하나를 지속해서 키우는 요청은 문서 정리 후 이어갈 예정이고 계열 선택·생성은 아직 진행하지 않았다.
